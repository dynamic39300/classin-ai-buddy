# 1000 样本会话结构只读查询计划

状态：`READY_FOR_METADATA_CONFIRMATION`。本计划定义查询目的、输入输出和校验，不记录凭据，不把知识库中的示意表名当作当前实例已确认元数据。

## 1. 查询纪律

- 只读、显式列名、小批量 ID、可重放；
- 先确认表和字段，再执行样本查询；
- 原始库小范围索引查询优先，数仓聚合结果用于交叉核对；
- 有分区字段的数仓查询必须带分区；
- 成员状态、课程状态和软删除状态分别解释；
- 所有 ID 按字符串导出；
- 不在仓库或输出中保存 Token。

## 2. 输入范围

输入 `sample_cluster_scope.jsonl`，预期：

- 1000 个会话窗口；
- 780 个 `observed_type=0`；
- 220 个 `observed_type=1`；
- 每个记录带窗口、消息时间范围和活跃 `sourceuid`。

如果实际范围 QA 与此不一致，停止查询并先解释差异。

## 3. 查询阶段

### Q0：元数据确认

确认群主记录、群成员、用户—群关系、课程、课程成员、机构教师、机构学生、监护关系（若存在）的实际表/视图、主键、状态字段、时间字段和分区字段。

输出 `metadata_contract.json`，记录已确认字段和查询时间。任何不存在或含义未确认的字段标为 `unavailable`，不得自行补写。

### Q1：type 0 课程关联全量门禁

对 780 个 type 0 `clusterid`：

1. 读取群主记录；
2. 以课程标识执行左连接；
3. 输出每个 cluster 的课程匹配数量、课程 ID、群/课程状态和创建时间；
4. 数仓课程关联标识仅作交叉核对。

必须生成：

- `matched_once` 清单；
- `not_matched` 清单；
- `matched_multiple` 清单；
- 分母为 780 的匹配率。

零匹配不直接解释为自建群，应继续排查历史课程、软删除、发号来源或导出错误。

### Q2：群聊完整成员与职业身份

对 type 0 群读取当前有效成员和必要的历史字段，再按 UID 关联机构职业关系。输出每位成员：

查询条件是完整的 `clusterid` 批次，不是已发言 `sourceuid`。因此必须返回当前未发言成员；scope 中的发送者清单只用于 Q4 交叉核验。

- 群内管理身份与课堂身份；
- 成员加入时间、退出状态或退出消息位点；
- 有效教师/管理者关系；
- 有效学生关系；
- 正式监护关系（仅在元数据证实时）；
- 机构/课程锚点和多角色冲突。

群主表的 `MemberCount` 不能替代有效成员行计数。

### Q3：1v1 双方关系与职业身份

对 type 1 会话读取双向用户—会话关系及 `ContactorUID`，验证：

- 每个会话是否恰好有两个有效参与者；
- 双向记录是否互相指向；
- 双方机构职业身份；
- 教师—学生关系是否存在共同机构或课程锚点；
- 家长判断是否有正式关系证据。

好友备注只作辅助证据，不决定职业关系。

### Q4：窗口发送者覆盖与时态核验

把 scope 中全部 `sourceuid` 与 Q2/Q3 的成员事实核对。报告：

- 无法在成员关系中找到的发送者；
- 当前已退出但在窗口时点可能有效的发送者；
- 消息时间早于入群时间等时态冲突；
- 群内角色和机构职业身份冲突。

## 4. Adapter 输出 Interface

将 Q1–Q4 合并成 `conversation_structure_facts.jsonl`，每个 `clusterid` 一条，遵循 `schemas/conversation_structure_facts.schema.json`。数据库 Adapter 只负责提供可追溯事实，不负责决定教师管理协作或一般教师内部沟通。

## 5. 停止与恢复

遇到权限、超时、字段不存在、分区不完整或状态语义不清时立即停止当前阶段；保留已执行 SQL 的只读摘要、返回行数和查询时间，不用空值伪装成功。恢复后从最近一个完整阶段继续。
