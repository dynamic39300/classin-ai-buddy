## 阶段性结论总览

1. TeacherIn 作为独立品牌的教研内容生产与市场分发产品线继续存在；ClassIn、WorkBuddy 与 TeacherIn 通过内容对象和任务通路协同，不再重复建设内容广场。
2. WorkBuddy 中的动作统一为“创建草稿到 TeacherIn”，成功后由教师前往 TeacherIn 编辑作品信息、设置授权并发布；未证实的审核环节不进入前台流程。
3. “我的文件”是 AI 协作 Artifact 的回溯与复用视图，底层文件仍存储在 ClassIn Space；页面不提供上传入口，也不收录普通上传文件。
4. 教师 WorkBuddy 是教师侧统一主 Agent；班级 Agent 是经授权进入公开群聊或私聊渠道的垂直 Agent。两者按角色、可见性、渠道与治理分轨，而不是把 Agent 市场中的全部 Agent 固定定义为学生 Agent。
5. IM 一期按三条独立渠道验收：教师私密 WorkBuddy、群内公开 `@` 班级 Agent、学生与同一班级 Agent 私聊。首条纵向切片选择“按作业分组提醒未提交学生”。
6. WorkBuddy 生成内容只有经教师审阅和确认后，才以教师本人身份作为一条群消息发送；学生不能看到或 `@` WorkBuddy。
7. 消息中心采用同一个 `MessageWorkspace` 的沉浸 Shell Mode，最多并列会话列表、当前消息和 WorkBuddy 三栏；退出沉浸只恢复 ClassIn 标准 Shell，并停留在消息 Tab 与原会话。
8. 班级详情的“班级群聊”复用同一沉浸式消息工作区，但因班级上下文已锁定，只保留班级群聊与 WorkBuddy 两栏，并确定性返回原班级详情。
9. WorkBuddy 作为右侧悬浮辅助工作台，保留完整且唯一的 Agent Run 表达，不另做压缩版；运行中展示当前步骤、进行中状态、旋转标识和已用秒数。
10. 通信主工作台与 WorkBuddy 之间允许拖动调宽；左侧会话列表与当前聊天合成一个主 Surface，WorkBuddy 是独立辅助 Surface，紧凑宽度转 Overlay。
11. WorkBuddy Composer 单行起步，随内容自动增长，最高约 10rem（约 6—7 行）后内部滚动；最多 4,000 字符，3,200 字符后显示计数。
12. Agent Run 完成不等于沟通任务完成。群消息草稿进入独立“待你审阅”成果面，默认可编辑，经发送前事实复核后由教师一键发送。
13. 待审阅成果面固定为四层，并使用单一 Canvas、暖色状态带、少边框视觉；发送成功后原位转为紧凑 ExecutionReceipt，不再使用庞大的成功卡片。
14. 教师从 1v1 或班级群进入沉浸消息时，WorkBuddy 默认持续展示，不提供关闭；退出提示“WorkBuddy 已收起”必须与真实 Surface 状态一致，退出只收起界面、不清空 Run、Artifact 或 Composer。
