## 一句话概括现状

ClassIn WorkBuddy 目前还不是一个已经完成定位、准备进入产品设计的项目，而是一个刚刚被提出的战略性产品命题：

> 基于 ClassIn 已有的课堂、教师、学生和教学数据，能否构建一个真正理解教育场景、能够参与教师完整工作流程的教育垂直智能体？

团队已经形成了若干产品想象和局部技术实验，但尚未回答“为谁、解决什么问题、创造什么价值、为什么由 ClassIn 来做”这些基础问题。

## 当前已经发生了什么

2026 年 8 月 14 日，销售、产品研发和设计团队围绕 WorkBuddy 进行了约 2.5 小时讨论。

会议出现了三类方案：

| 方案 | 实质 | 当前状态 |
|---|---|---|
| 销售方案 | “懂老师、懂学生、懂课堂”的智能教学助理 | 愿景和销售叙事较完整，但缺少落地闭环 |
| 产研方案 | 个性化作业、AI 推题、教研 PPT 生成 | 已有局部实验，但仍是若干单点能力，质量尚未达到直接教学使用标准 |
| 设计方案 | Task + Channel + Agent 构成的教师工作台 | 产品形态比较完整，但尚未证明老师为什么每天使用，以及如何实现 |

这些方案不是简单的三个产品方案，而是三个不同视角：

- 销售关注“这个产品能形成什么核心价值和销售故事”；
- 产研关注“AI 当前有哪些能力能够先做出来”；
- 设计关注“教育智能体应该以什么界面和工作范式呈现”。

由于会议没有先明确客群、商业目标和核心问题，三个方案实际上没有站在同一个问题上展开比较。

## 当前真正的核心分歧

表面上，会议争论的是：

- 做个性化推题，还是做方向性学习建议；
- 做若干 AI 工具，还是做一个完整 Agent；
- 做独立产品，还是做 ClassIn 内部工作台。

但深层其实有四个尚未解决的问题。

### 1. 产品到底服务谁

目前至少存在三种可能客户：

- K12 教培机构及其教师；
- 公立学校和校内教师；
- 个人教师或小型教学组织。

不同客群的采购者、使用者、工作流程、数据权限和付费逻辑完全不同。目前材料里没有完成选择。

### 2. 产品承担什么业务目标

目前存在两种方向：

- 作为新产品和销售方案，帮助 ClassIn 拉新；
- 服务已有 ClassIn 客户，提高活跃、留存和复购。

这不是传播口径的差异，而是会直接改变产品入口、功能优先级和价值衡量方式。

### 3. 它究竟是工具还是工作伙伴

现在实际存在三个层次：

1. AI 功能：生成题目、生成课件、生成报告；
2. 教学工作流：备课—上课—诊断—反馈—作业；
3. 教育智能体：持续理解教师、学生、班级和课程，并主动参与决策与执行。

团队目前有第一层的实验、第二层的想象，希望讲第三层的故事，但第二、第三层所需的数据结构、记忆机制、教研知识和执行闭环尚未建设。

### 4. “懂教育”到底是什么意思

这是目前最重要、也最模糊的命题。

已有材料把它初步拆成：

- 教学理念；
- 教学方法；
- 教学对象；
- 学科及课程知识体系。

但这还只是一个分类框架。尚未明确：

- 哪些知识需要被智能体掌握；
- 哪些是通用教育知识，哪些来自具体学校和教师；
- 如何从优秀教师实践中采集；
- 如何表达成可计算、可调用的 Memory、Skill、规则和评价标准；
- 如何判断智能体给出的教育建议是好的。

因此，“ClassIn 有课堂数据”是相对明确的潜在优势；“ClassIn 懂教育”目前还是一个需要证明和建设的假设。

## 路径一：内部认知与战略意图还原

这一条由你主导。目标不是马上写 PRD，而是把你掌握的内部背景、业务判断和个人观点显性化。

4. 他更关心产品收入、资本市场叙事、品牌影响、销售获客，还是 AI 转型？

3. 新客户从哪里来，销售周期如何？
4. 当前增长、转化、留存和续费分别有什么问题？
5. WorkBuddy 最可能影响哪一个经营指标？

### D. 用户与场景

2. 哪些任务最耗时、最痛苦、最依赖经验？
3. 哪些工作可以交给 AI，哪些必须由老师判断？
4. 老师真正需要的是生成内容、提供建议、执行任务，还是持续理解上下文？
5. 学校管理者、机构负责人、家长和学生分别期待什么？
6. 哪些场景高频，哪些场景虽然低频但价值特别高？

3. ClassIn 能理解哪些课堂行为和学习结果？
4. 公司内部有哪些教研、教师网络、课程资源和最佳实践？
5. 当前 AI、数据、产品和工程团队的实际能力边界在哪里？
6. 哪些能力是竞争对手短期内难以复制的？

### F. 组织与推进条件

1. 谁是最终决策人，谁是实际负责人？
2. 销售、产品、设计、研发分别希望从项目中得到什么？
3. 当前有哪些已承诺的方案、时间或客户？
4. 谁能提供客户、数据、教研和技术资源？
5. 项目最可能因为什么失败？
6. 组织现在更适合做研究验证、快速 Demo，还是正式产品建设？

你可以在回答时标注四种性质：

- **事实**：有数据、文件或明确表态支持；

- **未知**：当前没有信息。

这个区分会非常重要。现在团队最大的危险之一，就是把高层愿望、销售叙事、产品假设和用户事实混成一件事。

## 最后的汇合方式

两条路径完成后，不应该简单“取平均”，而是做一次结构化对照：

| 比较对象 | 要回答的问题 |

| 强假设 | 哪些关键结论目前没有证据？ |
| 可验证项 | 哪些问题可以通过客户访谈、数据分析或原型测试解决？ |
| 决策项 | 哪些问题无法靠研究自然得出，必须由 CEO 或决策组选择？ |

1. 项目命题；

3. 第一目标客群；

5. ClassIn 的独特优势；
