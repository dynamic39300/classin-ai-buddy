### Prompt 01｜Agent Run 流式交互的视觉、动效与信息密度优化

时间：2026-08-22 11:27:17

> 当前 Agent Run 的状态已实现流式输出。针对整体 UI 表现，提出以下三点专业优化建议：
> 1.
> 强化视觉质感与拟真度：针对不同状态阶段及文案内容，建议精细化调整色彩体系与高亮配色，提升界面的拟真感与沉浸感。当前页面偏向基础功能性布局，缺乏 AI 原生交互的质感。建议对标行业领先的 Agent 输入/输出流设计范式，或参考 GitHub 优质开源案例，优化现有的视觉呈现形态。
> 2.
> 引入动态交互反馈：增加系统级状态动效（如加载动画、处理中状态指示等），通过直观的视觉反馈，清晰传达 Agent Run 的实时执行逻辑与处理进度，降低用户的等待焦虑。
> 3.
> 优化卡片布局与信息密度：弹窗确认卡片的元素构成与交互逻辑已趋于完善。在 UI 呈现上，建议通过缩减卡片尺寸并提升信息密度，优化视觉紧凑度。参考主流 Agent IDE（如 Codex）的设计语言，应更强调局部交互的精炼感，避免大篇幅展示带来的视觉冗余，从而提升操作效率。

#### 助手关键输出与产出摘要

- 将时间线从“同图标、同层级”改为语义化执行轨道，区分排队、运行、待确认、完成、失败与停止。
- 动效只服务当前活动步骤：增加呼吸、扫光与对象级进度，并完整支持 Reduced Motion。
- 将补参、计划、Action 与 Approval 压缩为紧凑多列布局，审批弹窗明确区分“授权”与“实际执行”。
- 当时验证：415 项测试、M4.1 E2E 14/14、视觉旅程 2/2、Build/axe/Reduced Motion 通过。
- 关键产出：[实现评审](../../04-specs/features/workbuddy-m4-agent-run-ux/M4-1-IMPLEMENTATION-REVIEW.md)。

## 跨轮次持续坚持的设计与工程原则

- **状态单一来源**：步骤、计划、进度和 Artifact 直接投影既有领域状态，不为动效再造第二套布尔状态。
- **真值标签**：模拟数据、模拟导入、模拟 PPTX、未接入的第三方编辑器和 Runtime 均显式标注，不能伪装生产能力。
- **AI 过程可观察但不展示隐藏思维链**：展示任务拆解、工具/能力调用、业务步骤、等待原因和结果，不呈现模型私有推理。
- **教师控制与审批**：WorkBuddy 结果在教师确认前不进入班级群或正式业务对象；确认后以教师身份写入并生成回执。
- **渠道与权限隔离**：教师私密 WorkBuddy、群内公开班级 Agent、教师/学生 Agent 私聊分别执行独立可见性和上下文策略。
- **Hover 不是唯一入口**：重要浮层同时支持 Focus、点击、触屏替代和 Escape；状态使用图标、文字和颜色冗余表达。
- **Reduced Motion**：关闭旋转、扫光和位移时，仍保留静态状态、步骤位置和可理解的反馈文案。
- **桌面滚动所有权**：应用 Shell 锁定视口，消息列表、时间线、辅助区正文各自在明确容器内滚动。
- **专业工具边界**：WorkBuddy 内提供预览和审阅，不尝试取代 Word、PowerPoint 等专业文档编辑器。
