# ClassIn IM 逐条消息与事项标注方法里程碑

## 1. 里程碑范围

本里程碑封存 Pilot 0 v2–v2.3.3 形成的“逐条消息开放编码 + 事项层记录 + 样本层总结”方法。最终版本提供：

- 原始 Excel 行、会话、消息、发送者与正文的逐行溯源；
- `strtalker`、`sourceuid`、`user_type` 等角色上下文；
- 单方可见边界轨与标准互动轨分离；
- 消息层提问、请求、时效、回应、结果和证据边界；
- 事项层中性名称、对方期待和可见状态；
- 样本层只读公式镜像与双人独立标注结构。

## 2. 阶段性价值

该方法澄清了多项重要规则：单方可见不等于真实未回复；“尽快”属于模糊时效；新请求尚无结果属于“未看到”而不是事项问题；角色、结果和动机不能越过可见证据推断。

这些规则继续作为 Topic 方法的证据治理基础，但旧工作簿不再作为当前人工填写入口。

## 3. 转向原因

用户在 v2.3.3 标注员 A 工作簿中试填两条核心消息后确认：填写虽然清楚，却大量重复原文，无法稳定反映完整业务情境，也不能直接形成能够牵引后续研究的 Topic。复核还发现逐句改写会引入轻微语义漂移，并把同一沟通片段过度拆成多个事件。

因此主要分析单位由“单条消息”调整为“100条消息案例中的 Topic/沟通片段”。单条消息继续作为只读证据，不再要求人工逐字段完整编码。

Topic Pilot 50 从锁定的原始 Excel 重新抽取50个100消息案例，平衡单聊/群聊并分三批人工标注。人工只提炼 Topic 初稿和关键证据；AI 在人工 Topic 基础上进行结构化拆解；人工再校准并形成可验证 Codebook。
