# ClassIn IM P2 抽样与样本保全协议

## 1. 三个总体必须分开

| 层级 | 定义 | 当前是否可见 | 能否外推 |
| --- | --- | --- | --- |
| U0 平台真实总体 | 2026-08-01 至 27 日所有符合业务范围的自然会话与全部消息 | 不可见 | 当前不能 |
| U1 导出窗口总体 | 工作簿中的8,197个会话窗口，每个正序100行 | 完整可见 | 只能外推到这8,197个窗口 |
| S 研究样本 | 从U1按协议抽取的窗口/消息片段 | 可见 | 取决于抽样轨道 |

所有后续报告必须写明所指总体。除非获得导出 SQL、会话级入样逻辑和完整消息量，不得把 U1 改写成 U0。

## 2. 三段式抽样

### P2a Pilot-0：方法认知测试

目的：用少量、覆盖边界的 Case 检查标签能否被人一致理解、20条核心消息加上下文是否够用、哪些字段必须保持未知。

- 不是概率样本；
- 不产生主题发生率；
- 不用于产品优先级；
- 允许有意覆盖单聊角色未知、仅教师发言群、仅学习者发言群等难例。

### P3a A 轨：U1 代表性样本

目的：在 Pilot-0 修订方法后，从8,197个导出窗口中按已知分层随机抽取，用于估计 **U1 内部** 的分布。

- 每个样本保留入样概率和设计权重；
- 过采样稀有分层时必须加权还原；
- 仍不能外推到平台完整消息流 U0。

### P3b B 轨：发现性样本

目的：定向覆盖长文本、正文提取差异、窗口外回复、单向发言、教学管理疑似群等边界、高风险与罕见 Case。

- 不计算总体比例；
- 与 A 轨分开编号、分开报告；
- 同一 Case 即使同时满足多个触发条件，也只保留一个主入样原因，并记录其他命中。

## 3. 分析与标注单位

### 3.1 一级抽样单位：导出会话窗口

以 `clusterid` 对应的100行窗口为一级单位。原因：

- 单条消息无法表达参与关系和上下文；
- 当前工作簿的最稳定结构就是100行窗口；
- 会话自然边界之外的信息已经缺失，不能假装重建完整会话。

### 3.2 二级审阅单位：固定核心片段 + 只读上下文

Pilot-0 将每个100行窗口划为五个核心段：

- `1–20`
- `21–40`
- `41–60`
- `61–80`
- `81–100`

对每个入选窗口，用固定随机种子均匀选择一个20行核心段；展示时最多附加前5行和后5行作为只读上下文。

| 区域 | 是否标注 | 用途 |
| --- | --- | --- |
| 核心20行 | 是 | 计算标签与分歧 |
| 前后各最多5行 | 否，只读 | 理解代词、回复、连续任务 |
| 窗口外内容 | 不可见 | 标记 `context_outside_export`，不得推断 |

若任务跨越核心段，标注者先标记 `context_insufficient`，不能自行扩展或挑选更多消息。扩展上下文必须形成新的审阅版本并保留原判断。

## 4. Pilot-0 样本配额

Pilot-0 共24个会话窗口、480条核心消息。它刻意平衡方法难点，不追求 U1 比例：

| 样本组 | 数量 | 主要验证问题 |
| --- | ---: | --- |
| 单聊、窗口内观察到2位发送者 | 6 | 角色未知时能否只标事实、不猜师生关系 |
| 单聊、窗口内只观察到1位发送者 | 2 | 区分单向可见、无回应与截断未知 |
| 群聊、学习者与教职工均发言 | 8 | 验证多类观察角色同时出现时仍不预判群用途 |
| 群聊、仅学习者发言 | 4 | 防止把成员发言结构误写成群成员构成 |
| 群聊、仅教师/班主任发言 | 4 | 验证教学运营/管理群型判定边界 |

组内选择采用固定种子与结构多样性轮转，优先覆盖：

- 群规模三档；
- 100行覆盖时长：≤1天、1–7天、7–27天；
- 观察发送者数量：1、2、3–5、6+；
- 是否存在长文本、空正文、非 JSON 载荷或显式回复；
- 五个核心段位置。

## 5. 样本保全记录

每个样本必须记录：

| 字段 | 说明 |
| --- | --- |
| `sample_id` | 与真实 ID 脱钩的研究编号 |
| `source_sha256` | 锁定输入版本 |
| `selection_protocol_version` | 选择规则版本 |
| `seed` | 可复现随机种子 |
| `sample_group` | Pilot/A/B 与主入样原因 |
| `channel` | 声明单聊/声明班级群 |
| `observed_role_composition` | 只描述窗口内发言角色 |
| `user_num_bucket` | 仅群聊解释 |
| `sender_count_bucket` | 窗口内观察值 |
| `core_rn_start/end` | 核心20行 |
| `context_rn_start/end` | 只读上下文范围 |
| `selection_status` | selected/read_failed/excluded/replaced |
| `replacement_for` | 若替补，指向原样本 |
| `loss_reason` | 不允许为空后静默换样 |
| `estimation_eligibility` | none/U1-weighted/discovery-only |

真实 `clusterid` 与研究编号的映射只保存在仓库外的受限目录；仓库内清单不包含可还原 ID 或消息正文。

## 6. 样本损失与替补

允许损失原因只包括：

- 文件读取失败；
- 选中行在固定版本中不存在；
- 内容无法完成必要脱敏且风险不可接受；
- 明确违反研究范围；
- 用户要求撤回。

不允许因为“内容没价值”“没有明显教学主题”“不好标”“与预想不符”而替补。没有任务、纯表达、闲聊和无法判断都属于必须保留的真实样本。

替补规则：从同一抽样轨道、同一主分层的预生成候补序列中顺延，并保留原样本、替补样本和原因。

## 7. Pilot-0 通过条件

Pilot-0 只验证方法，满足以下条件后才设计 A/B 正式样本量：

1. ≥90%的核心片段可在当前上下文长度下完成表层意图标注；
2. 两位标注者能区分直接可见事实、解释性推断和无法判断；
3. 单聊角色没有被从内容擅自猜测；
4. 开放码不因发言角色直接生成群用途，且仅教师发言不自动等于管理群；
5. 样本损失、扩展上下文和仲裁均有日志；
6. 研究执行者和标注者都没有打开旧报告、旧样本表或产品方案材料；
7. 首轮开放码先保留原始措辞，再透明归并候选 Codebook；
8. 对低一致字段能够修订手册或明确放弃，而不是强行扩大样本。

## 8. 当前限制

Pilot-0 仍不能解决 U0 总体缺失、单聊角色缺失和消息类型单一。它的价值是验证“我们有没有能力对当前证据做可靠判断”，不是提前产出市场规模或功能优先级。
