# ClassIn IM Pilot 0 v2.3 合并简化标注操作指南

> **版本通知（2026-08-30）**：v2.3 的合并事项与分轨规则继续有效；时效四值已在 v2.3.2 简化为三值。当前审阅入口为 [v2.3.2 一体化审阅操作指南](./PILOT0-ANNOTATION-OPERATING-GUIDE-V2-3-2.md)。本文件作为基础规则和审计轨迹保留。

## 1. 当前使用状态

v2.3 现在只用于审阅“表格是否好理解、好填写、规则是否合理”。等能还原较完整的真实 IM 聊天现场与上下文后，再启动 A/B 独立正式标注。

因此当前：

- 可以浏览说明、虚构示例、表头和填写路径；
- 可以记录“看不懂、不好填、选项不合理”等方法问题；
- 不需要对现有样本完成正式填写；
- 不生成主题、比例、需求优先级或 IM/AI 产品结论。

## 2. v2.3 改了什么

1. 删除人工填写的 `04_事项汇总`，不再跨表复制 `sample_id`、`rn`、`sourceuid` 等 ID；
2. 在 `03_逐条开放编码` 同一行增加事项字段，消息证据和事项判断同屏；
3. 不再为每个样本预置 E1–E5 五个事项；有多少实际事项，就使用多少 `E1 / E2 / E3…`，不设上限；
4. `明确时间要求` 改为 `时效要求`，避免把“尽快”硬塞进是/否；
5. 新增 `00B_字段速查`，并在各填写区表头直接显示选值口径、Good case 和常见误区。

## 3. 标注单位

逐条消息是证据定位单位，不是脱离上下文的理解单位。实际顺序是：

1. 先读完同一 `sample_id` 的灰色上下文和核心行；
2. 理解片段中正在发生的事项；
3. 再标每条核心消息在该事项中的作用；
4. 同一事项的多条消息使用同一 `local_event_id`；
5. 事项字段只在该 ID 第一次出现的行填一次。

这样既保留逐条证据，又不要求标注者把每句话孤立贴标签。

## 4. 实际填写路径

### 标准互动轨

1. 先读 `00_使用与溯源说明`、`00A_填写示例`和 `00B_字段速查`；
2. 在 `03_逐条开放编码` 中阅读完整样本，只填黄色核心行；
3. 每条核心行填 O–AC 的消息层字段；
4. 某个 `E1/E2…` 首次出现时，同行填 AD–AG 的事项字段；后续同事项行留空 AD–AG；
5. 完成整个样本后，到 `05_样本总结` 写样本级判断；
6. 遇到规则问题填 `06_字段问题`。

### 单方可见边界轨

`P0-DIR1-01/02` 仍只能证明当前导出窗口中观察到一位发送者。只填 `03` 橙色简化行与 `08_单方可见汇总`，不把“窗口未观察到”写成“对方实际未回复”。

## 5. 最容易误标的字段

| 字段 | 正确口径 | Good case | Bad case / 不应如此选 |
| --- | --- | --- | --- |
| `时效要求` | `明确时限` / `模糊时效` / `无` / `无法判断` | “今晚8点前”=`明确时限`；“请尽快”=`模糊时效` | 不能因为“尽快”没有时钟时间就选`无` |
| `明确行动请求` | 本条是否要求对方执行动作 | “请把文件发给我”=`是` | “文件发了吗”主要在问状态，不必然是请求 |
| `提交/分享物` | 本条已经提交、发送或声明已分享 | “这是第3页[图片]”=`是` | “请把作业图片发来”是请求，本条并未提交 |
| `本条是否回应前文` | 只判断当前这条是否在回答、确认、拒绝、纠正或补充前文 | “明天19:00开始”回答前一问题=`是` | “明天几点开始？”后来获得回答，但这条自身仍=`否` |
| `结果证据` | 只记录当前可见的完成、进展、受阻或未观察到 | 目标就是“确认收到”且对方回“收到”，可标完成 | 普通事项里的“收到”不自动等于事项完成 |
| `local_event_id` | 同对象、同期望结果并连续推进的消息共用一个 ID | 三条都在确认开课时间，都填 `E1` | 不要每句新建事项，也不要为了填满预设数而拆分 |

其他字段的每个枚举值、适用场景、Good case 和 Bad case 均在工作簿 `00B_字段速查` 中展开。

## 6. 事项字段怎么填

仅在某个 `local_event_id` 第一次出现的行填：

| 字段 | 写法 |
| --- | --- |
| `事项中性名称` | “动作/问题 + 对象”，例如“确认课程开始时间”；不写“AI 提醒功能” |
| `对方被期待提供什么` | 如“提供明确开始时间”；没有明确期待写“未观察到” |
| `事项可见状态` | 完成 / 未完成或受阻 / 仅有进展 / 未看到 / 无法判断 |
| `事项关键缺口/备注` | 只写会影响判断的缺口，如“缺附件内容”；没有可空 |

`sample_id`、涉及 `rn`、`sourceuid` 等溯源字段不再要求标注者手工搬运。等真实标注完成后，将由脚本按所填 `local_event_id` 自动汇总。

## 7. 当前待澄清规则

| ID | 问题 | 当前处理 |
| --- | --- | --- |
| R-12 | 真实 IM 现场恢复到什么程度才能开始正式标注 | 当前暂不正式填；先审表格和方法 |
| R-13 | 事项首行的识别是否还会带来负担 | 在真实 Case 试填时验证；若仍繁琐，再考虑自动识别首行 |
| R-14 | 较长样本中事项 ID 是否容易漏号或重号 | 允许 E1/E2… 无上限；正式试填后再评估自动校验 |
| R-15 | `模糊时效` 的边界词是否需要扩展 | 当前包括“尽快/抓紧/早点”等；遇到新边界例进 `06` |
