# ClassIn IM Topic 教学关联与求助校准维度

## 1. 为什么不再使用“无教学诉求”

“无教学诉求”将至少四个不同问题混在一起：

1. 内容是否与学习/教学相关；
2. 是否在进行知识讲解或答疑；
3. 是否在处理教学服务或教学管理；
4. 发言者是否明确请求帮助。

因此，Topic 名称只保留中性可见事实，不再追加“无教学诉求”。教学关联和求助状态由后置结构化维度独立表达。

## 2. 推荐的结构化维度

### 2.1 中性 Topic

回答“大家在讨论什么”，只写可见对象、事项、行动和状态，不写产品方案，不把“未见”改写为事实上不存在。

### 2.2 内容领域（可多选）

- 学科知识；
- 学习任务/作业；
- 考试/测评/成绩；
- 课程/教材/教学进度；
- 调课/请假/考勤/到课；
- 课堂技术/产品使用；
- 教师运营/薪酬/合同；
- 社交/关系；
- 情绪/家庭；
- 生活/兴趣/娱乐；
- 商业/投资/其他；
- 无法判断。

### 2.3 教学关联类型（可多选）

| 取值 | 定义 |
| --- | --- |
| 知识教学/答疑 | 讲解知识、解题、纠错或回答学科问题 |
| 学习任务 | 作业布置、提交、订正、打卡或学习计划 |
| 教学过程/反馈 | 课堂表现、学习进度、教材难度或教学方法反馈 |
| 教学服务 | 课件、录屏、文件、技术支持、课程资料或教学资源 |
| 教学管理 | 调课、请假、考勤、到课、排课、教师协同或课时核对 |
| 学习环境相关 | 学校、开学、军训等教育环境话题，但未进入教学任务/服务 |
| 未见教学关联 | 当前100条窗口中未见与上述教学类型相关的可见内容 |
| 无法判断 | 载荷缺失、语义无法理解或关键上下文不足 |

一个 Topic 可以同时属于多类，例如“家长反馈学生口语进步并协商教材难度”可同时属于“教学过程/反馈”和“教学服务”。

### 2.4 沟通目的（可多选）

- 通知/传达；
- 询问/澄清；
- 明确求助；
- 协调/调整；
- 提交/回传；
- 反馈/评价；
- 提醒/催促；
- 协商/决策；
- 情绪表达/支持；
- 社交闲聊/娱乐；
- 单向发布/刷屏；
- 无法判断。

### 2.5 求助状态（单选）

| 取值 | 什么时候选 |
| --- | --- |
| 明确求助 | 直接请求讲解、解决、提供、协助或代办 |
| 隐含困难，未明确求助 | 表达“不会”、“写不完”、“压力大”等困难，但没有要求对方帮助 |
| 未见求助 | 当前窗口只有分享、通知、闲聊或状态表达，未见求助行为 |
| 不适用 | Topic 本身是平台刷屏、系统文本或无语义载荷，不宜判断求助 |
| 无法判断 | 消息缺失或语义不可理解，无法安全区分上述值 |

“未见求助”只是当前100条窗口的可见结论，不等于会话外从未求助。

## 3. 校准示例

| 原表述 | 中性 Topic | 教学关联 | 沟通目的 | 求助状态 |
| --- | --- | --- | --- | --- |
| “讨论作业进度，无教学诉求” | 讨论作业进度，表示尚未完成 | 学习任务 | 询问/状态交流 | 隐含困难或未见求助，按原文判定 |
| “协调调课请假，无教学诉求” | 协调课程时间、请假与补课安排 | 教学管理 | 协调/调整 | 未见求助（不否定其服务价值） |
| “处理课件与录屏，无教学诉求” | 提供课件并处理录屏缺失/损坏 | 教学服务 | 提交/反馈/协调 | 按是否明确请求重发单独判定 |
| “作业写不完，无教学诉求” | 表示作业尚未完成并打算放弃 | 学习任务 | 状态/情绪表达 | 隐含困难，未明确求助 |
| “讨论游戏，无教学诉求” | 讨论游戏角色和玩法，约定一起游戏 | 未见教学关联 | 社交闲聊/娱乐 | 未见求助 |
| “询问压电效应” | 学生询问压电效应、电荷分离和晶体结构，老师连续讲解 | 知识教学/答疑 | 明确求助/讲解 | 明确求助 |

## 4. 执行边界

- 结构化维度是 AI 证据回链阶段的候选 Codebook，不直接作为全量统计结论；
- 每个值都需要对应可见消息范围、有效发言数和置信度；
- 一条 Topic 可以多领域、多目的、多教学关联，但求助状态保持单选；
- 低置信度、边界和反例进入人工复核，不由 AI 自动升级为事实。
