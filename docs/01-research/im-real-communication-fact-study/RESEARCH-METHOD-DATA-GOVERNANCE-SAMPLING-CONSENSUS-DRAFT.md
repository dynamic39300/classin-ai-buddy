## 2. 原始数据与版本治理

### 2.1 数据分层

| 层 | 定义 | 允许操作 | 禁止操作 |
| --- | --- | --- | --- |
| L0 原始输入 | 用户提供的固定版本工作簿 | 只读、计算指纹、结构扫描 | 覆盖、改值、删除行、写回标签 |
| L1 结构化派生 | 类型统一、字段拆解、技术去重、缺失标记 | 使用版本化规则生成 | 静默修复、覆盖 L0、丢弃无日志样本 |
| L2 研究样本 | 从明确抽样框得到的受限样本 | 脱敏、编号、上下文保全 | 以规则命中样本替代概率样本 |
| L3 人工真值 | 按标注手册形成的标签与分歧记录 | 双人标注、仲裁、版本化 | 覆盖原标注、隐藏分歧 |
| L4 聚合结论 | 可复算统计、证据案例和边界 | 输出匿名聚合 | 输出可识别个人信息、夸大因果 |

### 2.2 版本标识

每个派生数据集至少记录：

- 来源文件 SHA-256；
- 生成时间、脚本版本或提交状态；
- 使用的字段映射和清洗规则版本；
- 输入行数、输出行数、排除行数和原因分布；
- 随机种子；
- 敏感等级、存放位置和保留期限；
- 已知缺陷与不可回答问题。

## 3. 数据字典与质量审计

在讨论语义标签前，先对每个字段建立下表：

| 字段 | 来源表 | 业务含义 | 类型 | 粒度 | 缺失率 | 唯一性 | 异常值 | 是否敏感 | 能支持的判断 | 不能支持的判断 |
| --- | --- | --- | --- | --- | ---: | ---: | --- | --- | --- | --- |
| 待审计 |  |  |  |  |  |  |  |  |  |  |

必须单独检查：

1. 会话是否为完整会话，固定 100 行的生成逻辑是什么；
2. 时间戳是否完整、排序一致、跨天和时区如何处理；
3. 消息类型、附件、撤回、系统消息是否有缺失或文本占位；
4. 单聊参与者角色、关系和方向是否存在可靠字段；
5. 群聊中的群类型、成员角色、人数与班级事实是否可靠；
6. 同一消息、模板、转发、长文本和重复导出如何识别；
7. 数据窗口左/右截断对事件开始和结局造成什么影响；
8. 是否缺失已读、回复关系、引用、@、通知、跳转、业务对象 ID 和最终结果。

## 4. 脏数据、缺失和修正规则

所有问题进入 `Data Issue Register`，不在代码里隐式处理：

| Issue ID | 现象 | 影响范围 | 类型 | 是否可修 | 处理候选 | 影响量 | 决策状态 |
| --- | --- | --- | --- | --- | --- | ---: | --- |
| 待登记 |  |  | 缺失/错误/重复/截断/歧义 |  | 保留/修正/排除/分层/未知 |  | 待确认 |

处理原则：

- **缺失**：缺失不是“否”，保留为显式 `unknown/missing`；
- **技术重复**：只有稳定键或完整字段一致且规则经审阅时才去重；
- **业务重复**：同一通知被重复发送可能正是研究事实，不做技术去重；
- **角色冲突**：不以消息内容猜身份，保留冲突并进入数据分层；
- **时间异常**：保留原值和标准化值，记录修正原因；
- **模板/长文本**：作为内容形态研究，不因易误标就直接删除；
- **截断**：显式标记左截断、右截断和双向截断，不把片段当完整闭环；
- **无法修复**：说明该数据不能支持哪些结论，而不是用推断填补。

## 5. 抽样设计与样本保全

### 5.1 两条样本轨道

| 轨道 | 目的 | 是否支持比例估计 | 选取方式 |
| --- | --- | --- | --- |
| A 代表性样本 | 估计真实分布、比较渠道与分层 | 在抽样框可靠且加权正确时支持 | 从完整抽样框分层随机抽取 |
| B 发现性样本 | 寻找罕见、边界、高风险和复杂 Case | 不支持总体发生率 | 规则、极端值、人工推荐等目的抽样 |

两条轨道不能合并计算总体比例。规则命中样本只能进入 B，除非它同时通过 A 的随机抽取进入代表性样本。

### 5.2 抽样单位待定

必须先比较以下候选，再确定主单位：

- 完整会话；
- 固定窗口内的连续沟通片段；
- 围绕一个对象/事项的沟通事件；
- 单条消息；
- 群/参与关系在时间窗口内的整体记录。

消息适合描述内容形态，不足以独立判断需求；事件适合理解任务，但需要可靠切分和上下文。正式分析可能采用“会话/群抽样 → 事件标注 → 消息证据”的多级设计。

### 5.3 必备分层维度候选

- 渠道：单聊 / 群聊；
- 群类型：师生班级群 / 教学运营管理群 / 其他 / 无法判断；
- 参与关系：老师—学生 / 学生—学生 / 教职工—教职工 / 其他 / 未知；
- 活跃度：低 / 中 / 高；
- 时间：日期、星期、时段、开课前后、数据窗口边缘；
- 内容形态：纯文本 / 图片 / 文件 / 链接 / 系统事件 / 混合；
- 长度与完整性：短片段 / 长片段 / 左截断 / 右截断；
- 机构、班级、学科等字段：仅在确有可靠字段且满足隐私最小化时使用。

### 5.4 样本保全日志

每个候选样本必须拥有稳定 `sample_id`，并记录：

- 所属抽样框与入样概率；
- 分层值和随机排序值；
- 抽中、读取失败、上下文不足、排除、替补和仲裁状态；
- 原样本被替补的原因与替补样本 ID；
- 是否可用于分布估计、只可用于发现，或完全不可用。

不得为追求“好看的 Case”静默换样。

## 6. 中性分析维度候选

以下维度用于描述事实，不预设对应 Product Feature：

| 维度 | 核心问题 | 典型值示例 |
| --- | --- | --- |
| 参与关系 | 谁与谁沟通，身份是否可靠？ | 师生、同学、教职工、未知 |
| 沟通场景 | 在什么群/关系与业务环境中发生？ | 班级教学、教务运营、私下协调、未知 |
| 业务对象 | 围绕什么客体？ | 课程、课堂、作业、考试、资料、账号、无明确对象 |
| 表层意图 | 这一发言在做什么？ | 询问、告知、请求、提交、确认、纠正、反馈、闲聊 |
| 潜在任务 | 是否存在需要推进的事情？ | 有明确任务、需澄清、仅表达、无法判断 |
| 任务角色 | 谁发起、负责、协作、等待或受影响？ | 发起者、执行者、审批者、接收者、未知 |
| 信息结构 | 完成沟通需要哪些信息？ | 时间、地点、对象、材料、截止、状态、原因 |
| 生命周期 | 事情推进到哪一步？ | 发起、补充、确认、执行、结果、关闭、悬置 |
| 摩擦 | 发生了什么沟通成本？ | 重复问答、信息缺失、查找困难、催促、误解、跨页跳转 |
| 结果证据 | 数据实际证明了什么结果？ | 明确完成、明确未完成、仅回复、无证据 |
| 情绪与关系 | 是否存在影响交流的情绪/关系信号？ | 中性、感谢、焦虑、冲突、鼓励；仅作辅助维度 |
| 敏感性 | 内容涉及何种风险？ | 学生身份、成绩、健康、家庭、账号、无明显敏感项 |
| 不确定性 | 为什么无法判断？ | 角色缺失、上下文截断、附件缺失、语义歧义 |

关键边界：一句“今天题目真难”可以被标为“表达/感受 + 作业或题目对象（若上下文明确）”，但不能自动标为“学习任务”“求助需求”或“需要 AI 解题”。只有出现请求、后续任务、阻塞证据或其他明确上下文时，才能升级相应判断。

## 7. 小规模标注实验

### 7.1 目标

小规模试标不是为了产出主题排行榜，而是验证：

1. 抽样是否覆盖关键分层与数据边缘；
2. 标注者是否能用同一规则区分事实、推断和未知；
3. 标签是否互斥、可多选或存在依赖关系；
4. 一段上下文是否足够支持判断；
5. 分歧集中在哪些概念和 Case；
6. 数据是否足以回答研究问题。

### 7.2 试标流程候选

1. 先从 A 轨道抽取一批覆盖所有主分层的代表性样本；
2. 从 B 轨道补入易误判、长模板、闲聊、教学管理群、复杂多轮、截断、附件缺失等边界样本；
3. 两名标注者独立标注，不先看到旧规则标签；
4. 记录逐字段分歧，不只计算一个总一致率；
5. 第三方或双方会议仲裁，更新标注手册与边界例；
6. 用修订手册重新标一小批未见样本；
7. 达到质量 Gate 后才确定扩展样本量。

### 7.3 质量指标候选

- 各主标签原始一致率；
- 对分类标签使用 Cohen's kappa 或适合多标注者/多标签的指标；
- 对多标签集合报告 micro/macro precision、recall、F1 与 exact match；
- `unknown` 使用率及其原因分布；
- 上下文不足率、截断率和附件缺失率；
- 仲裁后规则改动数与影响样本数；
- 对关键高风险标签设置单独 precision 下限。

具体阈值不在本草案中拍定，应结合标签基线率、样本量和用途共同确认。

## 8. 指标字典模板

每个数字必须先登记：

| 字段 | 要求 |
| --- | --- |
| 指标名称 | 不使用容易误读的简称 |
| 研究问题 | 该指标回答哪个问题 |
| 分析单位 | 消息/片段/会话/事件/参与者 |
| 分子 | 精确定义、是否多标签重复计数 |
| 分母 | 精确定义、过滤与缺失范围 |
| 去重键 | 无则明确写无 |
| 时间窗口 | 起止日期、时区和边界 |
| 分层/权重 | 抽样权重及适用总体 |
| 缺失处理 | 保留、排除或单列及其影响 |
| 置信表达 | 点估计、区间或仅描述性 |
| 可支持结论 | 允许写到什么程度 |
| 禁止推论 | 不允许被解释成什么 |
| 复算方法 | 数据版本、脚本和参数 |

示例：若计算“含明确求助事件的单聊会话比例”，分子应是经人工真值确认至少包含一个明确求助事件的**可判定完整单聊会话数**；分母是对应抽样框内**具备足够上下文且关系范围符合定义的可判定完整单聊会话数**。它不是求助消息占比，也不能直接代表 AI 可介入比例。

## 9. 从事实到能力的延迟映射

第一部分报告只允许在末尾记录“待验证启示”，且必须指向具体事实、反例和不确定性。进入第二部分时再使用统一决策链：

```text
事实模式
  → 用户任务与摩擦
  → 当前替代办法
  → 基础 IM / 业务流程 / AI / 不应产品化
  → 介入节点与治理边界
  → 价值、风险、可验证指标
```

不能从“高频”直接跳到“要做”；也不能因为低频就排除高风险、高价值或基础设施级问题。

## 11. 待共同确认的问题

1. 原始导出中的“一组 100 行消息”是如何抽取的：每个会话最新 100 条、随机 100 条，还是其他逻辑？
2. 是否能获得会话总消息数、消息在完整会话中的序号，或更长的上下文？
3. 是否存在可靠的用户角色、班级类型、群用途、机构或业务对象字段，但未包含在当前文件中？
4. 正式研究的主要总体是所有导出会话、真实师生会话，还是老师参与的教学沟通？三者需要不同抽样框。
5. 人工标注由谁参与，是否至少可以安排两名独立判断者与一次仲裁？
6. 首轮试标希望优先验证方法可靠性，还是同时希望得到可供产品团队阅读的 Case 图谱？两者可兼容，但样本配置不同。
7. 真实消息派生样本的允许存放位置、保留期限和参与者访问范围是什么？
