# ClassIn IM Pilot 0 v2.3.1 角色上下文增强标注指南

> **版本通知（2026-08-30）**：角色上下文规则继续有效；当前填写入口已升级为 [v2.3.2 一体化审阅操作指南](./PILOT0-ANNOTATION-OPERATING-GUIDE-V2-3-2.md)。本文件作为角色字段规则与审计轨迹保留。

## 1. 当前状态

v2.3.1 曾用于方法、角色上下文与表格可用性审阅，现作为角色规则和证据基线保留。正式填写入口已转到 v2.3.2；真实 IM 上下文恢复充分前仍不启动 A/B 独立正式标注。

v2.3 的逐条证据、事项首行、时效四值、分轨和完成自检规则继续有效，详见 [v2.3 合并简化指南](./PILOT0-ANNOTATION-OPERATING-GUIDE-V2-3.md)。本版只增加原表发言人和角色上下文。

## 2. 两个核心字段怎么用

| 字段 | 能直接说明什么 | 正确用法 | 不能怎么用 |
| --- | --- | --- | --- |
| `strtalker` | 原表中当前消息的发言人显示名 | 与 `sourceuid` 联合区分“谁在说话”，追踪同一发言人的连续消息 | 仅凭姓名、称呼或头像文字猜老师/学生 |
| `user_type` | 原表中当前消息的系统角色：班主任/教师/学生/旁听生/其他 | 作为当前消息和当前样本的角色上下文 | 把某条消息的角色固化成该 `sourceuid` 的全局永久身份 |

辅助字段：

- `msgdata.strTalker`：只用来与 `strtalker` 核对；它缺失时，以更完整的 `strtalker` 为主；
- `identity`：是 `user_type` 的原始编码校验，不要求标注者记住数字映射；
- `sourceuid`：用于稳定区分发言人，避免同名或显示名变化影响判断。

## 4. 在工作簿哪里看

| 工作表 | 使用方式 |
| --- | --- |
| `02_原表字段索引` | 保留 `identity`、`user_type`、`strtalker`、`msgdata.strTalker` 和 `sourceuid` 原值，用于精确回查 |
| `03_逐条开放编码` | J 列将 `strtalker` 标为主要发言人显示名；K 列是校验；L 列是当前消息 `user_type` |
| `01_样本与会话映射` | M:O 机械汇总当前样本的发言人、角色人数/消息数和多值/缺失提示 |
| `05_样本总结` | N:P 将同样的只读角色背景并列到样本总结，避免手工切表 |
| `00B_字段速查` | 增加两个核心字段、辅助校验字段和多值提示的 Good/Bad case |

样本级“可见角色构成”同时显示发言人数和消息数，例如：`学生：3人/17条；班主任：1人/13条`。它是当前30条可见样本窗口的结构描述，不是完整会话总体结论。

## 5. 标注时的判断顺序

1. 先用 `strtalker + sourceuid` 区分发言人；
2. 再读 `user_type` 作为当前消息的角色背景；
3. 读完同一 `sample_id` 的灰色上下文和核心行；
4. 再标消息作用、`local_event_id` 和事项首行；
5. 如同一 `sourceuid` 出现多个 `user_type`，保留原表多值并在样本提示中记录，不自行选一个覆盖。

## 6. 新增待澄清规则

| ID | 问题 | 当前处理 |
| --- | --- | --- |
| R-16 | `user_type` 是用户、班级成员关系还是消息时点角色 | 当前只按原表当前消息角色使用，等导出定义确认 |
| R-17 | 同一 `sourceuid` 多角色的业务或数据原因 | 当前保留多值，不归并、不报错、不猜原因 |
| R-18 | `strtalker` 缺失或与 `msgdata.strTalker` 不一致时如何处理 | 优先保留 `strtalker`；差异进入只读提示，不静默覆盖 |
