# ClassIn IM Topic Pilot 50 人工标注指南 v1.1

## 1. 第一性原理

人工标注的目的不是逐句复述消息，也不是预先证明某项 IM/AI 功能有价值，而是从完整聊天现场识别：

1. 人们实际在聊哪些 Topic；
2. Topic 是闲聊、信息表达、教学/学习、服务协同、寻求帮助，还是其他尚未命名的内容；
3. 可见聊天中是否真的出现诉求、行动、阻碍或不确定性；
4. 哪些内容在当前100条消息中形成了足够显著的讨论，哪些只是短暂表达。

主要分析单位是“一个100条消息案例中的 Topic/沟通片段”。单条消息只作为证据回链，不再要求逐字段编码。

## 3. Topic 准入规则

1. 同一语义 Topic 在当前100条消息中至少出现 **5条有效发言**，才写入 Topic 列。
2. “有效发言”不等于 Excel 行数。纯表情、重复发送、无语义符号，以及为了输入而拆成多条的同一句话，不应机械累加。
3. 少于5条的短暂表达、插曲或边缘事件不纳入当前 Topic 层；这不是“漏标”。
4. 发言数只衡量该 Topic 在当前聊天窗口里的**对话显著度/注意力**，不等于严重程度、业务价值或产品优先级。
5. 人工只负责识别 Topic，不需要精确数发言数。后续由 AI 回链原文、归并语义等价表达并提供可复核计数。

为了后续校准，可先使用下列**临时强度分层**，但不把它当作总体统计结论：

- 5–9条：次要 Topic；
- 10–19条：明显 Topic；
- 20条及以上：核心 Topic。

## 4. 三批执行

| 批次 | 数量 | 用途 | 操作约束 |
| --- | ---: | --- | --- |

## 5. Topic 怎么写

推荐句式：`沟通对象/事项 + 可见动作或诉求 + 必要限定`。

Good：

- `讨论周末聚餐安排，无教学诉求`；
- `询问课程开始时间，并提出调课请求`；
- `反馈作业文件无法打开，请求重新发送`；
- `表达题目困难，但未看到进一步求助`。

Bad：

- `课程相关`：过宽，无法说明在聊什么；
- `需要AI调课助手`：这是产品方案，不是聊天事实；
- `学生需要题目讲解`：若只说“今天的题太难了”，这是越过证据推断诉求；
- 把同一段连续问答机械拆成十几个“消息 Topic”。

闲聊、无明确事项和上下文不足都可以成为 Topic，但同样需要达到5条有效发言的准入门槛；不强行改写成教学任务。

## 7. 人机协作顺序

1. 人工通读案例，只在 J 列写入符合准入门槛的 Topic；
2. AI 在人工 Topic 与原始证据基础上回链消息、计算有效发言数/权重，再做结构化拆解，同时给出置信度；
3. 人工复核 AI 拆解，保留分歧和修订理由；
4. 前两批形成候选 Codebook；
5. 第三批检验规则是否能迁移；
6. 通过 Gate 后才讨论扩展到更多数据。

在此之前，不输出主题发生率、需求优先级或产品结论。
