# ClassIn IM 原始元数据与字段语义问题登记

## 1. 解释规则

字段研究严格分成四层：

1. **原始表述**：Excel 表头及其括号内说明，原样记录；
2. **取值证据**：仅由当前固定版本数据机械统计得到；
3. **暂定解释**：为继续技术处理而提出，可被推翻，不算业务事实；
4. **待确认问题**：仅靠数据无法回答，需要数据提供方或用户校准。

上一轮分析报告不是字段语义来源。即使原始表头提供了业务说明，也只证明“数据提供者这样描述该字段”，不自动证明生成 SQL、时点口径、完整性和所有边界场景。

## 2. 字段溯源表

| 字段 | 原始表述 | 当前取值证据 | 暂定技术处理 | 仍待确认 |
| --- | --- | --- | --- | --- |
| `identity` | `identity（发言用户身份）` | 群聊多为数值；单聊全部为字符串 `NULL` | 单聊身份保持未知 | 数值码字典；字符串 `NULL` 的生成逻辑 |
| `user_type` | `user_type（用户类型：班主任/旁听生/教师/其他/学生）` | 群聊出现所列类型；单聊全部为“其他” | 只描述导出行上的类型，不推断完整成员构成 | 类型来源、时点、单聊为何统一为“其他” |
| `user_num` | `user_num（这字段是跑数据时候做的标记，包括三类：班级成员数<30，[30,100), [100,), 以区分不同群的规模，聊天的内容，主题是否有差异）` | 仅三档；单聊也全部落入 `<30` 档 | 只对 `clustertype=0` 做结构分层；不参与语义结论 | 成员数取值时点；是否含退群成员；为何单聊被赋档 |
| `id` | `id（会话消息id）` | 全局唯一 | 暂作导出行稳定键 | 与 `msgid` 的区别；是否为业务主键 |
| `clusterid` | `clusterid（群id，如果是1v1私聊，系统也定义为1v1“群”的id，也认为是一个群，一个id即为一个私聊pair；如果是班级群聊，即为班级群id）` | 8,197 个值，每个恰好100行 | 当前导出窗口的一级单位 | 是否稳定跨时间；是否含已解散/退群关系；完整会话边界 |
| `clustertype` | `clustertype（群类型：1=1v1私聊，0=班级群聊）` | 只出现0/1，且每个 `clusterid` 内一致 | 仅按原始定义分为声明单聊/声明班级群 | `0` 是否只指正式班级群，是否还含运营/管理用途 |
| `msgbucketid` | 无说明 | 只出现4个值 | 不用于业务解释 | 分桶、分区还是业务字段；与消息检索的关系 |
| `msgid` | 无说明 | 全局重复；`clusterid + msgid` 在本文件内唯一 | 回复解析暂用复合键 | `msgid` 的真实作用域与生成规则 |
| `msgcmd` | 无说明 | 全表恒为 `50724904` | 只记录为单一命令值 | 命令字典；是否只导出了某一消息类型 |
| `msgdata` | 无说明 | 多数为包含 `content`、`strTalker` 的 JSON 对象，部分不是对象 JSON | 版本化正文提取的第一候选来源 | 消息协议、非对象分支、附件/表情等载荷定义 |
| `replymsgid` | 无说明 | 非零值可在部分同窗口消息中找到 | 只记录显式引用关系，不解释为回复或解决率 | 引用目标字段、作用域、0值和窗口外目标含义 |
| `sourceuid` | `sourceuid（发信人id）` | 可用于区分窗口内发送者 | 受限化名；不输出原值 | 账号主体类型、匿名角色映射、生命周期 |
| `targetuids` | 无说明 | 既有标量样式也有逗号列表样式 | 不解析为成员或可见范围 | 单聊/群聊各自语义；列表分隔和快照时点 |
| `timetag` | 无说明 | 约 `3×10^16`，不能按常见 Unix 缩放解释 | 暂不使用 | 单位、时区、排序意义 |
| `timeformat` | 无说明 | 与日期列和转换列一致，可解释为 Unix 秒 | 当前排序主字段 | 产生端时区、服务端/客户端时间、精度 |
| `dt` | 无说明 | 与 `timeformat` 转换后的本地日期一致 | 仅作字段一致性校验 | 是业务日期还是数仓分区日期 |
| `rn` | 无说明 | 每个 `clusterid` 严格为1–100，且时间正序 | 仅描述为固定正序窗口 | `PARTITION BY`、`ORDER BY`、截断与会话入样 SQL |
| `concent` | 无说明，字段名疑似 `content` 的拼写形式 | 多数与 `msgdata.content` 相同，但存在差异和空值 | 只作 fallback，不单独视为正文真值 | 生成逻辑、优先级、差异是否预期 |
| `strtalker` | 无说明 | 多数与 JSON 同名字段一致，少量缺失/差异 | 受限字段，不用来猜身份 | 是否为展示昵称；脱敏要求；差异原因 |
| `from_unixtime(a.timeformat)` | 原始表头即转换表达式 | 与 `timeformat` 到秒一致 | 仅作时间校验 | SQL 使用的时区和执行环境 |

## 3. 首批需要共同校准的问题

以下问题会影响抽样和解释，但在确认前都可以保持未知，不阻塞开放编码：

1. 8,197 个 `clusterid` 是日期范围内全部符合条件的会话，还是会话级再次抽样？
2. `rn` 是否来自 `row_number() over(partition by clusterid order by timeformat asc)` 并筛选 `rn <= 100`？
3. `id` 与 `msgid` 分别是什么主键，`replymsgid` 引用哪一个字段、作用域是否限于同一 `clusterid`？
4. `msgcmd=50724904` 代表什么消息类型；当前导出是否排除了图片、文件、表情和系统事件？
5. `clustertype=0` 的定义是“绑定班级的群”还是“师生教学用途群”；是否可能承载教务/排课/教师协作？
6. `user_num` 在什么时点计算，表示当前成员数、消息发生时成员数，还是导出时成员数？
7. `targetuids`、`msgbucketid`、`timetag` 的字段契约分别是什么？
8. `msgdata.content` 与 `concent` 哪一个是数据提供方定义的正文主来源，差异场景是否有明确规则？

获得回答后只更新本登记和版本化处理规则，不回写原始 Excel，也不追认上一轮报告为依据。
