# ClassIn IM Pilot 0 v2.3.3 字段精简审阅操作指南

## 1. 封存状态

v2.3.3 已于 2026-08-30 作为“逐条消息 + 事项事件”阶段方法封存，不再是当前人工填写入口。完整里程碑见[历史记录](../../07-history/stage-deliverables/20260830-ClassIn-IM逐条消息与事项标注方法里程碑.md)。

本版不生成主题比例、需求排序或 IM/AI 产品结论。它记录了当时关于消息证据、事项状态和推断边界的阶段判断，供只读复盘。

## 2. 实际填写路径

标准互动轨只填写 `03_逐条开放编码`：

1. 黄色消息层：每条核心消息填写；
2. 绿色事项层：同一事项只在首次出现行填写一次；
3. 紫色样本层：每个 `sample_id` 只在唯一紫色核心行填写一次。

`05_样本总结` 是紫色样本层的只读公式镜像，不填写。`P0-DIR1-01/02` 仍按单方可见边界轨填写 `03` 橙色简化字段和 `08_单方可见汇总`。

## 3. 事项层只保留三个字段

| 字段 | 填写规则 |
| --- | --- |
| `事项中性名称` | 用中性动作和对象命名，不使用产品 Feature 名称 |
| `对方被期待提供什么` | 写可见事项期待的答案、动作或材料 |
| `事项可见状态` | 按完整可见事项链选择完成 / 受阻 / 仅有进展 / 未看到 / 无法判断 |

原“事项关键缺口/备注”已删除。

### 请求刚发起时怎么填

“请尽快提交作业”是一个新请求。当前没有提交结果属于正常状态：

- 对方被期待提供什么：`提交作业材料`；
- 事项可见状态：`未看到`；
- 不推断学生未提交、逾期、故意不回或需要催办。

### 数据或证据确实受限时怎么填

统一写在消息层 `证据边界/推断警报`，例如：

- `附件未核验`；
- `关键前文缺失`；
- `角色关系未确认`；
- `窗口外结果不可见`。

这类记录描述的是研究者能看到的证据边界，不是用户或事项本身的“缺口”。

## 4. 其余已确认规则保持不变

- `本条是否回应前文`：是 / 否 / 无法判断；
- `时效要求`：明确时限 / 模糊时效 / 未见时效；“尽快”选择模糊时效；
- `本条提供的结果证据`：完成 / 受阻 / 仅有进展 / 未看到 / 无法判断；
- `strtalker + sourceuid` 用于区分发言人；`user_type` 只作为当前消息角色背景；
- `local_event_id` 按实际事项使用 `E1/E2/E3…`，不预设数量。

## 5. 完成一个标准样本的最小检查

1. 已先读完同一 `sample_id` 的灰色上下文和核心消息；
2. 黄色核心消息字段已按可见证据填写；
3. 同一事项沿用同一 `local_event_id`；
4. 每个事项只在首次出现行填写三个绿色字段；
5. 唯一紫色行完成一次样本总结；
6. `05` 能自动显示紫色行内容，且未重复填写；
7. 不确定规则进入 `06_字段问题`，不靠猜测补齐。
