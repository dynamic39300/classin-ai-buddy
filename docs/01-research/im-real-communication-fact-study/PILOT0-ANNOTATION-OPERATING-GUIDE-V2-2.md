# ClassIn IM Pilot 0 v2.2 分轨开放编码标注操作指南

> **版本通知（2026-08-30）**：v2.2 仍需要在 `03` 和 `04` 之间人工搬运事项 ID，且时间字段无法准确表达“尽快”。当前方法审阅请使用 [v2.3.2 一体化审阅操作指南](./PILOT0-ANNOTATION-OPERATING-GUIDE-V2-3-2.md)；本文件仅保留审计轨迹。

## 1. 本版解决什么问题

原 v2.1 把24个样本都放在同一填写路径中，但 `P0-DIR1-01/02` 的原始100行窗口只观察到一位发送者；其余单聊样本 `P0-DIR2-*` 在窗口内观察到两位发送者。若把两类样本混在一起，会把“导出窗口没有观察到另一位发送者”误写成“对方真实没有回复”。

v2.2 保留所有样本和原始字段，不删除 DIR1，只把填写路径分开：

| 轨道 | 样本 | 能回答什么 | 填写路径 |
| --- | --- | --- | --- |
| 标准互动轨 | `P0-DIR2-*` 与全部群聊样本 | 当前可见片段中的发起、回应、推进和结果 | `03` → `04` → `05` |
| 单方可见边界轨 | `P0-DIR1-01/02` | 当前窗口里这一位发送者做了什么、是否重复跟进、缺什么信息 | `03` 橙色行 → `08`；不填 `04/05` |

这里的“单方可见”是数据结构描述，不是用户关系、沟通态度或真实回复状态的结论。

## 2. 第一次怎么开始

1. 标注员 A、B 分别只填写自己的工作簿，不看对方答案；
2. 先阅读 `00_使用与溯源说明` 和 `00A_填写示例`；
3. **方法试填从 `P0-DIR2-01` 开始**，不要从工作簿最前面的 DIR1 样本开始；
4. 完成一个标准样本的 `03`、`04`、`05` 后，先检查字段理解和漏填，不讨论主题答案；
5. 再选择一个群聊样本试填；
6. 最后单独试填 `P0-DIR1-01` 的橙色行和 `08_单方可见汇总`；
7. 所有无法确定的规则进入 `06_字段问题`，不要靠猜测补齐。

## 3. 为什么仍然逐条标，但不能脱离上下文

逐条消息是证据定位单位，不是独立理解单位。正确顺序是：

1. 先读同一 `sample_id` 的全部灰色上下文和核心行；
2. 理解当前片段中可能存在的事项；
3. 再回到每条核心消息，标记这条消息在上下文中的作用；
4. 标准轨用同一个 `local_event_id` 把围绕同一事项的多条消息连接起来；
5. 在 `04` 和 `05` 提升到事项、样本层总结。

因此既不是“只看一句话贴标签”，也不是把整段对话压成一行后丢失逐条证据。

## 4. 各工作表怎么用

| 工作表 | 用途 | 操作 |
| --- | --- | --- |
| `00_使用与溯源说明` | 净室规则、版本和分轨路径 | 阅读并确认 |
| `00A_填写示例` | 虚构示例、错误示范、单方边界例 | 只读 |
| `01_样本与会话映射` | 查看样本所属轨道和原表会话 | 只读 |
| `02_原表字段索引` | 用原表行号、ID、昵称和正文回查 | 只读 |
| `03_逐条开放编码` | 标准轨黄色核心行；单方轨橙色简化核心行 | 主要填写 |
| `04_事项汇总` | 标准轨的事项切分与推进结果 | DIR1 不填 |
| `05_样本总结` | 标准轨的整体事实与缺口 | DIR1 不填 |
| `06_字段问题` | 登记字段和判读歧义 | 有疑问才填 |
| `07_样本保全` | 检查样本未丢失、未替换 | 只读 |
| `08_单方可见汇总` | DIR1 的窗口结构、可见行为和证据缺口 | 仅 DIR1 填写 |

## 5. `03_逐条开放编码` 的统一字段

无论黄色还是橙色核心行，都要先填写：

| 字段 | 填写方法 |
| --- | --- |
| `可理解程度` | 清楚 / 部分清楚 / 无法理解 |
| `事实性概括` | 用中性短句说明发送者直接做了什么，不写身份猜测和产品解法 |
| `开放码1` | 用“动作 + 对象”的自由短语，如“询问开始时间” |
| `开放码2/3` | 只有确实存在第二、第三个可区分行为时才填 |
| `明确提问` | 是否明确索取事实、解释或答案；问号不自动等于提问 |
| `明确行动请求` | 是否明确要求对方执行动作 |
| `明确时间要求` | 文本是否直接给出日期、时段、期限或截止 |
| `提交/分享物` | 本条是否实际提交或声明已分享内容；请求别人提交不算 |
| `本条是否回应前文` | 只判断当前消息是否在回答、确认、拒绝、纠正或补充前文 |
| `上下文依赖` | 低 / 中 / 高 / 无法判断 |
| `推断警报` | 没有推断填“无”；有则写明缺失或猜测风险 |

标准轨还应填写 `结果证据` 与 `local_event_id`。单方轨中这两个字段可空，避免把不完整互动硬切成正常事项；必要时只记录直接可见事实。

## 6. “本条是否回应前文”的准确口径

该字段原名“出现回应”，容易让人误解为“这条消息后来有没有得到别人回答”，v2.2 已改名为 `本条是否回应前文`。

虚构对话：

| 消息 | `本条是否回应前文` | 理由 |
| --- | --- | --- |
| “明天几点开始？” | 否 | 本条在提出问题，不是在回应前文 |
| “明天19:00开始。” | 是 | 本条正在回答前一条问题 |

第一条后来确实获得回答，应在事项层记录“观察到回应/推进”，不能把第一条自身改成“是”。消息层描述本条角色，事项层描述后续发生了什么。

若核心片段第一条明显承接窗口外内容，但当前看不到前文，填“无法判断”，并在推断警报说明原因。

## 7. 标准互动轨怎么填

对 `P0-DIR2-*` 和群聊样本：

1. 先读完整可见片段；
2. 只填写黄色 `核心-需标注` 行；
3. 围绕同一对象、同一期望结果并连续推进的消息使用同一个 `local_event_id`；
4. `NONE` 表示问候、纯表达或没有明确事项；`UNKNOWN` 表示可能有关联事项但上下文不足；
5. 在 `04_事项汇总` 记录发起者、被期待提供什么、可见推进、结果、摩擦和缺失上下文；
6. 在 `05_样本总结` 分开“直接可见事实”和“待验证解释”。

“收到”通常只能证明出现回应，不自动证明事项完成。只有事项目标本身就是“确认收到”时，才可把它作为完成证据。

## 8. 单方可见边界轨怎么填

对 `P0-DIR1-01/02`：

1. 阅读完整100行回查信息和当前可见片段；
2. 在 `03` 只填橙色 `单方核心-简化` 行；
3. 不填 `04_事项汇总` 和 `05_样本总结`；这些行已灰显并标注“只读·转08”；
4. 到 `08_单方可见汇总` 填写 E–M 列。

`08` 字段口径：

| 字段 | 填写方法 |
| --- | --- |
| `发送者主要行为` | 概括当前窗口内反复出现或最主要的询问、请求、补充、告知等 |
| `是否重复跟进` | 是否能观察到同一发送者再次追问或催办；不能理解对象时可填无法判断 |
| `是否出现明确问题或请求` | 只看可见文本是否存在清晰问题/行动请求 |
| `窗口内是否观察到对方发言` | DIR1 当前证据通常填“否”，它只是窗口观察值 |
| `对方实际是否回应` | 当前数据不能证明时填“无法判断” |
| `可见结果` | 只记录窗口内直接出现的完成、受阻、进展或无法判断 |
| `缺失信息` | 如另一方消息、窗口外上下文、附件内容、事项结果 |
| `置信度` | 对上述可见事实判断的信心，不是对原因猜测的信心 |

允许写：“当前窗口未观察到另一位发送者”“发送者重复询问时间”。禁止写：“对方故意不回”“对方拒绝沟通”“这里需要 AI 催办”，除非原文有直接证据；产品解释不属于本轮标注。

## 9. 常见误标

- 把“窗口内未观察到”写成“真实没有发生”；
- 把一句感叹直接升级为学习任务或求助需求；
- 用昵称、称呼或正文猜测老师/学生身份；
- 把提问消息因为后文有回答而标成“本条回应前文=是”；
- 把“收到”直接标成事项完成；
- 把请求别人发文件标成“本条提交/分享物=是”；
- 把多个互不相关事项因为都提到课程而合并；
- 在开放码或备注里写 IM/AI 功能建议。

## 10. 待澄清规则清单

| ID | 规则 | 状态 | 当前执行方式 |
| --- | --- | --- | --- |
| R-01 | 消息是证据定位单位，事项是主要理解单位 | 待试标验证 | 先读全段、逐条标、再汇总事项 |
| R-02 | “收到”“嗯”等最小回复怎样归入事项 | 待试标验证 | 明确承接时跟随事项；不足时用 `UNKNOWN` |
| R-03 | 事实概括与开放码允许多大程度重复 | 待试标验证 | 事实概括写句子，开放码写可复用短语 |
| R-04 | 后续是否获得回应/结果应在事项层判断 | 已确认 | 不回写到原提问消息的回应字段 |
| R-05 | 条件必填字段是否还需进一步收缩 | 待试标验证 | 先按工作簿色带执行，在 `06` 登记负担 |
| R-06 | “出现回应”改名为“本条是否回应前文” | 已确认 | v2.2 已执行 |
| R-07 | 单方可见样本保留，但与正常互动分轨 | 已确认 | DIR1 不删除，进入单方边界轨 |
| R-08 | 首个方法试填样本使用 `P0-DIR2-01` | 已确认 | 不再从最前两个 DIR1 样本开始 |
| R-09 | DIR1 是真实未回复还是导出遗漏 | 开放问题 | 当前一律不下结论，等待导出机制或更完整数据 |
| R-10 | DIR1 使用简化标注，不做正常事项闭环 | 已确认 | `03` 橙色行 + `08`，不填 `04/05` |
| R-11 | “未观察到回应”与“实际没有回应”必须分开 | 已确认 | 前者可标，后者无证据时填无法判断 |

## 11. 完成前自检

- 是否先读完整样本，再逐条填写；
- 是否从 `P0-DIR2-01` 开始方法试填；
- 是否只填黄色/橙色核心行，没有改灰色原始字段；
- 是否把提问消息与后续回答的两个层次分开；
- 是否让 DIR1 只进入 `03 + 08`；
- 是否把未知保留为未知；
- 是否没有写入主题比例、产品结论或 IM/AI 功能建议；
- 是否把规则疑问登记到 `06_字段问题`。
