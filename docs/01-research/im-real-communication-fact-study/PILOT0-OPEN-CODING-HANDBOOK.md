# ClassIn IM Pilot 0 开放编码手册

> **封存通知（2026-08-30）**：本手册及 v2.3.3 逐条消息/事项方法已封存为阶段里程碑，不再作为填写入口。当前人工执行见 [Topic Pilot 50 指南](./TOPIC-PILOT50-HUMAN-ANNOTATION-GUIDE-V1.md)。本文件继续保存旧方法的证据治理规则。

标注者的历史逐字段填写方法、虚构完整案例、单方可见边界和完成自检，见 [可溯源开放编码标注操作指南 v2.3.3](./PILOT0-ANNOTATION-OPERATING-GUIDE-V2-3-3.md)。角色上下文证据见 [v2.3.1 指南](./PILOT0-ANNOTATION-OPERATING-GUIDE-V2-3-1.md)。

## 1. 目标与边界

Pilot 0 不验证任何既有主题分类，也不回答“最应该做什么功能”。它只验证三件事：真实消息是否能在现有上下文下被人稳定理解、哪些沟通事实可以直接观察、主题与事项能否从 Case 中自然形成。

本轮禁止提供教学主题列表、产品机会、AI 能力或旧标签。标注者需要使用自己的语言描述看见的内容；事后归并同义码时必须保留原始开放码。

### 原表值与溯源

当前工作簿允许显示原始 Excel 已有的真实字段值，包括原表行号、消息/会话/发送者标识和昵称。它们只用于回查同一原表记录：

- 不代表外部真人身份；
- 不允许反查或补充原表之外的信息；
- `msgid` 不是全局唯一，优先用 `source_excel_row` 或原表 `id` 定位；
- 解释回复时联合 `clusterid + msgid + replymsgid`，不得跨会话全局匹配；
- 单聊仍不能仅凭昵称、称呼或内容确定师生关系。

### 原表发言人与角色上下文

- `strtalker + sourceuid` 用来区分当前是谁在说话；`strtalker` 本身不是角色真值；
- `user_type` 作为当前消息的原表角色上下文，不固化为用户全局永久身份；
- `msgdata.strTalker` 只用于校验，缺失时不覆盖 `strtalker`；
- 同一 `sourceuid` 角色多值保持原样，不自动归并或猜测原因。

## 2. 标注前声明

标注者开始前需确认：

- 没有阅读 Round 0 分析、旧人工复核表、产品方案或竞品材料；
- 不搜索外部参与者身份，不把原表昵称或 ID 还原为真人；
- 原表回查只在原始 Excel 和受限 v2 工作簿内完成，不复制到仓库或公共服务；
- 不因某个 Case “没有价值”而跳过或换样；
- 没有证据时使用“无法判断”，不追求把每条消息归入主题。

## 3. 审阅单位

每个样本包含固定20条核心消息，以及前后各最多5条只读上下文。

| 区域 | 标注要求 | 用途 |
| --- | --- | --- |
| 上下文行 | 不做消息编码，只读 | 理解代词、引用和事项边界 |
| 核心行 | 逐条记录观察 | 形成开放码与可观察事实 |
| 连续事项 | 样本级汇总 | 识别一段沟通是否围绕同一件事 |

不得向窗口外扩展上下文。确需扩展时先记录 `上下文不足`，由研究负责人生成新版本，原判断不覆盖。

## 4. 第一遍：逐条开放观察

每条核心消息填写以下字段。除枚举字段外，全部使用脱敏概括，不复制姓名、联系方式、账号或其他可识别信息。

| 字段 | 填写规则 |
| --- | --- |
| `可理解程度` | `清楚` / `部分清楚` / `无法理解` |
| `事实性概括` | 用一句中性短句描述这条消息直接说了什么；不写动机和产品解释 |
| `原始开放码1–3` | 用标注者自己的短语概括正在发生的沟通；不从预设主题中选择 |
| `是否出现明确提问` | `是` / `否` / `无法判断`；只认文本或上下文中可见的问询 |
| `是否出现明确行动请求` | `是` / `否` / `无法判断`；“希望、请、麻烦、需要做”等不是单独充分条件，需看具体语义 |
| `时效要求` | `明确时限` / `模糊时效` / `无` / `无法判断`；“尽快”属于模糊时效 |
| `是否出现提交/分享物` | `是` / `否` / `无法判断`；只记录可见行为，不判断质量 |
| `本条是否回应前文` | `是` / `否` / `不适用` / `无法判断`；只判断当前消息的作用，后续是否获得回答属于事项层 |
| `是否出现结果证据` | `完成` / `未完成或受阻` / `仅有进展` / `未看到` / `无法判断` |
| `上下文依赖` | `低` / `中` / `高`；高依赖时不得强行归类 |
| `推断警报` | 若判断涉及猜身份、猜群用途、猜需求、猜结果或猜动机，写出推断点；没有则填 `无` |

### 事实性概括的例子

- 合格：“发送者询问一个时间信息。”
- 合格：“发送者表达某项内容有难度，没有提出请求。”
- 不合格：“学生急需 AI 帮忙解题。”——身份、紧迫度和产品解法都不是直接事实。

## 5. 第二遍：样本内事项切分

完成逐条观察后，按“是否围绕同一对象、期望结果和连续回应”把核心片段切成若干 `local_event_id`。无法切分时允许标记 `UNKNOWN`。事项 ID 按实际出现数使用 `E1/E2/E3…`，不预置五个事项，不设上限。

每个事项只在该 ID 第一次出现的消息行记录：

| 字段 | 填写规则 |
| --- | --- |
| `事项中性名称` | 标注者自由命名，不使用产品 Feature 名称 |
| `对方被期待提供什么` | 自由文本；无明确期待则写“未观察到” |
| `事项可见状态` | 完成 / 未完成或受阻 / 仅有进展 / 未看到 / 无法判断 |

新请求尚未出现结果时，事项状态填写“未看到”，不另建缺口字段。窗口截断、附件未核验等数据限制统一记录在消息层“证据边界/推断警报”。

`sample_id`、涉及 `rn`、`sourceuid` 和发起者等可从消息行恢复的字段，不再由标注者跨表手工搬运，后续由脚本自动汇总。

“没有形成事项”“只有表达/社交”“主要是不可理解载荷”都是有效结果，不得为了产出主题而强行切分。

## 6. 样本级判断

每个样本完成后记录：

- 当前片段整体是否足以理解：充分 / 部分 / 不足；
- 是否观察到一个或多个明确事项：是 / 否 / 无法判断；
- 标注者认为最能描述该片段的 1–3 个自由主题短语；
- 哪些判断是直接事实，哪些只是待验证解释；
- 是否需要补充数据字段或扩大上下文；
- 标注置信度与理由。

群聊不得仅凭“只有教师/班主任发言”判定为教学管理群；单聊不得从称呼或内容猜测师生关系。

## 7. 双人独立规则

1. A/B 使用独立工作表，不查看彼此开放码和概括；
2. 两人先完整完成逐条观察，再完成事项切分；
3. 仲裁前不统一主题叫法，避免过早收敛；
4. 结构字段可以计算一致率；自由开放码先做语义聚类和差异说明，不直接套既有 Codebook；
5. 仲裁必须保留 A 原始码、B 原始码、归并理由和未解决分歧。

## 8. 首轮后的 Codebook 形成

Pilot 0 完成后，按以下顺序形成候选 Codebook v0.1：

1. 汇总 A/B 的全部原始开放码，不删除低频码；
2. 仅合并语义等价或上下位关系明确的词；
3. 为每个候选码写入定义、包含条件、排除条件、正例、反例和易混淆项；
4. 标记来源样本数、标注者数和分歧情况；
5. 将“事实对象”“沟通行为”“问题/摩擦”“解释假设”分层，不能混成一个主题；
6. 使用未参与 Codebook 形成的新样本进行盲测；
7. 只有通过盲测的码才进入后续统计标签体系。

## 9. Pilot 0 Gate

只有同时满足以下条件，才能进入 Codebook 验证：

- 24/24 样本有明确状态，480/480 核心行无静默丢失；
- 两名标注者均完成独立标注与净室声明；
- 至少90%的样本可以完成事实性概括，或明确记录无法完成的原因；
- 单聊关系、群用途和结果状态没有被凭内容擅自升级为事实；
- 自由开放码、原始分歧、样本损失和上下文不足均完整保留；
- 没有引用 Round 0、旧样本表、产品方案或竞品材料。

Pilot 0 仍不产生主题发生率、平台占比或产品优先级。
