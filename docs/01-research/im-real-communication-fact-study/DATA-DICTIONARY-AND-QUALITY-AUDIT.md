# ClassIn IM 原始工作簿数据字典与质量审计

> 本文只保留从原始 Excel 机械复算的结构证据。字段的业务含义不从上一轮分析报告继承；原始表头说明、实际取值、暂定解释和待确认问题已拆分到 [原始元数据与字段语义问题登记](./RAW-METADATA-AND-SEMANTIC-QUESTION-REGISTER.md)。文中的“当前可支持”只表示暂定技术用途，不是最终业务定义。

## 0. 审计结论

当前工作簿适合用于研究 **8,197 个被导出会话窗口中的沟通内容与结构**，但不能直接当作 8 月 1–27 日全量自然消息流，也不能直接回答“老师和学生真实需求的总体发生率”。

最关键的原因不是语义分类，而是抽样结构：

1. 8,197 个 `clusterid` 每个都严格包含 100 行，共 819,700 行；
2. 每个会话的 `rn` 都严格为 1–100；
3. 所有会话中 `rn=1` 的时间都早于 `rn=100`；
4. 这与“每个会话在筛选范围内按时间正序截取前 100 行”的结构完全一致，但仍需导出 SQL/说明最终确认；
5. 因此，高活跃会话在达到 100 行后被右截断，按日期统计会天然偏向窗口前部；任何日趋势、完整闭环、真实消息量和总体响应率都不能从当前文件直接推出。

本轮没有运行主题分类，也没有推导 IM/AI Feature。

## 3. 关键质量事实

### 3.1 当前文件是等会话、定长窗口，不是自然消息流

| 证据 | 结果 | 影响 |
| --- | ---: | --- |
| 每个会话行数 | 8,197/8,197 均为 100 | 所有会话对消息级比例贡献相同，不代表真实消息量权重 |
| `rn` 完整性 | 8,197/8,197 均为 1–100 | 明确存在导出层定长处理 |
| 时间方向 | 8,197/8,197 均为 `rn=1` 早于 `rn=100` | 强烈指向正序前 100 行；高活跃会话右截断 |
| 单聊窗口跨度 | 88 个≤1小时；986 个为7–27天 | 同样 100 行可能代表完全不同活跃强度 |
| 群聊窗口跨度 | 531 个≤1小时；3,471 个为7–27天 | 不能只按100行把活跃强度视为相同 |

因此，当前可以讨论“窗口内的消息构成”，不能讨论“平台所有消息的构成”或“8 月日趋势”。

### 3.2 单聊角色完全缺失

- 1,805 个单聊窗口中，`user_type` 全部是“其他”，`identity` 全部是 `NULL`；
- 1,760 个窗口观察到两位发送者，45 个只观察到一位发送者；
- 这 1,805 个窗口不能直接命名为“老师—学生单聊”；它们可能包括师生、学生间、员工间或其他关系；
- 后续单聊语义试标必须把关系写为 `unknown`，除非获得独立角色映射。

### 3.3 “班级群”不是“师生教学群”的充分条件

在 6,392 个声明班级群窗口中，按前 100 行**已发言者**观察：

| 观察到的角色组合概括 | 窗口数 | 占群窗口 |
| --- | ---: | ---: |
| 学习者与教职工均发言 | 4,913 | 76.86% |
| 仅学习者发言 | 1,096 | 17.15% |
| 仅教师/班主任发言 | 383 | 5.99% |

383 个窗口只证明“导出窗口内观察到的发言者均为教师/班主任”，不能单独证明群用途。用户已明确提醒数据中可能存在教务/排课/管理沟通，但首轮开放编码不会预设群用途菜单，而是根据可见 Case 自由描述并保留未知。

### 3.4 消息类型信息不足

`msgcmd` 在全表恒定为 `50724904`。当前数据无法比较文本、图片、文件、表情、系统事件、撤回等 IM Feature 的真实使用结构。若该命令代表文本消息，则当前文件本身已经排除了其他类型；若不是，则需要命令字典解释。

### 3.5 正文应重新建立受治理的 canonical extractor

- `msgdata` 中 813,580 行是合法 JSON，`content` 与 `concent` 精确相等 803,525 行，去空白后再相等 3 行；
- 8,726 行二者不同；684 行仅 JSON `content` 非空；642 行两者都为空；
- 另有 6,120 行 `msgdata` 不是对象 JSON；
- 因此后续不能只读 `concent`。需要建立版本化正文提取规则，并对差异、空值、非 JSON 载荷分别记录。

### 3.6 回复引用证明截断，不能证明解决

- 70,005 行带非零 `replymsgid`，占全部行 8.54%；
- 57,294 条在同一 `clusterid` 的 100 行窗口内找到目标；
- 12,711 条未在同一窗口内找到，占显式回复 18.16%；
- 未命中可能来自前 100 行之外、当前日期范围之外、被删除内容或其他未导出类型；
- 无论是否命中，都不能被解释为“问题已解决”。

### 3.7 不做静默去重

- `id` 与 `clusterid + msgid` 均无重复；
- 完整 20 字段行没有精确重复；
- 排除行 ID/消息 ID 后，有 9,476 行呈相同会话、发送者、目标、时间、命令和载荷，约占 1.16%；
- 这些可能是合法重复通知、批量操作或技术重复。在人工确认前保持为事实，不清洗掉。

## 4. 当前可以与不能计算的指标

| 指标 | 当前可否计算 | 正确解释 |
| --- | --- | --- |
| 导出窗口中单聊/群聊占比 | 可以 | 8,197 个导出窗口的构成，不代表平台全部会话构成 |
| 每个窗口前100行中的内容分布 | 有条件 | 只能代表定长、右截断窗口 |
| 平台总消息量及渠道消息量 | 不可以 | 活跃会话超过100行部分被截断 |
| 8月每日活跃趋势 | 不可以 | 正序前100行造成日期偏前 |
| 师生单聊需求分布 | 不可以 | 单聊角色全部缺失 |
| 教学班级群需求分布 | 不可以直接算 | `clustertype=0` 混有管理/运营等可能群型 |
| 显式回复引用率 | 可以描述窗口值 | 不能等同回复率、解决率或体验效果 |
| 完整任务闭环率 | 不可以 | 缺上下文、结果字段且存在右截断 |
| 图片/文件/表情使用率 | 不可以 | `msgcmd` 单一且类型字典缺失 |
