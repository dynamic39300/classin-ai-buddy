# ClassIn IM 会话语义主题分析方法 V1

> 状态：本轮研究执行基线  
> 日期：2026-08-31  
> 研究规模：1,000 个会话窗口  
> 研究对象：原始 Excel 中可识别的 IM 会话窗口及其原始消息  
> 证据边界：仅使用原始数据、原始字段、原始字段的客观含义，以及本轮明确确认的研究规则

## 0. 文档用途与研究重启声明

本文定义一套从原始 IM 消息出发的、可执行且可审计的语义主题分析方法。它同时是本轮 1,000 个会话窗口分析的操作计划、数据契约和质量门禁。

本研究从方法层重新开始。除原始 Excel、原始字段及其客观含义外，不读取、不继承、不引用此前形成的主题、标签、分类树、抽样规则、标注方法、比例、需求判断或产品结论。历史材料可以物理保留，但不得作为本轮模型提示、分类先验、验收答案或解释依据。

本文所说的“会话”在数据完整性未经额外证明时，统一写作“会话窗口”。若一个窗口含 100 条可见消息，结论只对这 100 条可见消息负责，不外推为完整自然会话。

## 1. 第一性原理与最终目的

本研究首先回答一个问题：

> 在一个可见的 IM 会话窗口里，参与者实际聊了哪些具有一定讨论重量或特殊业务意义的主题？

只有把“聊了什么”识别准确，才能继续回答：

1. 这些主题可以怎样形成稳定、可解释的一级、二级、三级内容目录；
2. 哪些主题在更多会话中出现，哪些主题占据了更多消息；
3. 老师、学生、家长或其他参与者在这些主题中表达了什么需求，遭遇了什么摩擦；
4. 哪些问题适合由基础 IM 能力、业务工作流或 AI 能力辅助。

因此，研究必须遵循以下顺序：

```text
原始消息
→ 会话上下文语义理解
→ 主题实例提取
→ 原始消息证据回链
→ 主题类型归并
→ 一级/二级/三级内容目录
→ 主题分布统计
→ 需求与痛点研究
→ IM / 工作流 / AI 能力机会评估
```

不能从关键词命中直接跳到主题，不能从主题频次直接跳到痛点，也不能在主题事实尚未通过质量门禁时直接推导产品功能。

## 2. 研究问题

### 2.1 本轮必须回答

1. 每个抽样会话窗口包含哪些符合准入规则的主题实例；
2. 每个主题实例由哪些原始消息支持；
3. 每个主题在窗口内的有效关联消息数及占比；
4. 每个主题是普通主题、特殊业务主题，还是未进入主统计的短暂候选；
5. 跨会话出现的主题实例可以归并成哪些主题类型；
6. 这些主题类型如何组成一级、二级、三级内容目录；
7. 各主题类型的会话覆盖率、主题实例数和消息占用量分别是多少；
8. 哪些主题值得进入下一阶段的需求、痛点与产品能力研究。

### 2.2 本轮主题识别阶段不直接回答

1. 某条消息是否代表用户一定需要 AI；
2. 某主题高频是否等于它是最大的痛点；
3. 某次回应是否意味着问题已经解决；
4. 无法由原始字段或可靠上下文确认的参与者真实身份；
5. 会话窗口之外发生了什么；
6. 全平台总体发生率——除非抽样框、抽样概率及权重足以支持该外推。

这些边界必须在统计报告和 HTML 审阅页面中显式展示。

## 3. 术语与分析单位

| 术语 | 定义 |
|---|---|
| 原始消息 | 原始 Excel 中的一条消息记录。原始行号、消息 ID、时间、发送者字段和正文等均保持不变。 |
| 会话窗口 | 由原始数据客观标识为同一窗口的一组按时间排序的消息；本轮典型窗口为 100 条可见消息。 |
| 候选主题 | 模型通读整个窗口后发现的、围绕同一对象、事项、问题或连续内容展开的候选讨论单元。 |
| 主题实例 | 在某一个具体会话窗口中，满足普通主题门槛或特殊业务例外规则的独立主题。 |
| 普通主题 | 有效关联消息数达到窗口消息数 5% 门槛的主题实例。 |
| 特殊业务主题 | 虽未达到 5% 门槛，但具有独立业务意义、满足严格例外条件的老师或班主任单向公告、提醒、安排或重要通知。 |
| 短暂候选 | 未达到 5% 门槛且不满足特殊业务例外的候选内容；保留供审计，但不进入主主题分布。 |
| 主题类型 | 跨会话对语义相同或高度相近的主题实例进行归并后形成的标准化类型。 |
| 分类路径 | 某主题类型在“一级领域 → 二级场景 → 三级事项”内容目录中的位置。 |
| 有效关联消息 | 结合完整上下文后，能够支持某主题存在或推进该主题的一条原始消息记录。 |
| 证据映射 | 主题实例与精确原始消息之间的多对多成员关系；本轮以可逆的 ID 与窗口序号保存，不要求为每条证据持久化“发起/回应/推进”等作用标签。 |
| 人工金标准 | 人工在可见原文基础上复核、修正并确认的主题及证据结果，用于评估模型，而不是用模型自报置信度代替。 |

主题实例是主分析单位；原始消息是最小证据单位；会话窗口是上下文边界；主题类型和分类路径是跨会话统计单位。

## 4. 核心原则

### 4.1 上下文优先

主题必须在完整会话窗口中识别。模型应按时间顺序阅读全部可见消息，综合发送者、时间、回复关系、指代、话题转场、前后承接和可见附件占位信息做语义判断。

### 4.2 关键词只辅助，不裁决

关键词可以帮助搜索证据或检查遗漏，但不得单独决定：

- 一个主题是否存在；
- 哪些消息属于该主题；
- 主题属于哪个目录；
- 主题的消息权重；
- 参与者有什么需求。

关键词出现次数也不得替代有效关联消息数。

### 4.3 主题尽可能完整，但必须有边界

一个窗口可以有多个主题，不设置主题数量上限。模型需要尽可能提取所有符合准入条件的主题，同时避免：

- 把语义不同的事项强行合并成一个大主题；
- 把同一事项的连续追问和回应拆成多个碎片主题；
- 因为某个词相同，就把上下文无关的消息归到一起；
- 因为消息相隔较远，就机械地把同一事项拆开。

### 4.4 事实与推断分离

主题名称和描述只陈述原文可支持的沟通事实。角色、动机、结果、需求、痛点和产品机会必须分别记录；证据不足时保持“未知”或“无法判断”。

### 4.5 全程可逆

任何分类节点、主题类型和主题实例都必须能回到具体会话窗口及原始消息；任意原始消息也必须能反查它被关联到哪些主题。摘要不得替代原文证据。

本轮所说的“可逆性”，特指 `Topic instance ↔ exact source message` 的多对多映射，不等于必须为全部消息生成状态标签。未关联消息仍保留在完整会话原文中，但不强制逐条写入“寒暄/无法理解/不计入原因”。

## 5. 主题准入规则

### 5.1 普通主题：5% 消息门槛

对含 `N` 条原始消息的窗口，普通主题的最低有效关联消息数为：

```text
普通主题门槛 = ceil(N × 5%)
```

因此，100 条消息窗口的门槛为 5 条有效关联消息。

普通主题只有在以下条件同时成立时才进入主统计：

1. 有一个可用中性语言描述的共同对象、事项、问题或连续内容；
2. 至少达到 5% 的有效关联消息门槛；
3. 每条计入分子的消息都能通过上下文说明其与该主题的关系；
4. 证据映射完整且可回溯。

5% 是本轮约定的“讨论重量准入线”，不是痛点强度、业务价值或功能优先级。

### 5.2 特殊业务主题例外

老师或班主任在班级场景中发布的单向公告、提醒、课程安排、任务要求或重要变更，可能只有 1—4 条消息且无人回应，但仍可能具有独立业务意义。这类内容可作为特殊业务主题进入分析，但必须同时满足：

1. 原始角色字段或可靠上下文支持发布者是老师、班主任，或具有明确班级管理职责；
2. 内容面向班级或明确的集体对象，而不是私人寒暄；
3. 内容能够独立表达一项通知、安排、提醒、要求或变更；
4. 事项具有可识别的业务对象，例如课程、作业、考试、活动、资料、考勤或班级事务；
5. 证据消息被完整回链；
6. 记录例外原因，不以“模型觉得重要”作为理由。

特殊业务主题必须标记：

```text
admission_mode = SPECIAL_BUSINESS_EXCEPTION
special_reason = 具体例外理由
```

它与达到 5% 门槛的普通主题分开统计，不得混合后声称二者具有相同讨论重量。

若发布者身份、群体对象或业务意义无法由证据确认，不得使用该例外；该内容进入短暂候选并等待人工复核。

### 5.3 短暂候选保留

未达到普通主题门槛且不满足特殊业务例外的内容，不进入主主题统计，但仍保留为短暂候选。记录至少包括：

- 候选名称；
- 关联消息；
- 有效消息数；
- 未准入原因；
- 是否建议人工查看。

保留短暂候选有三个目的：

1. 让人工检查 5% 门槛是否漏掉了重要内容；
2. 为未来规则调整保留可重算证据；
3. 防止模型为了满足门槛把无关消息拼接成主题。

短暂候选不得参与正式主题会话覆盖率、实例数和消息占用量排名。

## 6. 有效关联消息与计数规则

### 6.1 哪些消息可以计入

结合完整上下文，一条消息出现以下任一作用时，可以计入某主题：

- 发起：提出事项、问题或讨论对象；
- 补充：增加与事项直接相关的信息；
- 请求：提出问题、申请、行动要求或信息需求；
- 回应：回答、解释、拒绝、澄清或纠正；
- 推进：推动事项进入下一步；
- 确认：确认安排、收到或共同理解；
- 结果：陈述可见结果或阶段状态；
- 公告：构成特殊业务主题的单向发布内容。

短文本、表情、图片占位或“收到”等不能仅因形式简短而自动排除；如果上下文能明确证明它在推进或确认某主题，它可以计入。反之，内容很长也不意味着一定属于主题。

上述“发起、回应、推进”等作用用于模型判断消息是否应计入主题证据；本轮机器产物不要求逐条持久化作用标签，只保存主题实例与精确原消息之间的成员映射。细分证据作用属于后续人工复核增强项。

### 6.2 不能机械计入的情况

以下情况需要结合上下文处理，不能仅靠字面命中计数：

- 与主题无关的寒暄、表情或语气词；
- 只复用了相同词汇、但讨论对象不同的消息；
- 指代无法解析、无法证明属于任何候选主题的残缺消息；
- 同一原始记录被重复读取；
- 疑似导出或技术重复的数据。

疑似重复数据不得静默删除。应保留所有原始行，并分别记录原始计数、疑似重复标记和用于准入判断的有效计数。只有能被客观规则确认的技术重复才从有效计数中排除；无法确认时保留并进入人工复核。

### 6.3 多主题重叠

- 同一原始消息在同一主题实例中最多计数一次；
- 一条消息确实同时承载两个独立事项时，可以关联多个主题实例；
- 因此，同一窗口中多个主题的消息占比之和可能超过 100%；
- 报告必须标注这是多主题重叠，不得把重叠消息强制只分给一个主题来制造互斥比例。

### 6.4 分母固定

窗口内主题占比的分母使用该窗口的原始可见消息记录数 `N`，而不是“模型认为有意义的消息数”。若窗口并非 100 条，仍按实际 `N` 使用 `ceil(N × 5%)` 计算门槛。

## 7. 上下文语义主题提取流程

每个会话窗口按照以下固定流程处理。

### 步骤 1：建立只读上下文

1. 根据原始会话标识聚合消息；
2. 按原始时间及稳定次序排序；
3. 展示原始发送者字段、角色字段、回复字段和正文；
4. 保留原始行号与消息 ID；
5. 不修改、补写或“修复”原始正文。

角色信息只作为理解上下文的辅助证据。无法确认的角色不得由内容风格猜测。

### 步骤 2：通读完整窗口

模型必须先通读完整窗口，再输出主题。禁止逐条独立分类后简单汇总，因为短消息的真实含义常依赖前后文。

### 步骤 3：识别候选片段与转场

模型标出：

- 新对象或新事项的出现；
- 对前文的追问、回应和确认；
- 话题暂时中断及随后恢复；
- 一条消息中并列出现的独立事项；
- 无法理解或缺少载荷的内容。

### 步骤 4：合并或拆分主题边界

- 同一对象、同一目标、同一事项的多段非连续讨论，可以合并为一个主题实例，并保留多个证据区间；
- 对象、目标或待处理事项明显不同，即使关键词相同，也应拆分；
- 一条消息同时包含多件独立事项，可以支持多个主题；
- 同一事项中的提问、解释、确认和结果通常不应拆成四个主题。

### 步骤 5：生成中性主题名称

名称应概括“在谈什么”，而不是评价、原因推断或产品建议。

推荐格式：

```text
对象 / 事项 + 当前沟通动作或问题
```

例如“确认明日课程开始时间”“讨论某道题的解法”“发布作业提交提醒”。避免写“需要 AI 提醒”“学生缺乏自律”“老师服务不到位”等超出证据或提前引入方案的表述。

### 步骤 6：建立逐消息证据映射

为每个候选主题关联全部实际支持消息，保存精确 `message_id`、窗口消息序号和原始行号，并允许一条消息映射多个主题。不得只选择少量代表性消息后用摘要替代完整计数依据。本轮不持久化“发起/回应/推进”等细分作用标签。

### 步骤 7：计算准入并分轨

按有效消息数和 5% 门槛，分别标记：

- `STANDARD`：达到门槛的普通主题；
- `SPECIAL_BUSINESS_EXCEPTION`：通过严格例外规则的特殊业务主题；
- `TRANSIENT_CANDIDATE`：未进入主统计的短暂候选。

### 步骤 8：反向覆盖审计

重新扫描窗口中的全部消息做漏题检查，并用窗口级 `coverage_note` / `window_uncertainty` 记录附件缺失、指代缺失、疑似重复或其他理解限制。未关联消息不强制逐条分类；逐消息的未关联原因属于后续人工复核增强项。

覆盖审计用于发现漏提主题，不用于强迫每条消息都归入主题，也不把窗口级说明误写成逐消息金标准。

## 8. 可逆证据数据模型

本轮输出至少包含六张逻辑表；可以存储在 Excel、CSV、JSON 或数据库中，但字段语义必须保持一致。

### 8.1 `source_manifest`：原始数据清单

- 原始文件名及绝对路径；
- 文件哈希；
- 工作表名；
- 原始行数与列名；
- 提取时间；
- 分析代码版本；
- 随机种子；
- 禁止修改原始数据的声明。

### 8.2 `sample_manifest`：抽样清单

- `sample_id`；
- 原始会话窗口标识；
- 原始客观会话类型字段；
- 抽样层；
- 抽中概率或权重；
- 随机排序号；
- 所属批次；
- 是否进入盲测集；
- 不可分析原因与替补记录（如有）。

### 8.3 `topic_instance`：主题实例表

- `topic_instance_id`；
- `sample_id` 与原始会话窗口标识；
- 中性主题名称；
- 主题事实摘要；
- `admission_mode`；
- 有效消息数；
- 窗口原始消息数；
- 窗口内占比；
- 特殊例外理由；
- 主题类型 ID；
- 一级、二级、三级分类 ID；
- 模型置信度及其理由；
- 人工审核状态；
- 不确定性说明。

### 8.4 `message_topic_map`：消息—主题映射表

- 原始文件与工作表；
- 原始行号；
- 原始消息 ID；
- 原始会话窗口标识；
- `sample_id`；
- `topic_instance_id`；
- 规范化消息 ID 与原始消息 ID；
- 消息在窗口内的证据序号；
- `qualification`；
- 原文只读副本或可定位引用。

关系表只生成实际计入某主题证据的消息；未计入消息没有关系行，但仍完整保留在会话窗口原文中。证据 ID 与序号由程序做成对校验。

该表是可逆性的核心。它必须支持：

```text
分类节点 → 主题类型 → 主题实例 → 会话窗口 → 原始消息
原始消息 → 一个或多个主题实例 → 主题类型与分类节点
```

### 8.5 `taxonomy`：分类目录表

- 分类节点 ID；
- 父节点 ID；
- 层级；
- 节点名称；
- 定义；
- 纳入规则；
- 排除规则；
- 正例；
- 反例；
- 版本号；
- 生效时间；
- 变更原因。

### 8.6 `human_review`：人工审阅反馈表

- 审阅对象 ID；
- 认同 / 部分认同 / 不认同；
- 问题类型；
- 漏掉的主题；
- 错误主题；
- 应合并 / 应拆分；
- 证据映射错误；
- 分类路径错误；
- 特殊例外使用错误；
- 建议修正；
- 审阅者与时间；
- 裁决结果；
- 规则是否需要更新。

任何派生表都不得删除原始溯源字段。

## 9. 一级、二级、三级主题目录

### 9.1 目录只描述“聊的是什么”

三层目录必须沿同一语义轴逐级细化：

- 一级：大的内容领域；
- 二级：该领域中的业务或生活场景；
- 三级：可识别的具体事项类型。

角色关系、单聊 / 群聊、沟通目的、情绪、紧迫程度、是否解决和 AI 适配性不得混入主题目录。它们可以作为独立辅助属性用于后续切片。

### 9.2 目录从主题实例中归纳形成

本轮不预设一棵固定目录去套原文。目录按照以下方式形成：

1. 先从原始窗口独立提取主题实例；
2. 对语义相近的实例进行归并，形成候选主题类型；
3. 根据候选类型的共同内容，自下而上形成三级、二级、一级节点；
4. 为每个节点补齐定义、纳入、排除及正反例；
5. 在新会话上验证目录覆盖力；
6. 保留“新类型”和“无法判断”，不强行归类；
7. 目录冻结后再进行稳定统计。

### 9.3 主路径与跨域

每个主题实例原则上拥有一条主分类路径，以支持互斥的主分布统计。确实跨域时可以增加关联标签，但必须说明主路径选择理由；关联标签不重复计入主路径主题实例数。

### 9.4 版本治理

目录每次新增、合并、拆分或改名都必须产生新版本及映射表。不能直接覆盖旧分类结果。目录发生实质变化后，已分析样本需要重跑或通过确定性的旧—新节点映射重新计算。

### 9.5 平行辅助维度：语义沟通场景

人工审阅可以在主题目录之外，为整个会话窗口补充“语义沟通场景”。它回答的是“当前可见窗口中，哪些角色以什么关系和互动方式在沟通”，而不是“聊了什么”。该维度不得混入 L1 / L2 / L3 主题目录，也不得覆盖原始系统字段。

必须分层保留四类信息：

1. **会话形态（原始事实）**：群聊或 1v1，由 `clustertype` / `chat_type` 等原始字段决定；
2. **系统容器属性（原始事实）**：例如班级群；原表可提供时只读保留；
3. **窗口内可见发言角色（机械派生事实）**：依据当前窗口中的发送者和 `user_type` / `role` 汇总，仅代表可见发言，不代表完整成员构成；
4. **语义沟通场景（人工或模型推断）**：结合完整窗口、角色字段、称呼指向、主题和互动上下文判断，挂在 `window_id` 上。

群聊窗口的第一版场景预设为：教师管理协作、教师同伴交流、师生班级沟通、学生同伴交流、家校群体沟通、混合／其他、无法判断。1v1 窗口的第一版场景预设为：教师／管理者与教师／管理者、教师与学生、教师与家长、学生与学生、其他关系、无法判断。

群聊预设的判定边界如下：

| 场景 | 纳入 | 不纳入 |
|---|---|---|
| 教师管理协作 | 教师、班主任、助教或管理者围绕排课、人员、运营、考勤等进行内部协作 | 老师面向学生发布课程通知；虽无人回应，目标受众仍是学生 |
| 教师同伴交流 | 教职人员之间的专业交流、同伴讨论或非管理型日常交流 | 明确的管理协作；师生班级服务 |
| 师生班级沟通 | 教师与学生围绕课堂、作业、课程服务或班级事项沟通；也包括目标明确指向学生的老师单向公告 | 仅凭系统容器是班级群、但窗口内容实际全是教师内部协作 |
| 学生同伴交流 | 学生之间主导的学习或日常互动 | 家长主导；教师参与并主导班级服务 |
| 家校群体沟通 | 教师、家长或监护人围绕学生、课程或服务进行群体沟通 | 仅因学生账号存在就猜测为家长 |
| 混合／其他 | 同一窗口存在两个以上无法合理确定主场景的关系或模式 | 只是 Topic 多，不等于场景混合 |
| 无法判断 | 正文、角色或指向不足，不能可靠判断 | 为了提高覆盖率而强行猜测 |

1v1 预设只表达双方的语义角色关系。若系统显示学生账号，但原文明示“我是孩子妈妈／爸爸”，可以标为“教师与家长”并在备注中记录系统字段与语义冲突；证据不足时选择“无法判断”，不得把家长并入“学生与学生”。

预设在人工界面中保持一次点击，但派生层同时保存规范化的 `scene_label`、`inferred_role_relation` 和 `interaction_mode`。普通明确案例不要求书写证据；混合、低把握或系统字段与语义明显冲突时，可以填写 `scene_note`。家长属于语义推断角色，不能伪装成原始 `user_type` 真值。

当前标注单位是 100 条左右的**会话窗口**，不是永久群实体。一个系统班级群在某段窗口里可能主要承载教师管理协作，也可能在另一段窗口里承载师生班级沟通。后续若要给整个 `clusterid` 形成群画像，必须先聚合同一实体的多个窗口，输出主导场景、时间覆盖、稳定性与冲突，不能用单个窗口静默改写永久群类型。

## 10. 主题分布统计口径

“哪些主题最多”至少需要三种独立指标。

### 10.1 会话覆盖率

```text
会话覆盖率 = 出现该主题类型的唯一会话窗口数 / 被分析的有效会话窗口数
```

同一窗口中同一主题类型出现多个实例，计算覆盖率时只记一次。

### 10.2 主题实例数

```text
主题实例数 = 该主题类型下相互独立的主题实例总数
```

它回答“发生了多少个独立讨论事项”。

### 10.3 消息占用量

窗口内：

```text
主题消息占比 = 该主题实例的有效关联消息数 / 该窗口原始可见消息数
```

跨窗口：同时报告有效关联消息总数、平均占比、中位数及分布，不用单一平均值掩盖长尾。

### 10.4 特殊业务主题单列

特殊业务主题分别报告：

- 特殊主题会话覆盖率；
- 特殊主题实例数；
- 单向发布消息数；
- 对应分类分布。

不得用其不足 5% 的消息占比与普通主题的讨论重量直接比较。

### 10.5 多标签重叠

由于一条消息可支持多个主题，主题消息占比相加可能超过 100%。报告必须同时提供：

- 非去重的主题关联消息数；
- 去重后的至少属于一个正式主题的消息数；
- 多主题重叠消息数与重叠率。

### 10.6 抽样权重与外推边界

若 1,000 个窗口采用不等概率分层抽样，推断总体分布时必须使用抽样权重；未经权重修正的结果只能描述样本。探索性目录发现、人工审阅便利与总体比例估计要分别标注，不能混用。

## 11. 需求、痛点与产品能力的后置链路

主题目录和分布通过质量门禁以后，才进入第二阶段分析。

### 11.1 从主题事实到需求

对每个经过验证的主题类型，回到具体主题实例及原文，分别判断：

- 需求主体：证据支持的老师、学生、家长或其他参与者；
- 希望完成的事情或希望获得的信息；
- 当前可见的处理方式；
- 是否出现信息缺口、受阻、重复确认、催促、纠错、沟通失败或明确负面结果；
- 窗口内可见状态，以及哪些状态无法判断。

不能强迫每个主题产生需求；日常谈话可能只是交流。不能把“主题高频”直接解释为“痛点严重”。

### 11.2 两条独立判断轴

后续优先级至少拆为：

1. **主题普遍度 / 讨论重量**：来自本轮主题统计；
2. **可见需求 / 摩擦强度**：来自主题内部的需求与摩擦证据。

高频低摩擦、低频高摩擦和高频高摩擦需要分别解释。

### 11.3 能力机会评估

需求与痛点通过人工校验后，再比较三类承载方式：

- 基础 IM 能力：消息组织、引用、检索、提醒、状态表达等；
- 业务工作流能力：课程、作业、请假、资料等结构化流程；
- AI 辅助能力：在语义理解、生成、归纳、个性化或复杂协同中有明确增益的场景。

能力评估必须引用主题实例和原始证据，不允许从目录名称直接生成“功能清单”。

## 12. 人机协作与校验机制

### 12.1 模型负责

- 阅读完整会话窗口；
- 语义提取候选主题；
- 建立精确消息 ID 的主题成员映射；
- 执行准入判断；
- 提出主题名称、主题类型和分类路径；
- 标记不确定性；
- 根据人工裁决重新分析受影响样本。

### 12.2 人工负责

- 复核模型是否遗漏、虚构、过度合并或过度拆分主题；
- 复核每条证据是否真正相关；
- 裁决特殊业务例外；
- 审核目录边界；
- 对争议样本给出金标准；
- 批准方法或目录变更。

### 12.3 置信度用途

模型置信度仅用于安排人工审阅顺序，不能代表真实准确率。每个置信度必须给出理由，至少考虑：

- 主题语义是否明确；
- 证据消息是否充分；
- 指代与附件是否缺失；
- 主题边界是否容易与其他主题混淆；
- 分类节点是否已有稳定定义。

真实准确性必须通过独立人工复核和盲测计算。

### 12.4 语义沟通场景的训练与评估边界

语义沟通场景的自动推断是主题分析完成后的独立算法环节。模型输入可以包含完整窗口原文、原始会话形态、窗口内可见角色分布及已经人工校验的 Topic，但不得退化成关键词命中或只按 `user_type` 机械映射。

A、B、C 阶段的人工场景标签可用于规则形成、样例校准和错误修正；D 阶段保持未见，用于最终评估。若根据 D 的错误重新调整标签或提示，则该批次不再是 holdout，必须更换新的未见样本。群聊与 1v1 分开报告准确率、Macro-F1、逐类 Precision / Recall、混淆矩阵、拒判覆盖率、置信度校准，以及系统字段与语义推断冲突率。低置信、混合场景、家长语义角色和字段冲突案例优先进入人工复核。

## 13. 1,000 个会话窗口抽样设计

### 13.1 抽样目标

抽样同时服务两个目标：

1. 尽可能覆盖真实会话中的不同主题，形成内容目录；
2. 在明确抽样概率的前提下，估计样本或总体中的主题分布。

不能根据关键词或旧主题标签筛选“看起来有教学内容”的会话，否则会系统性遗漏未知主题并扭曲比例。

### 13.2 抽样框

从原始 Excel 中机械生成唯一会话窗口清单，只使用原始可验证字段。每个窗口至少记录：

- 原始会话窗口标识；
- 原始记录数；
- 原始客观会话类型字段及取值；
- 最早与最晚可见时间；
- 是否存在正文或可见消息载荷；
- 数据可分析状态。

不使用旧分析标签、不使用关键词命中数、不使用模型预判主题作为抽样条件。

### 13.3 分层与随机性

若原始字段能够客观区分单聊、班级群或其他会话类型，则按这些原始类型分层；默认采用与抽样框规模相符的比例分配，同时为客观存在但数量较少的层设置最低观察量。任何过采样必须保留抽中概率和统计权重。

每层使用固定随机种子无放回抽样。输出完整随机排序和候补序列，使抽样可重现。不得人工挑选“有意思的案例”替换随机结果。

若样本窗口因客观数据损坏无法分析：

1. 原样保留在抽样清单；
2. 记录不可分析原因；
3. 按同层候补序列依次替补；
4. 不根据消息内容决定是否替补。

### 13.4 批次安排

1,000 个窗口均须完成分析，但按以下批次控制方法与目录的稳定性：

| 批次 | 窗口数 | 用途 |
|---|---:|---|
| A：方法校准 | 100 | 检查提示、主题边界、5% 计数和特殊例外是否可执行；快速形成第一版争议清单。 |
| B：目录形成 | 200 | 扩展主题类型，形成一级、二级、三级候选目录和节点定义。 |
| C：规模分析 | 600 | 使用冻结方法和候选目录处理主体样本；继续允许新增类型，但触发版本治理。 |
| D：盲测验证 | 100 | 在冻结方法和目录下独立分析；不得在评分前用于修改规则。 |

合计 1,000 个窗口。A、B、C 中产生的规则变化需要对受影响的已处理窗口重跑。D 批次评分完成前保持封闭；若 D 未通过门禁，修订后必须使用新的未见样本再次验证，不能在同一批上反复调参后宣称通过。

### 13.5 样本清单冻结

执行前生成并冻结：

- 原始文件哈希；
- 1,000 个样本及候补样本 ID；
- 分层依据及各层数量；
- 随机种子；
- 每个窗口所属批次；
- 抽中概率与权重；
- 盲测标记。

## 14. 执行步骤计划

### 阶段 0：输入冻结与字段审计

1. 读取原始 Excel 及字段说明；
2. 生成文件哈希、工作表、列名、行数和关键字段取值清单；
3. 区分原始事实、业务确认和未知解释；
4. 检查会话窗口键、消息键、时间顺序及缺失情况；
5. 生成只读数据清单。

完成条件：任何样本与派生数据都能指向唯一的原始文件版本和原始行。

### 阶段 1：抽取并冻结 1,000 个窗口

1. 生成抽样框；
2. 按客观会话类型分层；
3. 固定随机种子抽取 1,000 个窗口及候补；
4. 分配 A / B / C / D 批次；
5. 校验唯一性、层分布、消息数量及可分析状态。

完成条件：抽样可复现，无关键词或主题筛选介入，1,000 个有效窗口均有稳定 `sample_id`。

### 阶段 2：批次 A 方法校准

1. 模型通读每个窗口并提取候选主题；
2. 建立全量消息—主题映射；
3. 应用普通门槛、特殊业务例外和短暂候选分轨；
4. 生成人工审阅 HTML；
5. 人工对一组覆盖普通主题、特殊主题、多主题和无正式主题的案例进行审阅；
6. 汇总漏提、误提、错误合并、错误拆分、计数和例外错误；
7. 修订操作规则并重跑 A 批次。

完成条件：主题与证据结构稳定，准入规则可以被不同审阅者一致执行。

### 阶段 3：批次 B 目录形成

1. 独立提取 B 批次主题；
2. 将语义相近实例归并为候选主题类型；
3. 自下而上形成三级、二级、一级目录；
4. 为目录节点补齐定义、纳入、排除及正反例；
5. 人工审阅有争议的归并和分类；
6. 冻结目录版本 V1；
7. 使用 V1 重算 A、B 批次。

完成条件：目录节点互有边界，新增主题可进入现有节点或明确标为“新类型 / 无法判断”。

### 阶段 4：批次 C 规模分析

1. 按冻结方法批量分析 600 个窗口；
2. 优先人工审阅低置信度、边界案例、特殊业务例外及新类型；
3. 定期抽取高置信度结果检查系统性错误；
4. 对新类型触发目录变更流程；
5. 目录实质变更后重跑受影响样本；
6. 完成全部证据回链和统计中间表。

完成条件：900 个开发窗口均有可审计结果，目录版本稳定，无待处理的结构性规则冲突。

### 阶段 5：批次 D 盲测

1. 使用冻结方法与目录分析 100 个未见窗口；
2. 人工独立提取并裁决主题与证据；
3. 计算精确率、召回率、证据映射、合并拆分及分类路径指标；
4. 根据门禁判定是否允许发布主题分布。

完成条件：达到第 17 节质量门禁；否则回到方法修订并使用新的未见样本复验。

### 阶段 6：分布与后续研究

1. 冻结主题实例、证据映射和目录版本；
2. 按三种统计口径计算主题分布；
3. 分开报告普通主题、特殊业务主题和短暂候选；
4. 说明抽样权重、重叠和无法分析数据；
5. 选取高频、高讨论重量或具有特殊业务意义的主题，进入需求与痛点研究；
6. 只有需求与痛点证据通过人工复核后，才进入 IM / 工作流 / AI 能力机会分析。

## 15. HTML 人工审阅页面规范

HTML 页面是研究审阅工具，不是产品原型。它应支持对全部 1,000 个窗口逐个检查。

### 15.1 总览页

展示：

- 总窗口数、已分析数、待审阅数和有争议数；
- 普通主题、特殊业务主题、短暂候选数量；
- 一级 / 二级 / 三级目录树；
- 各主题的会话覆盖率、实例数和消息占用量；
- 单聊、群聊等原始客观类型筛选；
- 批次、置信度、人工状态、特殊例外筛选；
- 从目录节点进入主题实例和原文的路径。

### 15.2 会话审阅页

每个窗口展示：

- 稳定 `sample_id`、原始会话窗口标识和客观字段；
- 按时间排序的全部原始消息；
- 发送者和原始角色字段；
- 原始会话形态、窗口内可见发言者数量和原始角色消息分布，并明确其不代表完整成员构成；
- 独立于 Topic 的窗口级语义沟通场景标注；
- 每个主题的名称、分类路径、准入方式、计数和占比；
- 特殊业务例外理由；
- 短暂候选；
- 全部未高亮原文，以及窗口级的无法理解、附件缺失或疑似重复限制说明。

### 15.3 主题高亮

- 每个主题使用稳定颜色和主题编号；
- 关联消息整行高亮，并显示关联主题编号或徽标；
- 一条消息属于多个主题时显示多个色条或主题徽标，不能只保留一个颜色；
- 点击主题可只查看该主题的全部证据，并保持原始时序和上下文邻近消息；
- 点击任意高亮可跳到主题卡片；
- 原文不得被摘要替换或省略。

颜色只能作为辅助编码，必须同时提供文本标签，以满足可访问性和打印审阅。

### 15.4 人工反馈

每个会话和主题均支持：

- 认同；
- 部分认同；
- 不认同；
- 漏掉主题；
- 主题不成立；
- 应合并；
- 应拆分；
- 证据多选 / 少选；
- 消息计数错误；
- 分类路径错误；
- 特殊业务例外错误；
- 修改建议与备注。

会话级反馈还可以保存 `scene_label`、`inferred_role_relation`、`interaction_mode` 和选填的 `scene_note`。这些字段属于人工派生层；原始会话形态、容器属性、发送者和角色字段始终只读。

导入反馈必须检查受支持的 schema 版本、字段白名单及场景三元组与会话形态的一致性。未知字段不得进入派生反馈或被再次导出；群聊窗口不得接受 1v1 场景，场景名称、角色关系与互动模式不一致时必须 fail closed。任何延迟保存实现都必须保证“输入后立即导出”仍包含最后一次编辑。

反馈应以结构化 JSON / CSV 导出，并保留审阅前结果、审阅后裁决和规则版本，禁止直接覆盖历史判断。

### 15.5 本地与隐私

页面默认作为本地静态页面运行，不加载第三方分析脚本、远程字体或外部资源，不向公网发送原文或标识字段。

## 16. 质量评估指标

所有指标均以人工金标准为基准。

| 指标 | 定义 |
|---|---|
| 主题精确率 | 模型输出的正式主题中，经人工确认成立的比例。 |
| 主题召回率 | 人工确认的正式主题中，被模型识别到的比例。 |
| 特殊例外精确率 | 模型判为特殊业务主题的实例中，经人工确认符合全部例外条件的比例。 |
| 证据映射精确率 | 模型选入主题的消息中，人工确认相关的比例。 |
| 证据映射召回率 | 人工确认属于主题的消息中，被模型回链的比例。 |
| 准入一致率 | 模型的 5% 计数及 `STANDARD / SPECIAL / TRANSIENT` 分轨与人工一致的比例。 |
| 过度合并率 | 人工认为应拆分、但模型合并的主题占比。 |
| 过度拆分率 | 人工认为应合并、但模型拆分的主题占比。 |
| 一级分类准确率 | 主题主路径一级节点与人工金标准一致的比例。 |
| 二级分类准确率 | 二级节点与人工金标准一致的比例。 |
| 三级分类准确率 | 三级节点与人工金标准一致的比例。 |
| 可逆性通过率 | 主题能完整回到原始会话及消息、原始消息能反查主题的比例。 |

还需报告不同原始会话类型、普通 / 特殊主题、单主题 / 多主题、不同置信度和不同消息占比区间中的分组表现，避免平均值掩盖薄弱场景。

## 17. 质量门禁（QA / Gate）

### Gate 0：原始证据完整性

- 原始文件哈希固定；
- 派生数据没有修改原始记录；
- 100% 样本可定位原始窗口；
- 100% 原始证据行可回查。

任一项失败即停止分析。

### Gate 1：抽样有效性

- 1,000 个有效会话窗口唯一；
- 抽样可由固定种子复现；
- 分层数量、抽中概率和权重完整；
- 替补只依照预先冻结的候补顺序；
- 没有关键词、旧主题或人工兴趣筛选。

### Gate 2：主题结构完整性

- 100% 正式主题具有消息级证据；
- 100% 普通主题满足 5% 有效消息门槛；
- 100% 特殊业务主题具有明确例外理由；
- 100% 短暂候选不进入主统计；
- 消息—主题映射的引用完整、无孤儿记录。

### Gate 3：盲测质量

在 D 批次 100 个未见窗口上，暂定最低发布门槛为：

- 主题精确率 ≥ 90%；
- 主题召回率 ≥ 85%；
- 特殊业务例外精确率 ≥ 90%；
- 证据映射精确率 ≥ 95%；
- 证据映射召回率 ≥ 90%；
- 准入一致率 ≥ 95%；
- 一级分类准确率 ≥ 90%；
- 二级分类准确率 ≥ 85%；
- 三级分类准确率 ≥ 80%；
- 可逆性通过率 = 100%。

同时公开过度合并率和过度拆分率；任何一项出现跨场景系统性错误，即使平均指标达到门槛，也需修订后复验。

### Gate 4：统计发布

- 使用冻结的主题规则和目录版本；
- 普通主题与特殊业务主题分开报告；
- 三种“最多”口径不混用；
- 多主题重叠明确说明；
- 不等概率抽样使用权重；
- 样本结论和总体外推明确区分；
- 所有图表可回到主题实例及原始证据。

未通过 Gate 3 时，不得发布具有方向牵引含义的主题比例。

### Gate 5：需求与产品推导

- 主题事实已经通过 Gate 4；
- 需求与摩擦有原文证据；
- 高频与痛点分开论证；
- 角色不能确认时不强猜；
- 产品机会明确区分基础 IM、业务工作流和 AI；
- 每项机会都能回链到主题类型、主题实例和原始消息。

## 19. 数据安全与治理

1. 仅处理用户提供的、已经脱敏的原始数据；
2. 原始文件保持只读，不覆盖、不清洗写回；
3. 生成物可以保留原表中的消息 ID、发送者昵称、用户 ID、原始行号等已脱敏字段，用于快速溯源；
4. 所有含消息原文的 Excel、JSON、CSV 和 HTML 默认仅保存在授权的本地研究目录；
5. 不将消息原文、用户 ID 或昵称发送到外部网站、公共仓库或第三方遥测；
6. HTML 页面不引用远程脚本、字体或图片；
7. 日志不得包含账号密钥、Token 或未经授权的真实身份信息；
8. 对外分享时另行生成最小化、去标识版本，不直接复制本地审阅包；
9. 任何人工修改都写入派生层，保留原始值、模型原值和人工裁决，不覆盖证据。

## 20. 已确认规则与待由数据检验的问题

### 20.1 本轮已确认的执行规则

- 研究主轴是识别会话窗口中“聊了什么主题”；
- 100 条窗口的普通主题至少需要 5 条有效关联消息；
- 老师 / 班主任的单向公告、提醒等可按严格条件作为特殊业务主题；
- 不满门槛的其他内容保留为短暂候选，但不进入主统计；
- 一个窗口可以包含多个主题；
- 主题必须基于完整上下文的语义分析，而不是关键词匹配；
- 主题、目录、会话和原始消息之间必须双向可追溯；
- 语义沟通场景是与 Topic 目录平行的窗口级辅助属性，不能覆盖系统会话属性或被当作永久群类型；
- 主题分类与分布完成后，才研究需求、痛点和产品能力；
- 本轮分析 1,000 个会话窗口，并提供 HTML 人工审阅页面。

### 20.2 需要在执行中检验，而非预先假定

- 5% 门槛在不同会话类型中是否会系统性漏掉重要主题；
- 特殊业务例外是否需要进一步细分；
- 三层目录是否足以容纳真实主题，是否存在两层即可表达或需要关联标签的情况；
- 主题边界在中断后恢复、多个并列事项和附件缺失时是否稳定；
- 模型在日常闲聊、教学讨论、通知安排等不同语境中的召回差异；
- 1,000 个样本是否足以使目录趋于稳定；
- 原始字段能支持哪些角色和会话类型切片，哪些必须保持未知。

这些问题的答案应来自 1,000 个窗口的证据和人工复核，而不是在执行前写成结论。

## 21. 研究完成定义

本轮研究只有在以下条件同时满足时才算完成：

1. 1,000 个会话窗口均按冻结规则完成语义分析；
2. 所有正式主题与短暂候选均有可逆消息证据；
3. 主题目录具有清晰定义、边界和版本；
4. HTML 页面可以从目录、主题或消息任一方向完成查证和反馈；
5. 盲测达到质量门禁，或明确记录未通过项且不发布误导性比例；
6. 统计口径、抽样权重、重叠和限制均被说明；
7. 需求、痛点和产品能力结论没有越过主题事实与原始证据；
8. 所有生成物可被后续研究复现、定位和审计。
