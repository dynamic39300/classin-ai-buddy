# IM 会话语义场景标签规则 v1.1（草案）

> 状态：`SUPERSEDED_FOR_PRIMARY_EXECUTION_BY_D-114`。本文件保留阶段 A/B 的历史语义场景探索，不再作为会话结构和角色关系的主执行协议。当前方法以数据库解析结构与成员职业身份，并把教师群沟通用途作为独立语义轴；见 `../im-conversation-structure/CONVERSATION-STRUCTURE-AND-PURPOSE-METHOD-V1.md`。历史人工结果不得删除或覆盖。

## 1. 标签回答什么

场景标签回答：**在当前 100 条左右的可见窗口里，主要由哪些语义角色，以什么关系和方式进行沟通。**

它不回答聊了什么，不替代 Topic，也不代表整个群实体的永久类型。一个相同 `clusterid` 在不同时间窗口可能呈现不同主导场景。

## 2. 四层证据必须分开

| 层 | 性质 | 使用规则 |
|---|---|---|
| 会话形态 | 原始硬事实 | `clustertype` / `chat_type` 决定群聊或 1v1；自动标签不得跨 namespace |
| 系统容器属性 | 原始事实 | 班级群等属性只读保留，不等同于实际活跃场景 |
| 窗口内可见参与 | 机械派生 | 统计可见发送者、原始角色消息数和互动结构；不外推完整成员构成 |
| 语义场景 | 人工／模型推断 | 结合完整原文、称呼、行动、Topic 和互动上下文判断，可拒判 |

`user_type`、昵称和称呼均不能单独作为角色真值。阶段 A 已观察到原始角色字段与语义身份多次冲突；这些字段只作弱证据和冲突信号。

## 3. 群聊标签

| 标签 | 纳入 | 排除 |
|---|---|---|
| 教师／管理协作 | 教师、班主任、助教、运营或管理者围绕排课、人员、服务、考勤等内部协作 | 面向学生或家长提供课程服务；顾问面向学员教学或服务 |
| 教师／专业同伴 | 教师或专业人员之间的非管理型同伴交流 | 明确管理流程；师生／顾问—学员服务 |
| 教师／导师／顾问—学生／学员班群 | 教师、导师或顾问面向学生／学员教学、反馈、通知或持续服务 | 教职内部管理；纯学生同伴群；家长主导沟通 |
| 学生／学员同伴 | 学生或学员主导的学习、兴趣或日常互动 | 教师持续参与并主导课堂／班级服务 |
| 家校群体沟通 | 教师与家长／监护人围绕学生、课程或服务沟通 | 只因账号是学生就猜测家长；教职内部协作 |
| 混合／其他 | 同一窗口确有多个无法确定主导关系的场景 | 仅仅 Topic 数多；单一场景但领域特殊 |
| 无法判断 | 正文、称呼或参与信息不足 | 为提高覆盖率强行选择一个关系 |

教师／导师／顾问是沟通关系角色，不代表 Topic 必然属于学校教学。投资、职业或其他行业培训仍可呈现“顾问—学员”关系；具体内容由 Topic 目录表达。

## 4. 1v1 标签

| 标签 | 纳入 | 排除 |
|---|---|---|
| 教师／管理者 ↔ 教师／管理者 | 教学与运营人员之间的管理或专业沟通 | 一方是实际接受教学／辅导的学员 |
| 教师／导师／顾问 ↔ 学生／学员 | 明确存在教学、辅导、反馈或专业指导关系 | 纯同伴玩笑；家长代表孩子沟通 |
| 教师 ↔ 家长／监护人 | 围绕孩子、课程、学习或服务的家校沟通 | 只因学生账号推断家长 |
| 学生／学员 ↔ 学生／学员 | 同伴之间的学习或日常沟通 | 称呼与行动明确体现导师—学员关系 |
| 其他关系 | 有可辨认的其他关系，但当前标签集尚未独立承载 | 信息不足；信息不足应选无法判断 |
| 无法判断 | 角色关系证据不足或互相冲突 | 为减少拒判而猜测 |

阶段 A 出现疑似家长与学生／被照护者的 1v1。先记录为 `其他关系 + scene_note`，在 B 的自然样本和定向补样中观察覆盖量，再决定是否新增独立标签。

## 5. 独立的互动结构

场景关系之外，程序机械计算 `participation_pattern`：

- `one_way_broadcast`：窗口只有一个可见发送者，或绝大多数消息为单向发布且无实质回应；
- `two_way_exchange`：两个主要参与者持续来回；
- `multi_party_discussion`：三个及以上可见参与者有实质互动；
- `participation_uncertain`：身份字段冲突、正文缺失或证据不足。

互动结构不能自动决定角色关系。一个单向窗口可以是师生公告、教师内部通知、顾问播报或无人回应的个人连续发送。

## 6. 人工标签完成条件

- 必须先满足群聊／1v1 namespace；
- 明确案例可一键选择，无需编写长证据；
- 低把握、混合关系、家长语义身份、只有一个发送者或元数据冲突时，应填写 `scene_note` 或选择无法判断；
- 模型质检只能生成复核提示，不能静默覆盖人工值；
- 一个窗口若未选场景，也必须显式登记为“待标”，不能计为已完成。
- 人工复核明确确认最终场景后，辅助质检建议不得覆盖该值；若最终标签、`scene_note` 与当前 Codebook 定义仍冲突，应额外记录 `annotation_codebook_conflict`，该窗口在边界再次仲裁前不直接用于自动场景规则归纳。

## 7. 后续模型输入与输出

模型输入可以包含：完整窗口、原始会话形态、可见发送者行为、原始角色弱证据和经过人工校验的 Topic。模型输出至少包含：

- `scene_label`；
- `inferred_role_relation`；
- `interaction_mode`；
- `confidence` 与简短理由；
- 支撑判断的消息索引；
- `metadata_conflict`；
- 是否拒判。

不得使用关键词或 `user_type` 的单字段映射替代语义判断。

## 8. 开发与盲测边界

- A / B / C 的人工标签用于发现规则、补足稀有类别和修正提示；
- B 的顺序样本保持自然分布，稀有标签定向补样单独报告；
- D 在规则和标签集冻结前不得查看或用于调参；
- 最终按群聊和 1v1 分开报告 Macro-F1、逐类 Precision / Recall、混淆矩阵、拒判率、置信度校准和元数据冲突切片；
- 若根据 D 的错误修改规则，D 立即失去 holdout 资格，必须更换新的未见样本。
