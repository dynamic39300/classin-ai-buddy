> 输入：用户写入 v2.1 候选树的 5 处备注、阶段 A+B 80 个已复核会话与 331 个 `effective_topic`  
> 边界：用户已确认本文修正方向，本文作为 v2.2 冻结输入；不改写带人工备注的候选树，不读取阶段 D，Topic 适配只生成可逆迁移预览。

## 1. 总体判断

用户的 5 处备注全部成立，集中为四个结构问题：

1. `课程进度` 与宽泛的 `教学实施` 存在名称覆盖，但真实事项仍可区分；
2. 数字平台分支把故障、配置、工具对象和文件对象混成同级节点；
3. 普通闲聊缺少自然落点，且不能用“玩笑、梗”兜底；
4. `日常起居与生活事务` 和 `个人近况、经历与日常安排` 都过宽，后者尤其会吞并所有相邻节点。

目录可以在不同领域采用不同主轴，但**同一父节点下的兄弟节点必须能够比较，并能写出稳定的纳入、排除和相邻裁决规则**。

## 2. 逐项反馈与建议

### 2.1 教学内容／课程进度与教学实施

**判断：接受问题，但不建议合并。** 重叠主要来自 L2 名称过宽，而不是“教什么／教到哪里”与“怎么教”无法区分。

实例：

- `S1000-0024 / STI-9ef16a5c9a0d794249aa`：确认教材、页码和授课内容；
- `S1000-0123 / STI-8fe34e95060400c81c66`：确认教材、课程内容和后续进度；
- `S1000-0041 / STI-eba54660f706308a8009`：调整课堂语速，属于“怎么教”；
- `S1000-0044 / STI-b0895ea115c1f8e7673e`：调整朗读、记忆、提示和独立表达方式，属于教学方法。

拟议结构：

```text
L1-002 教学设计、实施与改进
├─ L2-023 教学内容规划与资源〔分组〕
│  ├─ L3-073 教材、教学资料与课件
│  └─ L3-012 课程内容范围与教学进度
└─ L2-042 教学方法、课堂规范与质量改进〔分组〕
   ├─ L3-014 教学方法与课堂活动设计
   ├─ L3-074 课堂互动规范与参与要求
   └─ L3-015 教学质量评价与改进
```

边界：

- 教什么、学到哪一页／单元、已完成和接下来覆盖什么 → `课程内容范围与教学进度`；
- 怎么教、如何提问、引导、调节语速或组织活动 → `教学方法与课堂活动设计`；
- 学生在课堂中应如何参与 → `课堂互动规范与参与要求`；
- 评价教师、课程设计或授课效果并提出改进 → `教学质量评价与改进`。

旧“教材与课程进度”的 5 个 Topic 中至少 3 个是复合事项，后续不能批量搬迁，需要按主要事项判断，必要时拆 Topic。

### 2.2 设备、应用、在线工具与文件媒体

**判断：接受问题。** 当前 `设备与应用配置` 的名字会自然包含在线工具和文件操作，兄弟节点不可稳定互斥。

实例：

- `S1000-0129 / STI-25955a34809779ca84c9`：调整应用使用时长，是真正的设置／限制；
- `S1000-0011 / STI-f465c15f5799da0ac687`：使用成长页黑板功能，属于在线协作功能；
- `S1000-0011 / STI-3ea0fb0c2b5ce5f28a9b`：拍照并发送图片，属于消息与媒体操作；
- `S1000-0033 / STI-9de114c0bf1b2e282a08`：打字与语音输入，旧路径“应用与设备使用”过宽，应改入消息输入操作；
- `S1000-0129 / STI-03c2e90fc1342549711f`：手机取用与位置，主要不是数字操作，应迁出本领域。

优先采用“用户正在解决的数字操作”作为同层表达方式：

```text
L2-045 设备、应用与数字操作〔分组〕
├─ L3-029 技术故障与连接排查
├─ L3-030 设备设置、应用安装与使用限制 ◇
├─ L3-032 在线课堂与协作功能操作 ◇
└─ L3-033 消息、文件与媒体操作
```
裁决顺序：

- 出现错误、断线、不可用并以排障恢复为主 → `技术故障与连接排查`；
- 安装、更新、配置、使用权限或时长限制 → `设备设置、应用安装与使用限制`；
- 黑板、白板、共享、课堂互动等教育协作功能 → `在线课堂与协作功能操作`；
- 输入、发送、上传、下载、图片、附件或媒体处理 → `消息、文件与媒体操作`。

与课程运营的边界：询问某节课的入口、会议号或是否能进入 → `教室与课堂接入`；因错误或连接异常无法进入并持续排障 → `技术故障与连接排查`。

备选方案是按技术对象建立节点，再把故障／配置／使用变成正交属性。该方案建模更纯，但会新增一层数据设计。建议先用上述最小修正版回放 A+B；若数字分支仍大量冲突，再升级为“对象 + 动作属性”。

### 2.3 普通闲聊与玩笑

**判断：接受问题。** `玩笑、梗与语言游戏` 不能承担所有闲聊。

需要区分两件事：

- “聊了什么”是主 Topic，例如天气、吃饭、影视、家庭或旅行；
- “以什么方式聊”是交流方式，例如闲聊、求助、提醒或反馈。

因此，聊明星仍归娱乐，聊天气仍归天气，聊晚餐仍归日常生活；不能因为语气轻松全部归入“闲聊”。但当一段持续对话没有更具体的外部议题，主要目的就是寒暄、分享近况、回应关心或维持联系时，这种社交功能本身可以成为一个窄 Topic。

A+B 压力实例：

- `S1000-0035 / STI-896436e0b0c1f0b31dfb`：夜间状态、准备睡觉与道晚安；
- `S1000-0018 / STI-7b5859bb7969e32bc1a1`：未及时回复、解释休息与确认没有忽略对方；
- `S1000-0008 / STI-adbcb1fb3a04476cdfff`：误读文字后持续围绕读音开玩笑，属于真正的“玩笑、梗”；
- `S1000-0113 / STI-a1f63588179f2c6369fb`：骑车险情与安全提醒，不属于玩笑，应按实际内容迁出。

建议在原社交分组中增加一个 provisional 节点，而不是创建无边界的“所有闲聊”兜底：

```text
L2-012 社交活动、日常交流与社群参与〔分组〕
├─ L3-038 见面、聚会与交流安排
├─ L3-084 日常寒暄与关系维系 ◇
├─ L3-039 社群参与与成员交流
└─ L3-040 玩笑、梗与语言游戏
```

`L3-084` 只在以下条件同时满足时使用：

1. 达到正式 Topic 门槛或特殊业务例外；
2. 没有更具体、持续的内容主题；
3. 沟通本身的主要功能是寒暄、陪伴、关心或维持联系。

后续如需要统计“闲聊型沟通”在所有主题中的比例，可再增加 `interaction_mode=casual_chat`；它不能替代内容 Topic。

### 2.4 日常生活的两个宽泛节点

**判断：两处问题都接受，但处理方式不同。**

旧日常生活实例主要是：

- `S1000-0047 / STI-ff9d6caf00f2c2e3f447`：餐食、饮品与领取；
- `S1000-0127 / STI-f2975f5aac73a6971ef1`：晚餐时间；
- `S1000-0129 / STI-fb20b50c87535e0fd59e`：晚餐安排；
- `S1000-0129 / STI-b05ae32373da58f74616`：宿舍生活用品寄送与领取。

建议：

1. `L2-047 日常起居与生活事务` 收窄为 `饮食、作息与生活事务〔终点〕`；
2. `L2-048 个人近况、经历与日常安排` 退出当前可选树，不再作为兜底；
3. 健康、宠物、天气、位置旅行继续进入其具体节点；
4. 没有明确外部议题、以分享近况和维持联系为主的内容，压力测试新节点 `L3-084`；
5. 仍无法稳定归类的 Topic 保留为 `taxonomy_gap`，而不是强塞进宽泛节点。

`饮食、作息与生活事务` 纳入吃饭、睡眠作息、生活用品、寄取和日常办事；排除健康医疗、旅行位置、天气、宠物、社交聚会、课程排期和学校事务。

## 4. 建议形成的 v2.2 共识

1. 教学分支不合并，以“教什么／进度”与“怎么教／质量”划界并收窄名称；
2. 数字分支先使用统一的操作型名称，清除 `设备与应用配置` 的宽泛覆盖；
3. 普通闲聊优先按内容归类；只有无更具体议题的持续寒暄／陪伴才进入 provisional 的 `日常寒暄与关系维系`；
4. 收窄 `日常起居与生活事务`，撤销宽泛的 `个人近况、经历与日常安排`；
5. 同步收紧零证据或名称超出证据范围的外围节点；
6. 以上共识确认前不修改原候选树，不启动 331 Topic 迁移。

## 5. 共识后的适用性扫描

共识形成后，对 A+B 331 个 Topic 逐条生成以下结果：

- `直接适配`：新节点和证据一致；
- `需改路径`：Topic 成立，但应进入别的节点；
- `需拆 Topic`：同一 Topic 实际包含两个独立且持续的主题；
- `taxonomy_gap`：当前树仍无稳定位置；
- `上下文不足`：仅凭现有窗口无法裁决。

每条结果必须保留 `window_id`、`topic_instance_id`、原有效路径、拟议新路径、证据消息 ID、裁决理由和置信度。扫描只生成迁移预览，不覆盖阶段 A/B 的原始模型路径与人工路径。
