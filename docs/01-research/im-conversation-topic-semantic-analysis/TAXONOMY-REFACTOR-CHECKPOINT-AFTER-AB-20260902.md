## 1. 重构目标

目标不是让目录更短，而是让相邻节点在完整上下文下可以稳定判断：

- 同一 Topic 不因说话角色不同而跨越多个 L1；
- 同一层级尽量只使用一种分类轴；
- 同义、近义或上下位混用的节点得到合并、拆分或明确边界；
- 每个节点具备名称、定义、纳入、排除、相邻节点决策规则和真实例子；
- A+B 的每个 Topic 可以从旧路径可逆映射到新路径；
- 历史模型结果与人工结果原样保留，新路径只进入派生迁移层。

## 2. 人工明确提出的三个优先问题区域

新附件中的红、橙、紫边框代表“需要优先复核重复定义和边界”的范围。边框表示审查范围，不等于框内节点必须全部合并；最终操作仍可能是合并、拆分、移动或补充定义。

### 2.1 红框：评价与反馈的上下位边界

- `L3-008 测评与考试反馈`
- `L3-010 学习表现与反馈`

人工进一步澄清：本轮真正比较的是上述两个叶节点；`学习计划与资源` 只是相邻节点，不是此次提出的重复项。两者本质上都在表达表现和反馈，测评／考试只是更具象的证据来源，而课堂表现、作业状态和教师观察更宽泛。

当前不预设“直接合并”。需要比较“正式测评与成绩 vs 日常学习表现”两个互斥叶，以及“统一评价主节点 + 证据来源属性”两种候选；备考和考试安排不能继续仅因出现考试词而归入“反馈”。

### 2.2 橙框：教材、材料和课件

- `L3-011 教材与材料选择`
- `L3-013 教学资料与课件`

人工进一步澄清：本轮真正比较的是上述两个叶节点；`教材与课程进度` 只是相邻参照。从自然语言看，“教学资料与课件”可以包含教材、材料及其选择，现有名称让普通标注者难以把对象与选择动作视为互斥类目。

优先验证“合并资源对象主节点 + 选择／适配／制作／获取／分享等受控动作属性”的方案；若保留两个叶，则必须统一改成动作型名称并验证混合动作 Topic 能否稳定裁决。

### 2.3 紫框：到课处理与课程服务管理范围

新图框出的优先审查范围跨越：

- `L3-019 到课与缺勤处理`；
- `L2-006 课程服务管理` 及其叶节点：
  - `L3-020 课程费用与薪酬`；
  - `L3-021 教师事务与人员管理`；
  - `L3-022 课程沟通与衔接`；
  - `L3-023 课程服务与行政`。

人工进一步澄清：到课／缺勤会直接影响教师课酬，也可能触发教师事务或行政处理；同时，“课程沟通与衔接”与“课程服务与行政”仅凭名称几乎无法区分。前半部分属于一个业务事件的原因、处理与后果相互关联，后半部分属于宽泛节点边界缺失，不能用同一种合并逻辑处理。

当前候选方向是保留具体业务事项为主路径，并用属性或跨 Topic 关系保存“缺勤导致扣薪、退款、取消、补课或人员处置”；“课程沟通与衔接”应收窄到可观察的课程生命周期事项，“课程服务与行政”作为只有一个特殊实例的宽泛兜底需考虑撤销或降级。当前不提前冻结。

## 4. 结构性问题类型

每个 taxonomy 问题至少标记为以下一种，防止只凭名称相似就合并：

| 类型 | 判断问题 | 可能处理 |
|---|---|---|
| 同义重复 | 两个节点的纳入案例是否基本相同 | 合并并保留旧 ID 映射 |
| 上下位并列 | 一个节点是否实际包含另一个节点 | 重排层级或收窄父节点 |
| 分类轴混用 | 同层是否同时按角色、对象、动作、流程分类 | 选定主轴，其他轴改为属性 |
| 多概念捆绑 | 一个节点名称是否包含两个可独立判断的对象 | 拆分节点 |
| 宽泛兜底抢占 | 宽泛节点是否覆盖多个已有具体节点 | 收紧定义并设置排除条件 |
| 生命周期相邻 | 节点是否属于同一流程的不同状态 | 保留节点并建立状态决策树 |
| Taxonomy 缺口 | 人工只能选择明显不合适的最近叶节点 | 新增节点或扩展定义 |
