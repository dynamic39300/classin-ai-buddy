# Taxonomy v2 候选树层级深度审计：以 A+B 实例为门禁

> 状态：`DEPTH_PROBLEM_CONFIRMED / V2_1_CANDIDATE_GENERATED / PENDING_HUMAN_REVIEW`  
> 输入：v2 候选树、阶段 A+B 80 个已复核会话、331 个 `effective_topic`；阶段 D 保持未见  
> 目的：判断哪些 L3 是必要业务分叉，哪些只是为保持固定三级而产生的空壳或过细分类。

## 1. 结论

人工指出的问题成立，而且不是个别现象：

| 每个 L2 的 L3 数 | L2 数量 |
|---:|---:|
| 1 | 1 |
| 2 | 15 |
| 3 | 9 |
| 4 及以上 | 4 |

当前 29 个 L2 中，有 25 个（86.2%）只有 1～3 个 L3。第二版候选树确实带有“先规定必须三层，再向下填节点”的倾向。

但正确处理不是“L3≤3 一律合并”，而是改成**可变深度 Taxonomy**：

- L1 是领域节点，不可直接作为最终分类；
- L2 可以是分类节点，也可以直接成为可选择的**终点主题**；
- L3 只在真实实例证明内部存在稳定、互斥且有研究价值的细分时出现；
- 一个 L2 有子节点时，该 L2 只负责分组、不可同时被选为终点；
- Topic 自由文本保留具体语义，Taxonomy 只承担稳定聚合，不必预先枚举所有可能内容。

## 2. 不按数量机械裁剪

子节点数量只触发审查，不直接决定合并：

| 情况 | 默认动作 | 例外 |
|---|---|---|
| 只有 1 个 L3 | 必须退出三级：父子合为终点 L2 | 无；一对一层级没有信息增量 |
| 2～3 个 L3 | 逐项做实例门禁 | 业务边界清晰、实例互斥时可以保留 |
| 4～7 个 L3 | 可正常保留 | 仍需检查是否同轴、互斥、非属性 |
| 超过 7 个 L3 | 触发拆组复核 | 防止一个 L2 变成无结构大包 |

两个典型对照：

- **应保留差异**：正式测评 4 个旧口径 Topic、日常学习表现 8 个；人工已明确要求互斥，且两者对应的证据来源和潜在处理不同。
- **不应提前细分**：`入学、升学与录取`、`专业、方向与选课` 在 A+B 都没有干净实例；当前只能进入候选池，不能因结构看起来完整就冻结为 L3。

## 3. L3 实例准入门禁

候选 L3 原则上需同时满足：

1. 同一父节点至少存在两个兄弟主题；
2. 兄弟节点使用同一种分类轴，而非把对象、动作、角色、渠道、原因和后果混排；
3. 每个节点都有一句可执行的纳入／排除边界；
4. 每个节点原则上至少有 2 个有效 Topic，并分布在至少 2 个会话；
5. 分开统计能够回答不同研究问题，而不只是让名称更具体；
6. 具体差异不能更合理地放入 Topic 文本或动作／角色／原因等属性；
7. 低频但人工确认具有特殊业务意义的节点可以例外保留，但必须标明例外原因。

证据不足时的处理：

- 0 个干净实例：放入“待验证候选池”，不进入当前可选树；
- 1 个实例：可作为 provisional 候选，不能声称边界稳定；
- 存在实例但人工认为是临时最近路径：不得用来证明该节点有效；
- 只有关键词相似、没有上下文语义证据：不得建节点。

## 4. 三种压缩动作

### A. 父子一对一：直接改为终点 L2

当前唯一明确实例：

```text
人际关系与社交
└─ 个人身份、特征与自我认知〔终点 L2〕
```

原 `身份与自我认知 → 个人身份、特征与自我认知` 只有一个子节点；A+B 只有 `S1000-0122 / STI-6e9a0fb4b88392be6407` 的 MBTI Topic。保留两层同义名称没有信息增量。

### B. 子概念不同，但父节点只是薄包装：把子节点提升为横向 L2

这类操作不丢失 Topic，只减少无意义的中间层。例如外围领域可使用：

```text
商业、消费与金融
├─ 商业与消费〔终点 L2〕
└─ 金融市场分析与交易〔终点 L2〕
```

具体“宏观信息”“交易安全”等 0 实例细分先进入候选池。

### C. 相邻薄 L2 属于同一稳定轴：横向聚合后保留 L3

例如原来的两个学习 L2 都只有两个 L3，但四个子主题有实际意义：

```text
学习与学业内容
└─ 学习任务、计划与评价〔分组 L2〕
   ├─ 作业布置、完成与订正
   ├─ 学习计划、复习与备考
   ├─ 正式测评、考试与成绩
   └─ 日常学习表现与反馈
```

A+B 旧口径分别有 11、2、4、8 个 Topic；聚合中间层不会删除人工已确认的正式测评／日常表现边界。

## 6. 建议的 v2.1 结构方向

不是简单减少叶主题，而是减少“只起包装作用的中间层”：

1. 学习：把两个薄 L2 合为一个 4 叶分组；
2. 教学：保留“内容与资源”二分；把实施、规范、质量和记录合为一个分组；
3. 课程运营：保留排期与课堂运行；按学员／教师两个业务对象重组服务、权益、人事和结算；
4. 数字平台：保留账号／联系人／群治理；把设备、应用、访问、课堂工具和文件操作合为一个技术操作分组；
5. 人际社交：压平身份的一对一层级，保留有实例的关系和社交三分；
6. 娱乐创作：保留两个较大分组，但不冻结零实例棋牌叶，合并低频且相邻的文字创作／角色扮演；
7. 日常及外围领域：优先使用终点 L2，等真实实例足够后再长出 L3；
8. 所有 0 实例细分进入“待验证候选池”，不进入当前可选目录。

## 7. 统计和实现影响

采用可变深度后，统计口径必须固定：

- L1：领域分布；
- L2：全局核心主题类目分布；
- L3：只用于某个 L2 内部的 drill-down；
- 不把终点 L2 与其他 L3 混成一张“同粒度排名”；
- 如需终点主题总榜，必须带 `terminal_level` 并明确它只用于检索，不代表同粒度比较。

现有实现强制三层，后续若确认 v2.1，需要同步修改：

- `taxonomy_schema.json`：允许 L2 没有 children，并显式记录 `is_terminal`；
- `topic_classification_schema.json`：路径长度从固定 3 改为 2～3；
- 分类与统计脚本：从“唯一 L3”改为“唯一终点节点”；
- 审阅台：L2 为终点时不再要求选择 L3，并显示“终点主题”标记；
- 导出字段：增加 `terminal_node_id` 与 `terminal_level`；
- 旧路径原样保留，禁止用同名伪 L3 填充两层路径。
