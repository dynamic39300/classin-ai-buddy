# Taxonomy v1 优先问题清单：A+B 实例回放

> 状态：`FOUR_DIRECTIONS_CONFIRMED / FULL_TREE_AUDIT_BEFORE_MIGRATION`  
> 输入：阶段 A+B 共 80 个会话、331 个源 Topic、人工复核后的 `effective_topic` 及可逆证据  
> 边界：本文只登记人工明确指出的红、橙、紫三处；完整树的扩展审计另见专门文档。不读取阶段 D，不改写 taxonomy v1，不把候选方案视为已确认结论。

## 1. 本轮需要分开的三种结构问题

| 区域 | 人工指出的核心困惑 | A+B 有效 Topic | 当前结构诊断 |
|---|---|---:|---|
| 红框 | `测评与考试反馈` 与 `学习表现与反馈` 都属于表现与反馈，前者只是更具象 | 4 + 8 | 上下位概念并列，且“测评”节点混入成绩、估分、备考等不同事项 |
| 橙框 | `教学资料与课件` 在自然语言上已经能够包含“教材与材料怎么选” | 6 + 4 | 上位对象名称与选择／获取／制作等动作轴混用 |
| 紫框 | 到课缺勤会影响课酬，也可能进入教师管理；“沟通衔接”与“服务行政”难区分 | 19 + 5 + 3 + 4 + 1 | 同一业务事件的原因、处理和后果被当作并列主题，同时存在宽泛兜底节点 |

这些区域不能统一用“把相近名字合并”解决。候选模型应先区分：

- **主路径**：这段聊天主要在处理哪个业务事项；
- **属性**：事项涉及什么证据来源、对象、动作和角色；
- **关系**：一个事项造成了什么下游影响，或与另一个 Topic 是什么因果关系。

上述三层是本轮候选建模原则，仍需人工确认后才能冻结。

## 2. 红框：评价上位概念与具体来源混在同层

### 2.1 人工原意

本轮人工明确比较的只有：

- `L3-008 测评与考试反馈`；
- `L3-010 学习表现与反馈`。

`L3-009 学习计划与资源` 仅是相邻节点，不属于人工此次提出的重复项。

人工判断是：两者本质上都属于学习表现和反馈；测评／考试只是反馈证据更具体的一种来源，课堂反馈、作业状态和老师观察则更宽泛。

### 2.2 A+B 的可逆证据

| 现有叶节点 | 会话 / Topic ID | Topic | 暴露的边界 |
|---|---|---|---|
| 测评与考试反馈 | `S1000-0044 / STI-462a91cd3a4db008f27e` | Emily 的 IELTS 听力分数估算 | 有标准化分数语境，但只是估分，不是正式结果 |
| 测评与考试反馈 | `S1000-0111 / STI-44f9fa067d2d27a6f977` | 确认 FCE 考试是否通过及分数 | 典型正式考试结果 |
| 测评与考试反馈 | `S1000-0114 / STI-4b053949eb2f9dc847c4` | 剑桥少儿英语考试与 A1 Movers 备考 | “备考”被放进“反馈”，说明节点捆绑多个生命周期 |
| 学习表现与反馈 | `S1000-0044 / STI-195dbf47abe5e181514b` | Emily 的 IELTS 听力练习与薄弱项 | 日常练习表现、薄弱点和改进方向 |
| 学习表现与反馈 | `S1000-0103 / STI-098f86bc32858650572d` | 数学学习薄弱点、作业反馈与复习安排 | 人工从“数学学习”改入，主要目的确为学情反馈 |
| 学习表现与反馈 | `S1000-0114 / STI-a4f505041fa157202df7` | 学生英语课堂表现与口语学习 | 课堂观察与持续表现 |

`S1000-0044` 同一会话同时出现“听力练习薄弱项”和“IELTS 分数估算”，说明两类信息确实可以同时存在；问题不只是名称相近，而是当前树没有稳定表达“评价证据来源”和“沟通目的”的关系。

### 2.3 候选处理

优先比较两种方案：

1. **保留两个互斥叶节点**：改为“正式测评、考试与成绩”与“日常学习表现与反馈”。边界依据是证据来源，不依据是否出现“考试”等关键词；备考和考试安排移出反馈节点。
2. **合并为一个主节点**：“学习表现、测评与反馈”，再用 `evidence_context = classroom / homework / assessment_exam / teacher_observation` 表达来源。

当前倾向先测试方案 1，因为正式成绩处理与日常学情反馈可能牵引不同产品能力；但若 A+B 的迁移回放仍大量出现混合 Topic，则应改用方案 2。此处尚未裁决。

## 3. 橙框：教学资源对象与资源动作混用

### 3.1 人工原意

本轮人工明确比较的只有：

- `L3-011 教材与材料选择`；
- `L3-013 教学资料与课件`。

`L3-012 教材与课程进度` 仅作为邻接参照，不属于人工此次提出的重复项。

人工判断是：从普通使用者的自然语义看，“教学资料与课件”已经能包含教材、材料以及如何选择这些内容，标注者很难把“对象”与“选择动作”当作互斥类目。

### 3.2 A+B 的可逆证据

| 现有叶节点 | 会话 / Topic ID | Topic | 暴露的边界 |
|---|---|---|---|
| 教材与材料选择 | `S1000-0001 / STI-f2b296d99c9087b6fb81` | 为初学儿童学生选择课程教材 | 典型选用与适配 |
| 教材与材料选择 | `S1000-0019 / STI-fd7a9058103f2e9f4c51` | 英语教材与课件准备 | 同时含发送、版本、适配、进度和文件问题 |
| 教材与材料选择 | `S1000-0048 / STI-b5ea683ef2210fa50bd5` | 学生教材与阅读级别调整 | 选择与难度适配 |
| 教学资料与课件 | `S1000-0001 / STI-d24070844d8f7317985e` | 查找 Let's Talk 教材 | 对象仍是教材，动作变成查找 |
| 教学资料与课件 | `S1000-0026 / STI-9b98f8bf8b20abc8e9e6` | 使用 AI 制作个性化课件 | 制作与改编动作 |
| 教学资料与课件 | `S1000-0123 / STI-edfef61f6d5ff6e4c7fc` | 学生课件查找与推荐 | 同时横跨选择／推荐与获取 |

### 3.3 候选处理

当前更强的候选是：

- 合并两个对象叶为 `教材、教学资料与课件`；
- 把 `select / adapt / create / find / acquire / share / use / troubleshoot` 作为受控的 `resource_action` 属性；
- 将相邻的 `教材与课程进度` 另行复核，只承接页码、单元、已学／待学和内容衔接时，可收窄为“教学内容与课程进度”。

备选方案是保留两个节点，但改为动作型名称“教学材料选择与适配”与“教学材料获取、制作与共享”。该方案保留产品动作差异，却会让一个 Topic 因包含多个动作而频繁跨叶。A+B 中 `S1000-0019`、`S1000-0041`、`S1000-0123` 应作为压力测试案例。

## 4. 紫框：业务因果链不是目录同义

### 4.1 人工原意

人工指出两层真实困惑：

1. 到课、请假和缺勤会直接影响教师课酬，也可能触发教师事务或行政处理；
2. `课程沟通与衔接` 与 `课程服务与行政` 名称宽泛，无法从名称稳定判断边界。

这说明当前目录没有表达“事件 → 业务后果”的关系，但不意味着到课、薪酬和人员管理本身是同义主题。

### 4.2 A+B 的可逆证据

| 现有叶节点 | A+B Topic / 会话 | 关键证据 |
|---|---:|---|
| 到课与缺勤处理 | 19 / 13 | `S1000-0001 / STI-0adec9dc50ae441551d7` 同时讨论迟到、课程移除、扣罚和调整；`S1000-0027 / STI-5f413ec2e37fad749e71` 同时询问学生离开课堂后的处置和教师是否有课酬 |
| 课程费用与薪酬 | 5 / 5 | `S1000-0030 / STI-e1ffeb2915b6e19331c6` 的薪资延迟与同会话缺席链相关；`S1000-0050 / STI-93b9e9de5edf25e7248b` 又把课时费、课时记录与加课安排混在一起 |
| 教师事务与人员管理 | 3 / 3 | 招聘、入职、宣传材料较一致；`S1000-0107 / STI-429c8fec757131164c07` 的入职规则又天然携带出勤、薪酬、排班和教学规范 |
| 课程沟通与衔接 | 4 / 4 | 三个稳定实例实际都是试听、首课或新学员承接；`S1000-0008 / STI-30ffd603588244a68979` 仅因使用公开课链接沟通而误入 |
| 课程服务与行政 | 1 / 1 | 唯一实例 `S1000-0027 / STI-783a199447c502ec1b83` 只是“工作群沟通课程问题、请假提前三小时”的单消息规则，既可解释为请假规则，也可解释为教师工作规范 |

`S1000-0030` 是最清楚的跨节点因果链：多次缺席和请假影响学生继续预约，并进一步关联薪资延迟。当前两个 Topic 的证据消息没有重叠，说明它们可以是两个独立事项；但目录又没有保存二者的因果关系。

### 4.3 候选处理

当前不建议把紫框全部合并。候选结构是：

- 保留并收紧“到课、请假与缺勤处置”，只承接出勤事实、规则与即时处置；
- 将“课程费用与薪酬”至少在定义上区分学生侧课程收费／退款与教师侧课酬／薪资／奖励／扣罚；
- 保留“教师招聘、入职与人员管理”，一次迟到本身不进入人员管理，只有持续违规后的纪律、替换或离职进入；
- 将“课程沟通与衔接”收窄为“试听、首课与学员承接”；
- 撤销或降级“课程服务与行政”这一可直接选择的宽泛叶节点，规则通知回到具体业务对象；
- 用 `cause`、`business_impact` 和跨 Topic `relation` 保存“缺勤导致扣薪、退款、取消、补课或纪律处理”。

建议的裁决规则是：若聊天主要在确认是否到课及如何继续上课，主路径为出勤，薪酬记为影响；若主要在核算或申诉扣薪，主路径为结算，缺勤记为原因；只有两个诉求都独立持续推进时才拆成两个 Topic，并保留因果关联。
