# Taxonomy v1 全树结构审计：阶段 A+B 后、迁移前

> 状态：`FULL_TREE_AUDIT_COMPLETE / V2_CANDIDATE_PENDING_HUMAN_REVIEW`  
> 审计对象：`classin-im-semantic-topic-taxonomy-v1-20260901`，10 个 L1、20 个 L2、70 个 L3  
> 证据范围：阶段 A 50 个会话与阶段 B 30 个会话，共 331 个 `effective_topic`；阶段 D 保持未见  
> 本文性质：目录结构审计，不是 A+B Topic 迁移结果，也不是产品功能结论。

## 1. 本轮回答什么

本轮不只检查人工圈出的红、橙、紫三组节点，而是用同一套规则审查全部 L1/L2/L3：

1. 同义或高度重叠的节点是否并列；
2. 上位概念和下位概念是否被放在同一层；
3. 对象、动作、渠道、角色、原因、后果和安全属性是否被混成主主题；
4. 一个节点是否捆绑了多个可独立判定的概念；
5. 是否存在会吞并其他节点的宽泛兜底；
6. A+B 已经出现、但 v1 没有稳定位置的真实主题是否构成目录缺口；
7. 结构上看似合理、但 A+B 没有正例的节点是否被错误地当成已验证节点。

## 2. 审计判据

### 2.1 主路径只回答“主要在聊什么”

每个 Topic 进入一条唯一的 `L1 → L2 → L3` 主路径。路径按聊天中正在被处理的主要对象或事项判断，不按关键词、说话人角色、群聊类型、使用工具或未来产品能力判断。

### 2.2 以下信息不再与主主题争夺目录位置

- **动作属性**：选择、制作、查找、分享、使用、排障等；
- **媒介属性**：群聊、私信、电话、链接、文件、在线课堂等；
- **原因与影响**：天气导致断网、缺勤导致扣薪、请假导致补课等；
- **角色与场景**：老师、学生、家长、管理者，班群、管理群、1v1 等；
- **证据状态**：正式成绩、估分、观察、转述；
- **安全属性**：成人内容、隐私、风险等级；
- **分类状态**：上下文不足、目录缺口、需要拆题。

这些信息仍然需要保留，但应进入属性、关系或状态字段，而不是重复制造主目录节点。

### 2.3 证据强度分层

| 标记 | 含义 | 能否直接冻结 |
|---|---|---|
| 人工已确认方向 | 本轮对话已明确裁决的结构原则 | 可以进入候选树，但仍需看完整树的一致性 |
| A+B 有证据候选 | 有可逆 Topic 与消息证据支持 | 经完整目录审阅后可进入迁移测试 |
| 低证据候选 | 只有少量或边界不干净的实例 | 不能声称稳定，迁移时需单列 |
| A+B 未验证 | A+B 没有干净正例，仅有结构合理性 | 暂保留为候选，不得因零样本删除，也不得宣称已验证 |

## 3. 总体诊断

v1 的问题不是“分类数量太多”或“名称都不好”，而是部分分支使用了不同的分类轴：

- 学习分支把任务、计划、资源和评价放在同一 L2；
- 教学分支把资源对象、资源动作、内容进度和教学法混在一起；
- 课程运营分支把排期、出勤、接入渠道、费用、人事和行政兜底交叉组织；
- 数字分支会因为出现群、链接、通话或文件而抢走真实业务目的；
- 社交分支把关系、身份、活动和“闲聊语气”混为一轴；
- 娱乐分支把内容消费、游玩、收藏、创作和角色互动混为一轴；
- 日常生活分支缺少“个人近况与经历”，导致真实内容落入“轻松闲聊”；
- 教育、研究、职业、商业和消费被放在同一 L1；
- 金融、法律、安全风险和公共信息被放在一个只有单一 L2 的 L1；
- 成人内容与“无法分类”被错误地包装成同一个内容域。

因此，v2 候选不是简单地改几个名称，而是要统一“内容主路径”的分类轴，同时把动作、媒介、原因、影响、安全和不确定性移出目录树。

## 4. 各分支审计结论

### 4.1 L1-001 学习与学业内容

**保留 L1，重组 L2。**

主要问题：

- `学习任务与评价` 同时包含作业、计划、资源、正式考试和日常表现；
- `测评与考试反馈` 把备考、考试过程、正式成绩和估分捆在一起；
- `学习计划与资源` 中的“资源”是对象或媒介，不应与计划并列；
- A+B 出现教师指导学生做研究方法、论文项目和软件项目调试，v1 缺少稳定位置。

候选处理：

- 保留并扩展“学科、技能与研究学习”；
- 将原 `学习任务与评价` 拆成“学习任务与计划”及“学习评价与表现”；
- 按人工确认保留两个互斥叶：`正式测评、考试与成绩`、`日常学习表现与反馈`；
- 备考归 `学习计划、复习与备考`，练习估分不视为正式成绩；
- 新增 `研究方法与学术项目学习`，承接教学／辅导目的的研究、论文和项目方法学习。

### 4.2 L1-002 教学与课程内容

**L1 建议改名为“教学设计、实施与改进”，重组材料与实施分支。**

主要问题：

- `教材与材料选择` 与 `教学资料与课件` 是同一资源对象上的不同动作；
- `教材与课程进度` 中“课程进度”容易与日历排期混淆；
- `教学方法与课堂活动` 同时包含教学设计和课堂行为规范；
- `教学反馈与质量` 没有说明反馈对象，容易吞并学生表现和课程服务评价。

候选处理：

- 按人工确认合并为 `教材、教学资料与课件`，动作用 `resource_action[]` 表达；
- 收窄为 `教学内容与课程进度`，只承接页码、单元、已学／待学及内容衔接；
- 拆出 `课堂互动规范与参与要求`；
- 将教学评价明确为对教师、教学设计或授课质量的评价；学生表现与服务投诉另行归类。

### 4.3 L1-003 课程运营与服务

**保留 L1，按业务生命周期重组所有 L2。**

主要问题：

- 课前供给时段、具体预约、已排课程变更和实际出勤被混在一起；
- `在线课程运行` 把在线渠道当作主轴，与到课和技术故障交叉；
- `课程费用与薪酬` 把学员侧权益／退款与教师侧课酬／薪资混为一体；
- `教师事务与人员管理` 同时承接招聘入职与违规处置；
- `课程沟通与衔接` 和 `课程服务与行政` 名称宽泛、无法稳定区分。

候选处理：

- 按“供给时段 → 预约 → 变更 → 到课／运行”重组；
- 将“在线”降为媒介，主节点改为教室接入与课堂运行；
- 拆分学员权益费用与教师课酬结算；
- 拆分教师招聘入职与教师工作规范／人员处置；
- 收窄为 `试听、首课与学员承接`；新增 `服务评价、投诉与口碑跟进`；
- 撤销 `课程服务与行政` 的直接可选地位，规则或登记回到其实际治理对象。

### 4.4 L1-004 数字平台与技术

**保留 L1，收紧“技术本身是处理对象”的准入规则。**

主要问题：

- `在线联络与联系人` 同时包含联系人功能与约通话、担心失联等社交目的；
- `应用与设备使用` 是宽泛技术兜底；
- 文件、链接、群聊和在线课堂常只是教学或社交的媒介。

候选处理：

- 只有账号、群组空间、联系人功能、设备、应用、权限或文件操作本身被处理时才进入数字域；
- 把联系时间、社交邀约和关系担忧按真实目的移出；
- 将群设置扩展为 `群组空间与成员治理`；
- 将故障、正常配置、访问权限和文件操作分开。

### 4.5 L1-005 人际关系与社交

**保留 L1，统一为“关系／身份／社交安排”三种对象。**

主要问题：

- `个人与同伴信息` 与关系类型混轴；
- `同伴关系与互动` 同时承接关系状态和共同活动；
- `轻松闲聊与玩笑` 把“聊天语气”当成内容主题，已吞并个人真实经历。

候选处理：

- 将身份、自我特征和人格认知单列为 L2；
- 共同见面、聚会和交流安排归社交安排，关系冲突／支持归关系与相处；
- 将 `轻松闲聊与玩笑` 严格收窄为 `玩笑、梗与语言游戏`；
- 普通个人经历不能再因语气轻松而进入该节点。

### 4.6 L1-006 娱乐与创作

**保留 L1，统一为“消费／游玩／收藏”与“创作／扮演”两条轴。**

主要问题：

- 电子游戏节点包含游戏制作；
- 体育和棋牌桌游被合并；
- 收藏被放在创作分支；
- 纯文件处理可能误入音视频创作，普通角色称谓可能误入角色扮演。

候选处理：

- 电子游戏只保留玩法和游戏内容，软件项目学习回到学习分支；
- 拆分运动娱乐与棋牌／线下游戏；
- 收藏移动到娱乐消费分支；
- 创作节点要求存在实际创作、改编或发布动作；
- 角色扮演要求共同设定、角色分工或持续虚构行动。

### 4.7 L1-007 日常生活与健康

**建议改名为“日常生活、健康与出行”，重建两个异质 L2。**

主要问题：

- `日常生活与饮食` 同时装入饮食、睡眠、用品、取件、支付和个人安排；
- `旅行与地点经历` 同时装入通勤定位和旅行见闻；
- 天气、居住和个人形象超出当前 L1 名称；
- A+B 已出现“骑车险情”等个人近况，v1 只能临时放入轻松闲聊。

候选处理：

- 拆出饮食作息、居住用品、个人近况与日常安排；
- 将健康医疗与运动体能组织到同一 L2；
- 将天气、通勤位置与旅行经历组织到出行分支；
- 疾病或天气若只是调课、缺勤或断网原因，只记为 `cause`，主路径跟随实际待处理事项。

### 4.8 L1-008 教育与工作经济

**原 L1 撤销并重组为“教育路径、研究与职业”及“商业、消费与金融”。**

主要问题：

- 教育阶段、专业选择、独立研究、职业处境、卖方经营和买方消费没有共同的稳定分类轴；
- `升学与教育路径` 与 `高等教育与专业选择` 是上下位并列；
- `学术研究与论文` 仅按“论文”对象判断，吞并教师指导学生完成研究任务的学习场景；
- 职业事务把求职、入离职、工时和职场关系捆在一起。

候选处理：

- 教育路径按“入学升学录取”与“专业方向选课”拆分；
- 教学／辅导目的的论文与研究迁入学习分支；独立专业研究另设低证据候选；
- 职业分为职业发展与日常工作关系；
- 商业经营和个人消费移入新的商业金融分支。

### 4.9 L1-009 金融与公共信息

**原 L1 拆分为“商业、消费与金融”及“法律与公共事务”。**

主要问题：

- L1 下只有一个几乎同义的 L2，层级冗余；
- 金融、宏观经济、法律、个人风险、隐私和公共新闻混轴；
- `金融市场与交易` 与 `经济与市场信息` 对行情／市场分析存在重叠；
- “风险”是跨域属性，个人险情、账号安全、金融诈骗和公共安全不应共用一个叶。

候选处理：

- A+B 的金融实例常同时包含行情和交易，合并为 `金融市场分析与交易`，具体动作用属性表达；
- `宏观、行业与企业信息` 明确排除具体标的、仓位和进出场；
- 金融安全、数字安全、个人经历和法律权利按实际对象分别落位；
- 将法律权利、公共安全、政策社会议题和公共运行事件组织到独立 L1。

### 4.10 L1-010 特殊内容主题

**从主内容树撤销。**

主要问题：

- 成人性内容是内容安全属性，不是与“其他”并列的业务内容域；
- `其他/待细分主题` 把证据不足、目录缺口、需要拆题和真实新主题混在一起；
- A+B 的 7 个“其他”实例中，没有一个构成永久 Other 叶的干净正例。

候选处理：

- `content_safety=adult_sexual` 作为正交安全属性；
- `classification_status=matched / context_insufficient / taxonomy_gap / needs_split` 作为分类状态；
- 未匹配内容不进入主 Topic 频率统计，先进入待复核队列；
- 旧 L1-010/L2-020/L3-069/L3-070 只保留兼容映射，不再可选。

## 5. 全树共同边界规则

1. **反馈在评价谁**：学习者表现 → 学习；教师／教学质量 → 教学；服务体验／投诉 → 课程运营。
2. **进度是什么进度**：内容页码／单元 → 教学；日历排期 → 课程运营；学习计划执行 → 学习。
3. **课件问题是什么问题**：内容选择／制作／使用 → 教学资源；上传权限或格式 → 数字工具；获取只是媒介时按主要诉求判断。
4. **未进课堂为什么**：人未到 → 出勤；教室／会议码未配置 → 接入；网络设备异常 → 数字技术。
5. **规则约束谁**：请假规则、课堂互动规则、教师工作规范、群组治理分别回到对应对象。
6. **论文为了什么**：教师指导或课程任务 → 学习；独立专业研究和发表 → 专业研究。
7. **工具还是目的**：群、电话、链接、文件只是媒介时，不创建数字主题。
8. **风险属于什么对象**：个人经历、金融交易、数字账号、法律权利或公共安全分别落位；“风险”本身只做属性。
9. **疾病／天气是否只是原因**：若主要在调课、请假、退款或断网，主路径跟随业务事项，疾病／天气记为原因。
10. **闲聊有没有实际内容**：有稳定可概括的个人经历、作品、关系或生活事项时按内容落位；只有玩笑、梗或语言游戏才进入玩笑节点。

## 6. 需要人工审阅的结构风险

以下不是已冻结结论：

- `专业研究与学术发表`、`职业与工作`、`商业经营`、`宏观行业企业信息` 等在 A+B 中没有或几乎没有干净正例；
- `教学记录、总结与回放`、`课堂开结、时长与中断`、`链接、权限与内容访问` 等结构合理，但 A+B 未覆盖；
- `个人近况、经历与日常安排` 有真实缺口证据，但必须防止它变成新的“轻松闲聊”兜底；
- `公共事务与社会信息` 的 A+B 正例很弱，节点边界必须在后续阶段用新样本验证；
- 软件项目调试应按“学习／项目目的”与“通用应用故障”区分，不能只看技术词。

## 7. 数据冲突与迁移门禁

- `STI-b9d5718f8e82ff9771ed` 的机器字段显示 `decision=agree`，但人工备注明确认为应归学生学习内容；后续迁移必须列入冲突复核，不能直接当金标。

- 一对多拆分、上下文不足、目录缺口和低证据节点必须单列，不得为了覆盖率强行归类。
