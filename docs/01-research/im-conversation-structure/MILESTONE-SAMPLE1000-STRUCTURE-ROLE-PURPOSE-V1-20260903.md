# ClassIn IM 1000 会话结构、角色与沟通用途研究里程碑

## 0. 里程碑结论

本阶段已经完成固定 1000 会话窗口的会话结构核验、当前机构身份解析、班内身份并列保存、教师活跃候选窗口召回、教师管理协作用途语义裁定，以及最终结果物化和可逆审阅页建设。数据库证据不足的 165 个 1v1 和 7 个课程群也已由用户结合完整上下文完成人工裁定；5 条交叉检查异常经过用户确认修正。当前 1000 窗口范围内不再保留角色未解析结果。

本阶段建立了一个后续研究可以复用的事实框架：

```text
会话结构
× 当前机构身份构成
× 班内角色及其冲突
× 窗口活跃发送者构成
× 沟通用途窗口信号
× 已冻结 Topic
```

这些维度不再被压缩成一个含义混杂的“场景标签”。所有结论都保留会话、成员、UID、Topic 和消息证据的溯源关系。

本轮只回答“会话发生在什么结构和角色关系中，以及当前窗口呈现什么沟通用途”，不直接推出 IM 或 AI 产品功能结论。

## 1. 研究起点与问题

此前已经完成会话 Topic 识别与 v2.3 目录冻结，但 Topic 只回答“聊了什么”。为了进一步理解主题发生在哪类沟通关系中，本阶段集中回答：

1. 当前会话是课程班级群还是 1v1 单聊；
2. 完整成员分别是什么当前机构身份，而不只是窗口里谁发过言；
3. 当前机构身份与班内角色是否一致；
4. 1v1 双方是否可以被可靠识别为教师—教师、教师—学生或学生—学生；
5. 完整成员均为教师型角色时，窗口语义属于教师管理协作、教师内部沟通，还是证据不足；
6. 结构、角色、用途和 Topic 是否能够保持正交并可逆追溯。

| 抽样 Manifest | 1000 个唯一 `clusterid` | `eceda9bde708ae9e2cdc73d5879509587c8357573e38cd3e25f2cc09d1945e0f` |

每个 `clusterid` 在本次抽样中只出现一次，即只有一个 100 消息窗口。因此，本阶段可以形成“窗口用途信号”，但不能仅凭一个窗口把群永久定型。

## 3. 本阶段形成的关键规则

### 3.1 会话结构以业务事实为先

- `clustertype=0` 必须通过课程关联门禁后才能称为课程班级群；
- `clustertype=1` 作为 1v1 单聊处理；
- 不能仅凭消息数量、发言人数或语义猜测群结构。

固定样本中 780/780 个 `clustertype=0` 会话均且仅匹配一个课程。当前数据没有发现自建多人群或一个群关联多个课程的例外。

### 3.2 当前机构身份与班内角色是两套事实

最终判定规则如下：

1. 先由课程确定当前会话所属机构；
2. 只使用 UID 在该机构中的当前有效身份；
3. 不用其他机构身份或历史身份覆盖当前机构结果；
4. 班内角色独立保存，用于表达用户在具体班级中的职责；
5. 加入或创建班级不等于机构职业身份自动改变；
6. 两层身份不一致时记录 `role_conflict`，不强行选择其中一个覆盖另一个。

因此，“机构老师在某个班呈现学生式班内角色”和“机构学生在某个班呈现教师式班内角色”都是允许被记录的冲突事实。它们证明两层角色可能不同，但不能证明系统必然执行了机构身份转换。

### 3.3 完整成员不能由活跃发送者替代

窗口中只有教师型账号发言，并不表示完整成员只有教师。教师内部用途的正向判定必须先通过完整成员构成门禁。

### 3.4 教师群用途依赖完整语义

教师成员群的有效用途类型只保留：

- `teaching_management_collaboration`：教师管理协作；
- `teacher_internal_communication`：一般教师内部沟通。

“教师专业交流”作为 Topic 或内容特征保留，不单独设置群类型；“用途混合”和“用途待定”也不作为群类型。证据不足是拒判状态。

教师管理协作必须同时存在：

```text
管理对象 + 管理动作 + 组织方向或状态变化
```

课程进度、教学方法、课堂体验和教学活动本身不能决定群类型。只有当这些内容形成规则、分工、期限、督办、异常处置、验收或其他治理足迹时，才支持教师管理协作判断。禁止通过关键词命中直接分类。

## 4. 执行过程

### Phase 0：冻结范围与输入

- 固定 1000 个窗口、100,000 条消息和唯一 `clusterid`；
- 固定 v2.3 Topic 结果；
- 计算三份输入哈希，确保后续派生过程不覆盖源数据。

### Phase 1：核验会话结构

- 对 780 个 `clustertype=0` 会话执行课程关联门禁；
- 对 220 个 `clustertype=1` 会话建立 1v1 结构快照；
- 保存结构证据与 QA，而不是只保存展示名称。

### Phase 2：解析成员与角色

- 获取班级群完整成员，而不只读取发言人；
- 以课程机构为锚点解析 UID 当前有效机构身份；
- 并列保存当前机构身份、班内角色和冲突状态；
- 统计完整成员构成与窗口活跃发送者构成；
- 对 1v1 双方进行角色关系解析，证据不足时保留未解析。
- 对数据库证据不足的 172 个窗口建立独立人工 Gate；保留原人工选择，再通过结构、当前角色事实和完整聊天语义交叉检查形成生效裁决层。

### Phase 3：召回教师活跃候选窗口

- 从课程群中召回窗口内只有教师型账号发言的会话；
- 再检查完整成员构成；
- 把完整成员仍包含学生的会话作为结构负对照，不升级为教师内部群。

### Phase 4：教师沟通用途语义裁定

- 阅读完整 100 消息上下文和现有 Topic；
- 检查管理对象、管理动作和组织方向/状态变化；
- 保存用途标签、置信度、Topic ID、消息 ID、简短理由和不确定性；
- 对证据不足的窗口拒绝猜测。

### Phase 5：结果物化与验收

- 为全部 1000 会话生成研究展示标签；
- 生成结构 × 角色 × 用途 × Topic 交叉表；
- 建立包含完整消息、Topic、证据高亮和人工反馈导出的审阅页；
- 执行覆盖、一致性、证据引用、哈希和接口级测试。

### 5.4 当前机构身份与班内角色冲突

课程群共获得 18,765 条当前成员记录：

| 状态 | 成员记录数 |
|---|---:|
| 两层角色一致 | 18,463 |
| 两层角色不同 | 269 |
| 当前机构角色未解析 | 33 |

冲突或未解析合计 302 条成员记录、283 个唯一 UID，分布在 15 个课程群；其中 45 条是本次窗口中的活跃发送者记录。“成员记录”“UID”“会话”是不同分母，不得互换。

### 5.5 教师活跃候选窗口与用途

共召回 52 个“窗口内只有教师型账号发言”的候选窗口：

- 23 个完整成员为 `staff_only`；
- 29 个完整成员仍包含学生，因此继续归为师生班级群；
- 9 个满足教师管理协作三要素；
- 41 个明确不是教师内部窗口，其中包含上述 29 个结构负对照；
- 2 个证据不足；
- 本样本未发现达到稳定判定标准的一般教师内部沟通正例。

52 是方法验证候选集的分母，不代表平台教师群发生率。9 个教师管理协作结果也只代表对应窗口，不代表群的长期主导用途。

## 6. 当前可以确认与不能确认的事项

### 可以确认

- 固定样本中的 780 个 type 0 会话均为课程关联群；
- 当前机构身份和班内角色确实存在不一致记录；
- 仅看发言人会把一部分师生班级群错判为教师内部群；
- 教师管理协作能够通过完整语义和治理足迹被识别；
- 结构、角色、用途、Topic 可以被正交保存并回到原始消息复核。
- 固定 1000 窗口中的角色关系已通过数据库事实与人工完整上下文裁定实现 100% 覆盖。

### 不能确认

- 不能把当前成员快照无条件解释成每条历史消息发送时的角色；
- 不能把未解析 1v1 猜成家长、学生或教师关系；
- 不能由一个 100 消息窗口确定一个群的永久用途；该问题也不属于当前研究目标；
- 不能把当前未加权 1000 样本比例外推为全平台发生率；
- 不能从本阶段结果直接跳到具体 IM/AI 功能优先级。

## 9. 已完成的人工 Gate

本阶段所有必要人工 Gate 均已完成：

1. 16 个教师沟通用途边界会话已经复核并形成规则校准；
2. 数据库角色证据不足的 172 个会话已经逐个完成人工角色判断；
3. 5 条结构或语义异常已经由分析方复核并经用户确认修正；
4. 1000 会话的结构、当前角色关系、窗口用途、Topic、分类路径和消息证据已经连接为同一可逆派生数据集。

用户已明确当前研究不需要判断一个群的长期定义或长期用途。补取同群多个时间窗口属于另一项扩展研究，当前不执行，也不构成现有结果缺口。

## 10. 下一阶段计划

事实层完成后，进入研究解释与产品牵引阶段：

1. 基于 `Topic × 会话结构 × 生效角色关系 × 当前窗口用途` 形成分层统计；
2. 找出不同角色关系下高频、重复出现且具有明确痛点或信息诉求的主题；
3. 区分基础 IM 能力缺口、适合 AI 辅助的节点，以及不值得产品化的闲聊或低价值需求；
4. 再与 Slack 等沟通产品及教育业务流程做针对性对照，避免照搬；
5. 最终形成 IM 基础能力建议、AI 辅助能力建议和证据 Case，并映射到已有 Demo 或后续产品方案。

## 11. 当前用户需要做什么

用户当前没有必须继续填写的表或审阅任务。下一步由分析方基于已经冻结的事实层形成研究结论；只有出现会显著改变结论的新边界问题时，才提交少量定向 Case 请求人工复核。
