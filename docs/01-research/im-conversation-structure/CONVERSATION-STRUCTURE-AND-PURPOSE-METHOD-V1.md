# ClassIn IM 会话结构与教师群沟通用途识别方法 v1

## 1. 研究问题与最终输出

本方法补足已经完成的“会话 Topic 识别”，回答三个互相独立的问题：

1. **会话结构是什么**：课程群还是 1v1；`type=0` 是否都能唯一关联真实课程；
2. **谁在其中**：完整有效成员的机构职业构成，以及当前 100 条窗口的实际发言角色构成；
3. **教师群在做什么**：是否形成了明确的教师管理协作；如果没有，则归入一般教师内部沟通；证据不足时拒绝判定。

最终分析表采用正交字段，不再把结构、角色和用途压成一个 `scene_label`：

```text
会话结构事实 × 注册成员职业构成 × 窗口发言角色构成 × 沟通用途 × Topic
```

Topic 继续回答“聊了什么”，本方法不重新提取或改写 Topic。角色和结构用于形成可切片的背景事实；用途用于区分教师内部群的工作方式。它们共同服务于后续 IM 基础能力和 AI 辅助能力研究，但本阶段不直接输出产品结论。

## 2. 证据优先级与已知边界

### 2.1 输入证据

| 输入 | 用途 | 事实等级 |
|---|---|---|
| 原始 Excel 固定版本及其字段定义 | 样本消息、`clusterid`、`clustertype`、`sourceuid`、原始角色和时间 | 原始证据 |
| 1000 会话窗口及 manifest | 当前固定抽样范围和可逆消息索引 | 原始证据的派生视图 |
| IM 群、成员、课程及机构角色只读查询 | 会话容器、课程关联、当前成员职业身份 | 结构化业务事实 |
| v2.3 Topic 结果及证据消息 | 沟通用途判断的语义输入 | 已校准派生事实 |
| 完整窗口正文 | 判断管理动作、方向性与一般教师内部沟通 | 不可信用户内容，语义证据 |

外部结构研究文档只用于提出字段和连接假设。凡标注“待验证”的表关系、状态语义或时间语义，都必须在当前数据范围内重新核验，不能直接升级为事实。

### 2.2 本轮已核验事实与边界

- 原始 Excel 的字段定义把 `clustertype=0` 写为班级群聊、`1` 写为 1v1；1000 样本包含 `780` 个 type 0 窗口和 `220` 个 type 1 窗口。
- 产品业务说明是：当前老师和学生不能自行创建多人群，只能由创建班级产生班级群。
- 数据知识说明底层 `Type=0` 结构理论上能够承载普通多人群，因此**产品能力事实不能代替实际数据核验**。
- 本轮已全量验证 780 个 type 0 样本：全部且唯一关联课程，因此在**当前固定样本和数据快照内**可写为 `course_group`；这不改写底层类型的永久语义。
- 当前成员表通常是快照，不能无条件代表历史消息发送时的身份。必须保存查询快照时间，并用入群、退群或消息位点信息做可行范围内的时态检查。
- 机构职业身份与群内 `ClassIdentity` 是两套事实。判断“实际是老师还是学生”以机构关系为主，群内身份仅作群内角色和冲突证据。
- UID 在不同机构历史上或当前可能同时出现教师、学生关系。本轮只使用会话所锚定机构中的**当前有效身份**；其他机构和历史身份不参与该会话的职业身份判定。
- 加入他人创建的班级或自行创建班级只会产生班内角色，不会自动改写该 UID 在机构中的职业身份。两层不一致时保留冲突，不做覆盖。

## 3. 正交数据模型

### 3.1 会话结构快照 `ConversationStructureSnapshot`

每个 `clusterid` 一条，核心字段如下：

| 字段 | 取值或说明 |
|---|---|
| `conversation_form` | `course_group` / `direct_1v1` / `unsupported_type0_non_course` / `ambiguous` |
| `observed_type` | 原始 `clustertype`，只读 |
| `course_link_status` | `matched_once` / `not_matched` / `matched_multiple` / `not_applicable` |
| `course_id` | 唯一匹配时保存；标识符按字符串序列化 |
| `registered_role_composition` | `staff_only` / `staff_student` / `student_only` / `guardian_involved` / `mixed` / `unresolved` |
| `member_role_facts` | 每个有效成员的机构角色证据、群内角色、冲突和解析状态 |
| `direct_role_relation` | `teacher_teacher` / `teacher_student` / `teacher_guardian` / `student_student` / `other_or_unresolved` |
| `snapshot_at` | 数据库查询快照时间 |
| `warnings` | 非课程 type 0、多重课程关联、成员数异常、多角色冲突、时态不足等 |

### 3.2 窗口活跃发言角色构成 `ActiveSenderComposition`

每个 100 消息窗口一条，基于窗口内实际 `sourceuid` 及结构快照中的职业身份映射计算：

- `staff_only_active`；
- `staff_student_active`；
- `student_only_active`；
- `guardian_involved_active`；
- `single_sender_active`；
- `mixed_or_unresolved_active`。

完整成员为教师与学生的班级群，如果当前窗口只有老师发言，仍然是 `staff_student` 课程群，同时标记 `staff_only_active`。不得把活跃发送者构成反写成完整成员构成。

### 3.3 窗口沟通用途 `CommunicationPurposeAssessment`

只对结构与成员证据足以支持的教师内部窗口进行语义判断：

| 用途 | 定义 |
|---|---|
| `teaching_management_collaboration` | 围绕人员、课程、学员、考勤、服务、结算、规范或行政对象，存在分配、协调、确认、审批、督办、处置、交接等管理动作和方向性 |
| `teacher_internal_communication` | 教师之间的普通内部沟通，包含专业讨论、经验交流、互助、信息分享、关系维系及其他未形成管理动作链的交流 |
| `not_teacher_internal_window` | 完整语义足以证明本窗口是面向学生的授课/广播、非教学社群、个人记录或其他非教师内部交流；这是排除结果，不生成新的群类型 |
| `insufficient_evidence` | 只有寒暄、转发、短句、单向片段或身份/语义证据不足 |

这是窗口级派生判断，不等于群的永久属性。对同一群取得多时段窗口后，才能形成 `ConversationPurposeProfile`。

### 3.4 面向研究者的组合展示标签

底层仍保存正交字段，页面或统计可以按以下规则生成易读标签：

| 结构与角色条件 | 用途条件 | 展示标签 |
|---|---|---|
| `course_group + staff_only` | 多窗口语义证明存在持续管理动作 | 教师管理协作群 |
| `course_group + staff_only` | 未形成持续管理动作，且沟通证据充分 | 教师内部沟通群 |
| `course_group + staff_only` | 语义明确不属于教师内部交流 | 暂不生成教师群类型 |
| `course_group + staff_only` | 语义证据不足 | 暂不生成群类型 |
| `course_group + staff_student` | 不要求用途 | 师生班级群 |
| `course_group + student_only` | 不要求用途 | 学生成员班级群 |
| `direct_1v1` | `teacher_teacher` | 单聊：教师/管理者—教师/管理者 |
| `direct_1v1` | `teacher_student` | 单聊：教师—学生 |
| `direct_1v1` | `teacher_guardian` | 单聊：教师—家长/监护人 |
| `direct_1v1` | `student_student` | 单聊：学生—学生 |

“纯学生之间的私聊群”容易混淆群聊与 1v1，执行时拆成“学生成员班级群”和“学生—学生单聊”。展示标签是派生视图，不能覆盖组成它的原字段。

## 4. `type=0` 课程群数据门禁

### 4.1 核验范围

以 1000 样本中的全部 780 个 type 0 `clusterid` 为全集，不抽样。逐个执行：

1. 查询群主记录，确认 `Type`、群状态和创建时间；
2. 用 `clusterid` 关联课程标识；
3. 统计零匹配、唯一匹配和多重匹配；
4. 对唯一匹配项交叉核对课程状态及有效成员数量；
5. 对零匹配项再用底层发号来源、软删除状态和历史课程记录排查，禁止直接命名为“自建群”。

### 4.2 通过条件

- `type=0` 唯一课程匹配率必须是 `100%`，才可在**本数据版本和抽样范围内**锁定 `type=0 → course_group`；
- 任一零匹配或多重匹配都进入异常清单，保持 `unsupported_type0_non_course` 或 `ambiguous`，不得静默归入班级群；
- 即使 100% 通过，也只证明当前 2026 年 8 月样本，不把底层数据模型永久改写成“Type 0 只能是课程群”。

这一区分同时满足产品事实和数据事实：产品当前没有自建多人群入口，但仍用实际关联结果证明样本中是否存在历史、后台或异常数据。

### 4.3 对既有 Topic 结果的影响

既有语义提取曾按原始字段定义把 `clustertype=0` 投影为 `class_group`。如果本门禁 100% 通过，既有映射获得当前样本的数据支持；如果出现例外，不立即推翻全部 Topic，只优先复核：

- 例外会话的结构标签和用途结论；
- 依赖“班级公告/提醒”语义成立的少消息特殊业务 Topic；
- 任何把群容器类型写入 Topic 名称或分类理由的结果。

复核与修正必须走派生迁移层，原始 Topic 和证据不覆盖。

## 5. 成员职业身份解析

### 5.1 群聊

对每个有效成员 UID，分别保留：

1. 群内管理身份；
2. 群内课堂身份；
3. 机构教师/管理者有效关系；
4. 机构学生有效关系；
5. 家长/监护人关系（只有存在正式关系表证据时才可使用）；
6. 多角色冲突及解析理由。

成员查询以 `clusterid` 为入口读取群成员关系，不以窗口里的 `sourceuid` 清单为查询范围。因此没有在这 100 条消息中发言的成员也会进入完整成员集合；`sourceuid` 只用于之后计算“窗口活跃发言角色构成”和检查成员遗漏。

规则：

- 教师或管理者统一进入 `staff` 上位集合，但原始细分角色不丢失；
- 当前会话先锚定其课程所属机构，再读取 UID 在该机构中的当前有效身份；其他机构的当前或历史身份不参与本会话判定；
- 加入班级或创建班级只会形成班内角色，不自动改变机构教师/学生身份；班内 `ClassIdentity` 与机构身份必须并列保存；
- UID 在不同机构分别命中教师和学生关系时，以当前课程机构的关系为准；在同一机构仍同时命中两类有效关系时保留多角色冲突，不靠字段优先级猜测；
- 群内 `ClassIdentity=学生` 但当前课程机构教师关系有效时，会话职业身份仍为教师，同时记录 `group_role_profession_conflict`；反向情况同理；
- 退出成员不计入当前构成，但保留历史关系，以支持窗口时态核验。

### 5.2 1v1

必须先确认 `Type=1`、双方关系记录和恰好两个有效参与者，再判断：

- 双方均为教师/管理者：`teacher_teacher`；
- 一方教师、一方学生，并存在共同机构或课程锚点：`teacher_student`；
- 一方教师、一方有正式监护关系证据：`teacher_guardian`；
- 双方均为学生：`student_student`；
- 缺少正式家长关系时，不因昵称、称呼或学生账号代发而硬判家长，进入 `other_or_unresolved`。

## 6. 教师管理协作群与教师内部沟通群的精细识别

### 6.1 两阶段而非关键词匹配

第一阶段先判断“这个窗口是否满足教师内部沟通的结构条件”；第二阶段才用完整上下文、已识别 Topic 及其证据消息判断是否存在完整的管理动作链。关键词只能帮助定位证据，不能直接决定标签；任何“出现排课/考勤/薪酬词汇就算管理群”的实现都不合格。

### 6.2 教学管理群的动作—对象—方向模型

教学管理协作必须至少同时满足：

1. **管理对象**：课程、班级、学员、教师、排班、考勤、服务工单、课酬、规范、资源配置或行政事项；
2. **管理动作**：分配、调整、确认、通知、审批、督办、统计、交接、补位、处置、结算、执行规范；
3. **组织方向或状态变化**：存在明确责任方、上下游交接、截止要求、执行状态、异常处理或结果确认中的至少一项。

管理动作族：

- `schedule_attendance`：排课、调课、到课、缺勤、补课；
- `staffing_assignment_capacity`：教师分配、学员承接、课量和可用容量协调；
- `student_service_handoff`：学员服务、续课、投诉、跟进和跨角色衔接；
- `compensation_settlement`：课酬、费用、结算和核对；
- `rules_performance_personnel`：工作规范、质量要求、人员安排和绩效处置；
- `administrative_execution`：资料收集、系统操作、审批、报表和机构行政执行。

单纯出现“课、学生、老师、资料”等名词不成立；教师分享一份教案、讨论一道题、交流课堂技巧，也不因涉及教学对象而自动成为管理协作。

更重要的是，课程进度、教学方法、课堂体验和教学活动设计等 Topic 可以同时出现在两类教师群中。**Topic 回答讨论对象，群类型回答组织功能**，两者不能直接映射。判定时必须检查围绕该 Topic 的完整言语行为和后续结果：

| 相同讨论对象 | 教师管理协作语义 | 一般教师内部沟通语义 |
|---|---|---|
| 课程进度 | “本周落后两课时，王老师周五前补完并更新进度表”——有差距、责任人、期限和回写 | “这个单元节奏有点快，大家通常讲几节？”——交换经验，没有执行指令 |
| 教学方法 | “下周所有班统一采用分组练习，教研组长周四检查教案”——形成统一要求和检查动作 | “我试过分组练习，学生参与度更好”——分享方法和效果 |
| 课堂体验 | “近期反馈集中，请各班按模板整改并在群里确认”——问题处置、统一标准和结果确认 | “学生对这个互动环节反应不错，大家可以参考”——经验分享 |
| 教学活动设计 | “活动方案由李老师负责，明天定稿后分发各班执行”——任务分配、截止和落地 | “这个活动还能怎么设计得更有趣？”——开放式专业讨论 |

因此，模型不得因为 Topic 路径属于“课程运营”就自动判为管理群，也不得因为 Topic 路径属于“教学设计”就自动判为一般内部沟通。必须从完整消息链中识别是否留下“治理足迹”：统一规则、明确决策、责任分配、期限、审批、督办、状态追踪、异常处置或结果验收。

### 6.3 教师内部沟通判定

当窗口不满足管理动作—对象—方向模型，但教师内部交流语义充分时，统一判为 `teacher_internal_communication`。其中可以包含以下内容特征，但它们不再生成单独群类型：

- 解释或争论学科知识、题目答案、语言表达；
- 比较教材、课件、教学资源的专业适用性；
- 讨论教学方法、课堂活动、作业或测评设计；
- 复盘教学效果并探索改进方法；
- 教师之间请求或提供专业建议，而没有组织性的分配、督办或处置动作；
- 普通信息分享、同事互助、关系维系和内部闲聊。

若语义明确显示内容是教师面向学员的授课或单向广播，或课程群被用于投资、娱乐、个人记录等非教师内部交流，则使用 `not_teacher_internal_window` 排除；不得把“只有教师型班内角色发言”直接翻译为“教师内部群”。仅在无法分清内部交流与单向片段时才使用 `insufficient_evidence`。

同一窗口同时含一般内部交流和管理事项时，只要管理事项形成了独立 Topic 或符合少消息特殊业务规则，并且动作—对象—方向三项成立，窗口仍记为 `teaching_management_collaboration`；一般交流作为 Topic 保留，不再增加“混合群”类型。

### 6.4 Topic 的使用方式

- Topic 路径是语义证据和召回入口，不是用途标签的一对一映射；
- 所有 Topic 路径都只能帮助定位相关消息，不能为群类型提供直接分值；
- 无论 Topic 属于课程运营、教学设计、学科内容、测评还是日常交流，都必须重新检查管理动作、组织方向和状态变化；
- 每条用途结果必须保存 `topic_instance_ids`、`evidence_message_ids` 和简短理由，确保可逆复核。

### 6.5 从窗口到群实体画像

当前 1000 样本若每个 `clusterid` 只出现一个窗口，只产出窗口用途信号，不直接产出永久群类型。后续为教师内部群补取多个不重叠时段窗口，并按以下规则聚合：

- 至少 2 个具有充分证据的窗口；
- 在至少 2 个独立窗口中反复出现符合三要素的管理事项，或管理窗口占充分证据窗口 `≥30%` 且不少于 2 个，形成持续“治理足迹”，判为“教师管理协作群”；
- 不达到上述管理条件、但教师内部沟通证据充分，判为“教师内部沟通群”；
- 证据不足时不生成群类型，不用“混合/待定”冒充有效类型；
- 所有画像都保留时间覆盖和所依赖的窗口列表。

### 6.6 证据强度与置信度

- `high`：动作—对象—方向三项清晰，至少有两个相互支持的语义片段，或一个带明确责任/截止/状态变化的完整管理事项，且相邻类别无冲突；
- `medium_high`：三项成立但证据集中在一个主题，或一般教师内部沟通目的清晰但参与互动较少；
- `medium`：主要用途可判断，但部分依赖称呼、上下游关系或缺失上下文；
- `low`：只能通过词汇或弱推断成立。此时不得强行输出管理/专业类别，应优先选择 `insufficient_evidence` 并进入复核队列。

Topic 的常规 5% 证据门槛继续有效。少消息公告或提醒如果已经以 `special_business` 通过 Topic 规则，可以成为管理证据；但单条指令只证明该窗口出现一次管理行为，不能单独证明整个群的长期用途。

### 6.7 16 会话人工 Gate 后的单发送者约束

2026-09-03 的 16 会话人工复核确认了 8/9 个管理协作候选和 2/2 个证据不足拒判，同时暴露了单发送者窗口最容易混淆“当前内容用途”和“群实体类型”。后续执行增加以下约束：

- 单发送者只描述证据形态，不直接决定用途；
- 单向管理广播若要判为管理协作，除动作—对象—方向三项外，还必须能从完整消息或结构事实确认接收方和组织语境；
- 单向题解、教材、课程文案或资料清单可以支持“当前窗口并非教师内部协作”，但不能单独定义群实体类型；
- 系统原结论为 `insufficient_evidence` 时，人工选择“暂时无法判断”记为“确认拒判”，而不是模型错误；
- 按钮选择与文字备注冲突时不自动推断用户真实意图，该记录从确认校准集排除；
- 所有人工 Gate 通过独立字段并列保存，不覆盖系统原裁定和消息证据。

完整复核结果见 [教师沟通用途 16 会话人工复核与校准结论](./HUMAN-REVIEW-16-PURPOSE-CALIBRATION-20260903.md)。

## 7. 执行流程

### Phase 0：范围冻结与不变性

1. 锁定原始工作簿、manifest、1000 窗口和 v2.3 Topic 文件的哈希；
2. 导出 1000 窗口的唯一 `clusterid`、类型、消息时间范围和活跃发送者；
3. 不覆盖任何原始消息、Topic 或人工裁决。

完成条件：窗口数、消息数、type 分布和来源哈希全部通过。

### Phase 1：结构事实核验

1. 全量验证 type 0 课程关联；
2. 读取群/单聊有效成员；
3. 解析机构职业身份和群内身份冲突；
4. 生成 `ConversationStructureSnapshot` 和异常清单。

完成条件：780 个 type 0 全覆盖，220 个 type 1 双方关系完整率可量化，所有异常显式列出。

### Phase 2：窗口角色投影

1. 把 1000 窗口的 `sourceuid` 映射到成员职业身份；
2. 生成活跃发言角色构成、单发言者和身份冲突切片；
3. 结构事实与窗口事实并列保存。

完成条件：无法解析发送者率、职业身份冲突率和单向窗口率均有报告。

### Phase 3：教师内部沟通用途语义判断

1. 为防止把“窗口只有教师发言”误当成“完整成员只有教师”，先召回全部教师型账号独占发言窗口，其中允许保留 `staff_student` 作为结构负例；
2. 只有完整注册成员或可靠时态成员构成为 `staff_only` 的窗口，才进入教师内部用途正向判定；`staff_student` 无论窗口内谁发言，仍保持师生班级群；
3. 输入完整窗口、v2.3 Topic、Topic 证据和结构快照；
4. 按动作—对象—方向模型输出“管理协作 / 教师内部沟通 / 明确非教师内部窗口 / 证据不足”四种窗口结果；
5. 低置信度和混合案例进入专项复核队列。

完成条件：每个结论都可回到 Topic 和消息 ID；不存在关键词直接映射；用途证据不足时允许拒判。

### Phase 4：质量评估与实体聚合

1. 分层抽查结构异常、管理/专业边界、低置信度和 Topic—用途冲突；
2. 具备同群多窗口时再形成实体画像；
3. 输出结构 × 角色 × 用途 × Topic 的交叉统计，但保留重叠口径说明。

完成条件：结构事实准确率与语义用途审阅一致性分别报告，不合成一个虚假的总体准确率。

## 8. QA 与停止条件

以下任一情况出现即停止扩大执行范围：

- type 0 课程关联出现无法解释的零匹配或多重匹配；
- 群有效成员数、课程成员数和消息发送者之间存在系统性不一致；
- 机构身份关系无法按消息时点对齐，且可能显著改变教师/学生判定；
- 1v1 缺少双向关系或两位参与者；
- 教师管理协作与一般教师内部沟通的证据边界无法在抽查中稳定复现；
- 当前 Topic 证据消息与原始窗口不一致。

质量报告至少包含：覆盖率、拒判率、异常率、角色冲突率、type 0 课程匹配率、1v1 双方解析率、窗口用途分布，以及每项指标的分母。
