# 九章龙虾（NineClaw）产品设计与交互研究

## 0. 结论摘要

九章龙虾不是把若干 AI 小工具排列在一个页面里，而是一个以“新建任务”为统一入口、以持续对话承载执行过程、以本地文件/生成物承接结果的教师桌面 Agent 工作台。录屏中最稳定的产品闭环是：**教师表达目标 → Agent 识别缺失变量并结构化补参 → 形成计划并调用 Skill/工具/MCP → 持续显示执行状态 → 生成右侧可预览的产物 → 教师验证、AI 修改或直接编辑 → 保存**。【UI-E1】

它的外围模块不是彼此孤立的频道：技能广场扩展“怎么做”，工具广场/MCP 扩展“能访问什么”，内容广场把既有作品变成任务上下文，定时任务把同一套任务能力变成事件触发，模型、沙箱、IM、云端备份等设置构成运行配置。由此可推断，产品的中心对象是“任务及其产物”，而不是某一个工具页面。【UI-E1】【INF】

对 ClassIn WorkBuddy 最值得迁移的是统一目标入口、结构化补参、长任务可见性、产物右侧验证与迭代、历史/工作目录连续性，以及“内容 → 改编任务”的回流。最不应照搬的是把 Skill、MCP、模型、原始命令、绝对路径、环境变量和大段 JSON 暴露给普通教师，以及在缺少正式业务对象、审批、Diff 和执行回执时把“聊天完成”当成业务闭环。【UI-E1】【INF】

对当前运行时 23 个 Skill 的源码复核进一步确认：NineClaw 的 Skill 不是同一种实现。它们至少分为提示/知识工作流、本地确定性脚本、远端服务适配器和 Skill 供给/维护工具四类；一个教师任务通常由主 Agent 编排多个 Skill 与通用工具完成，而不是由单个 Skill 封闭实现。源码能够扎实佐证录屏中的核心教师能力，但“目录中存在 Skill”仍不等于已完成端到端运行、质量评估或机构级治理。【SRC-E4】【INF】

- 将动态录屏与同名静态截图交叉核对；动态行为优先于单张截图，截图用于补齐表单字段、状态与低频页面。
- 沿 `/Users/eeo/nineclaw/我的文件/.claude/skills` 的 23 个有效符号链接读取当前运行时 Skill；逐个完整读取 `SKILL.md`，并复核必要的 `references/`、`assets/`、`scripts/`、依赖清单与评价材料。工作区链接均指向 `/Users/eeo/Library/Application Support/NineClaw/SKILLs/<skill-id>`，因此“应用级安装副本 → 工作区挂载 → Agent 发现”的结构获得了当前目录实证。【SRC-E4】
- 以“UI 已观察且源码佐证 / 源码存在但 UI 未覆盖 / 只有说明或依赖、未证明稳定运行 / UI 出现但当前目录未安装”四类交叉验证功能。只执行本地静态语法检查，不调用带 Token 的远端服务，也不把私有数据作为测试输入。

## 2. 产品定位与边界

### 2.1 产品自我定位

介绍页将 NineClaw 定义为“专为老师打造的桌面超级智能体”，并用“从备课素材到课后学情，在一个工作台持续推进”“从一句教学目标，到完整课堂素材”等文案强调目标驱动、跨步骤和持续工作。【MKT-E2】

录屏实际支持的定位是：

1. **教师桌面任务工作台**：所有主要能力最终汇入“新建任务”和任务历史，而非要求教师先选一个独立工具完成一次性操作。【UI-E1】
2. **长任务执行与产物工作区**：Agent 会补参、计划、运行命令或工具、生成文件，并在同一任务里继续修改和保存。【UI-E1】
3. **能力与内容分发容器**：Skill、MCP 工具和内容作品可以安装、解锁或改编，再回到任务执行。【UI-E1】
4. **本地桌面壳**：工作目录、“我的文件”、本地标识、模型和沙箱设置都围绕桌面环境呈现。【UI-E1】

介绍页还用“本地运行 / 沙箱隔离 / 三层记忆 / 隐私优先”作为产品徽标，并将三层记忆解释为：记录教材版本、表达风格和长期偏好的陈述性记忆；从历史对话与产物中找回上下文的情境记忆；沉淀可复用流程的程序性记忆/Skill 管理。它还演示读取 PDF/XLSX、调用试卷诊断与成绩分析能力、输出 PPTX/DOCX/XLSX 等文件。这些均是介绍页的产品主张或演示，不能单独证明真实数据边界、记忆治理或沙箱隔离强度。【MKT-E2】

### 2.2 已观察到的边界

- 已覆盖：备课/教案、课后练习、教学动画、互动 HTML、PPT/文档等生成任务，文件读取与写入，Skill 与 MCP 扩展，内容发布/解锁/改编，定时执行，模型/IM/沙箱等配置。【UI-E1】
- 未观察到：与 ClassIn 课程、班级、课堂、学生、作业、消息等正式领域对象的绑定；面向这些对象的差异预览、教师审批、写回、回滚和执行回执；机构级 Skill 签名、版本审批与租户权限治理。【UI-E1】
- 因此，录屏证明的是通用教师生产力 Agent 和本地资产闭环，不能证明已经形成 ClassIn 业务系统闭环。【INF】

## 3. 关键用户、任务与价值链

| 用户/角色 | 录屏中的主要目标 | 代表任务 |
|---|---|---|
| 一线教师 | 从自然语言目标快速得到可用教学材料 | 智能教案、课后练习、教学动画、智能作业、逐字稿 |
| 教学内容创作者 | 生产、修改、发布和复用作品 | 内容广场发布四步、设置定价、提交审核、一键改编同款 |
| 能力配置者/高级用户 | 安装或创建 Skill，连接 MCP，选择模型与运行环境 | Skill 安装/上传/创建、自定义工具 JSON、模型/API 配置 |
| 有周期性工作的教师 | 让任务按计划重复运行并接收通知 | 创建定时任务、立即运行、查看历史、配置 IM 通知 |

主价值链可概括为：

```text
教学目标/文件/已有作品
        ↓
任务（缺失变量补齐、计划、执行、可中途修订约束）
        ↓
Skill（业务方法） + Tool/MCP（外部访问/原子能力） + Model
        ↓
Artifact（DOCX/PPTX/XLSX/HTML 等）
        ↓
预览/解析答案/编辑/AI 修改/保存
        ↓
本地文件、内容发布，或后续定时任务
```

该图是对已观察交互的归纳，不代表产品公开的数据模型或后台架构。【UI-E1】【INF】

## 4. 全局信息架构

### 4.1 固定应用壳

左侧固定导航从上到下包括：【UI-E1】

- 主行动：`新建任务`；
- 能力与内容：`技能广场`、`工具广场`、`内容广场`、`定时任务`；
- 任务连续性：历史任务区、搜索/列表控制、最近任务条目；
- 资产连续性：`我的文件`与文件数量；
- 系统与商业化：`设置`、会员推广卡、积分余额。

侧栏可收起为窄图标模式。主区域顶部显示当前任务标题、`本地`标识、工作目录和更多菜单；右上角显示用户头像/名称。【UI-E1】

### 4.2 首页/新建任务

首页中心是“Hi，有什么需要我帮忙的吗”的大输入区，而不是跨任务仪表盘。输入支持自然语言、文件/文件夹、附件、Skill 选择、模型选择和发送；快捷入口包括生成智能教案、教学动画、课后练习、逐字稿。工作目录选择器包含“添加文件夹”和“最近使用”。【UI-E1】

Skill 选择器可见 Word 文档、网页设计、文件上传、PDF 文档、PPT 演示文稿、学科专家等，并可进入技能广场；模型选择器支持默认模型和自定义模型设置。【UI-E1】

### 4.3 信息架构关系

| 一级模块 | 直接管理的对象 | 如何回到任务中心 |
|---|---|---|
| 新建任务/历史 | 目标、对话、计划、执行状态、文件产物 | 本身就是中心工作区 |
| 技能广场 | Skill 的发现、安装、启用、创建、删除 | “去使用/立即使用”新建带 Skill 上下文的任务 |
| 工具广场 | MCP/工具的安装、启用、自定义配置 | 任务执行时调用并显示请求/响应 |
| 内容广场 | 作品、解锁、收藏、发布、审核状态 | “一键改编同款”自动带入作品和提示词进入任务 |
| 定时任务 | 提示词、计划、工作目录、通知、运行历史 | 把任务定义变为时间触发执行 |
| 我的文件 | 工作目录和生成物 | 作为任务输入与产物落点 |
| 设置 | 模型、备份、IM、沙箱、应用信息、反馈 | 提供运行和通知配置 |

#### 5.2.1 当前运行时 Skill 的实现形态

2026-08-20 的教师工作区挂载了 23 个有效 Skill。排除 `node_modules` 和 Office OOXML 标准 schema 后，本次仍复核了 207 个分析范围文件，包括 4,557 行 `SKILL.md`、57 个 JavaScript/Python 等代码文件、74 个参考资料、8 个模板/资产文件和 10 个 eval/autoresearch 文件。23 个入口定义均来自应用级运行时目录的同名符号链接，而不是复制到工作区的独立版本。【SRC-E4】

| 主实现形态 | 数量 | Skill | 能证明到什么程度 |
|---|---:|---|---|
| 提示/知识/模板工作流 | 9 | `brainstorming`、`frontend-design`、`homework-generator`、`infographic`、`physics-solver`、`subject-expert`、`teacher-lesson-plan-assistant`、`teaching-plan-generator`、`teaching-transcript-generator` | 已把触发条件、补参、领域规则、产物结构和质量要求编码为 Agent 指令；不能据此证明确定性执行或稳定产物 |
| 本地确定性脚本/文件工具 | 6 | `docx`、`grade-analysis`、`learning-report-generator`、`pdf`、`pptx`、`xlsx` | 具有本地解析、计算、模板组装、文件读写或格式验证路径；真实可用仍取决于依赖、输入质量和 Agent 编排 |
| 远端服务/存储适配器 | 6 | `geometry-solver`、`oss-image-upload`、`paper-diagnosis`、`seedance-video-generator`、`single-page-creator`、`vision` | 本地代码主要负责鉴权、上传、请求、轮询/SSE、解析和落盘；核心识别或生成质量依赖远端服务，其中试卷诊断还组合了本地报告生成 |
| Skill 供给与维护工具 | 2 | `find-skills`、`skill-creator` | 支持发现、安装、创建、评测和迭代 Skill；同时扩大第三方供应链和自修改治理范围 |

这四类是“主实现形态”，不是互斥的技术边界。例如智能教案以提示/参考资料定义教学工作流，再依赖通用 DOCX 能力导出；试卷诊断以远端 API 识别和分析，再由本地模板生成 HTML；PPTX 则同时包含长指令、脚本、依赖和验证工具。因此 NineClaw 的真实复用单元更接近“Agent 可编排能力包”，而不是传统意义上的单一后端服务或前端 Feature。【SRC-E4】【INF】

## 6. 核心交互模式

### 6.1 模式 A：先结构化补参，再执行

智能教案和课后练习均不是收到一句话后直接生成。Agent 先识别教材版本、年级、内容范围、题型/数量、输出偏好等缺失变量，再用“需要您的确认”多步选择器补齐。选择器具有步骤点、单选项、“其他”文本输入和提交动作。【UI-E1】

这一模式的意义不只是“追问”：它把隐含需求变为可检查的任务约束，避免 Agent 在长任务完成后才暴露关键假设。【INF】

### 6.2 模式 B：计划与执行状态可见

任务内部可看到计划文本、`TaskCreate`、`TaskUpdate`、工具调用、文件读写和命令轨迹；运行时输入区显示执行中和停止按钮。教师能够判断“正在做什么”和“是否卡住”，但界面同时泄露了大量实现细节。【UI-E1】

适合迁移的是步骤、状态、来源、风险和可恢复错误；不适合迁移的是原始 shell、绝对路径、环境变量、完整 JSON 和内部工具名。【INF】

### 6.3 模式 C：运行中可修订约束

使用 PPT Skill 生成智能作业的录屏中，教师中途明确改口“不用制作 PPT，直接是 HTML 的格式可以”，Agent 随即调整产物策略并完成可预览的互动练习。Skill 因而更像可被任务约束调用的方法，而不是锁死的固定流程。【UI-E1】【INF】

### 6.4 模式 D：生成后可验证、可修改、可保存

教学动画、智能教案、课后练习和智能作业都把生成物从对话消息提升为右侧独立预览。课后练习还支持解析/答案切换、编辑模式、块级文本工具栏和 `AI 修改`；保存成功有明确反馈。教学动画同样支持预览、AI 修改和保存。【UI-E1】

这形成“产物不是终点，教师验收才是终点”的闭环，也是九章龙虾比一次性 AI 工具更接近工作台的关键证据。【INF】

### 6.5 模式 E：内容与能力回流任务

- Skill 详情中的“去使用”创建任务；
- 内容详情中的“一键改编同款”创建带引用和预填提示词的任务；
- 定时任务将提示词、工作目录和通知变为按计划运行；
- MCP 在任务中提供原始数据，Agent 再归纳成人类可读结果。【UI-E1】

因此各广场的核心价值不是浏览本身，而是为任务供给方法、接口或起始资产。【INF】

## 7. 逐条端到端操作链路与状态

### 7.1 生成教学动画

1. 教师从新建任务/快捷入口提出教学动画目标；
2. Agent 展开计划并创建/更新任务步骤；
3. 读取相关 Skill、素材或文件并执行生成命令；
4. 过程中展示运行状态、命令和文件轨迹；
5. 生成 HTML 教学动画/互动故事并给出文件链接；
6. 教师打开右侧预览检查；
7. 教师用自然语言要求调整内容，Agent 更新产物；
8. 教师保存，界面提供成功反馈。【UI-E1】

主要状态：已提交、规划中、执行中、文件生成、可预览、修改中、已保存。未观察到正式版本 Diff 或回滚。【UI-E1】

源码交叉验证：`single-page-creator` 的本地脚本会携带会话信息调用教学动画 SSE 接口，累积流式内容，从响应中截取完整 HTML 并写入临时文件；`geometry-solver` 使用同类链路，但默认只输出进度点，避免把整段 HTML 污染执行转录。Skill 本身止于“得到本地 HTML 路径”，右侧预览、AI 修改和保存仍由任务工作台与主 Agent 承接。这佐证了“Skill 生成产物、Task 管理完整闭环”的分层，也解释了不同 Skill 在会话中技术噪声多少不一致。【SRC-E4】【INF】

### 7.2 生成智能教案

1. 教师表达课程主题/教案目标；
2. Agent 判断教材版本、年级、课型或格式等信息不足；
3. 弹出“需要您的确认”多步选择器；
4. 教师逐步选择或补充其他选项并提交；
5. Agent 形成计划，调用教案/文档相关能力；
6. 生成 DOCX 等文件；
7. 在右侧预览中复核并继续编辑或 AI 修改；
8. 保存。【UI-E1】

源码交叉验证：智能教案 Skill 把必要输入、12 个内容模块、学科差异、参考资料和质量检查写成业务工作流，并强制要求最终导出 DOCX；但其目录没有独立导出脚本，实际文件生成需要主 Agent 继续组合通用 `docx` Skill/文件工具。这说明“智能教案”是业务方法层，“Word 文档”是产物工具层，录屏中的完整体验来自编排而非单 Skill 单体实现。【SRC-E4】【INF】

### 7.3 生成课后练习

1. 教师提出学科、主题和练习目标；
2. Agent 识别年级、教材版本、题型、题量等缺失变量；
3. 通过多步确认组件结构化补齐；
4. 形成并执行生成计划；
5. 生成含题目与答案解析的文档；
6. 右侧预览可切换解析/答案；
7. 教师进入编辑模式，使用块级工具栏或 `AI 修改`；
8. 保存并收到成功反馈。【UI-E1】

源码交叉验证：课后练习 Skill 明确要求按优先级补齐学科/年级、知识点、题型、题量、难度和答案解析，且建议每次只追问 1–2 个关键缺失项；它还包含题型、难度、学科规范和完整样例等参考资产。其主实现是 Agent 指令与知识包，没有确定性出题脚本，因此录屏里的结构化确认组件、Task 状态和右侧编辑器属于工作台/Harness 对 Skill 工作流的产品化承载。【SRC-E4】【INF】

### 7.4 生成智能作业并改变输出格式

1. 教师要求使用 PPT Skill 生成作业；
2. Agent 读取 Skill/参考文件，创建计划并检查依赖；
3. 长时间执行中暴露命令、路径、环境检查及部分限制；
4. 教师中途把输出约束从 PPT 改为 HTML；
5. Agent 更新策略而非重新开任务；
6. 生成互动 HTML 练习并在右侧预览；
7. 教师继续验证或修改。【UI-E1】

该链路同时证明了运行中约束修订的价值，以及工具环境不稳定时输出格式可能被替代的风险。【INF】

源码交叉验证：PPTX Skill 是当前资产中最深的工具包之一，包含 HTML→PPTX、OOXML 解包/回包、模板盘点、文本替换、缩略图和格式校验等脚本及本地依赖；因此录屏中的 PPT 路径有实质工具基础。教师中途改为 HTML 反映的是 Run 级目标可修订，并不等于 PPTX Skill 只是一段说明；但该次录屏也没有完成一个可验收 PPTX，不能据源码替录屏补写成功结果。【UI-E1】【SRC-E4】

### 7.5 调用已安装 MCP

1. 教师要求使用已安装 MCP 查询指定年级/学期的数学题；
2. Agent 发出一到多次 MCP 请求；
3. 会话直接显示查询参数和大段原始 JSON；
4. Agent 在工具结果之后整理出教师可读的题目列表；
5. 教师可继续追问或调整条件。【UI-E1】

这里应保留“调用了什么、来源是什么、是否成功”的可追溯性，但底层请求体和原始响应默认应折叠。【INF】

### 7.6 Skill 安装、使用、上传与创建

1. 在技能广场搜索或浏览 Skill；
2. 打开详情，查看说明、场景、核心功能和示例；
3. 点击安装，卡片变为已安装；
4. 点击“去使用/立即使用”，进入新任务；
5. 另一条路径从“添加技能”上传本地技能包；
6. 也可让 Agent 创建 Skill，过程中写入 Skill 定义文件；
7. 新 Skill 出现在“我的技能”，可启用、使用或删除；
8. 高影响动作会出现用户确认分支。【UI-E1】

当前工作区证实安装后的 Skill 以符号链接挂载，`find-skills` 定义了从外部 Skill 生态搜索/安装的流程，`skill-creator` 则包含创建、评价、基准比较和迭代脚本。它们为录屏中的“发现—安装—创建—再次使用”提供了实现侧佐证；但自然语言确认、目录校验和少量 eval 不能替代来源签名、机构审批、最小权限与运行时审计。【SRC-E4】【INF】

### 7.7 内容发现、解锁、改编与发布

发现/改编链：广场筛选 → 作品详情与预览 → 下载/积分解锁 → 一键改编同款 → 自动跳转新任务并带入引用和提示词 → 继续生成。【UI-E1】

发布链：

1. **上传文件**：拖拽或文件选择；出现上传中、失败、重试/重新选择和成功状态；
2. **完善信息**：标题、简介、学科、教材版本、年级、类型/语言标签、封面等；
3. **设置定价**：免费或积分价格；
4. **提交审核**：复核摘要并提交，之后进入审核状态管理。【UI-E1】

录屏出现上传失败后重试以及预览生成加载，说明失败不是旁路提示，而是发布流程中的正式状态。【UI-E1】

### 7.8 定时任务

1. 从空状态点击新建；
2. 填写标题、提示词、重复计划、日期时间、工作目录、到期时间和可选通知；
3. 保存后任务出现在列表并可启停；
4. 更多菜单支持立即运行、编辑、删除；
5. 立即运行后显示提示和运行中状态；
6. 在历史标签查看执行时间与状态。【UI-E1】

## 10. Skill、MCP、模型与任务的产品关系

- **Task** 是教师可见的目标和状态容器；教师可以在运行中改变约束。【UI-E1】
- **Skill** 是某类工作的可复用方法/提示与资源包；可发现、安装、启用、创建，并以“去使用”进入任务。【UI-E1】【INF】
- **Tool/MCP** 是外部数据或原子动作入口；任务中以请求/响应方式被调用，不等同于完整教学工作流。【UI-E1】【INF】
- **Model** 是运行配置，可在输入器或设置中选择，不应被解释为产品业务模块。【UI-E1】【INF】
- **Scheduled Task** 复用提示词、目录和通知，把人工发起任务变为时间触发。【UI-E1】【INF】
- **Content Work** 是可解锁、下载、发布和再次改编的资产；“一键改编”把内容重新变成任务输入。【UI-E1】【INF】

当前源码快照把 Skill 一侧的关系补充为：【SRC-E4】【INF】

```text
教师目标 / 当前文件 / 任务上下文
        ↓ 主 Agent 选择或显式挂载
SKILL.md（触发描述 + 工作步骤 + 质量规则）
        ├─ references / assets：按需加载的领域知识、示例和模板
        ├─ scripts：本地解析、组装、验证或远端服务适配
        └─ 通用 Skill：DOCX / PPTX / PDF / XLSX / Vision / Upload 等
        ↓
文件路径、HTML、结构化 JSON 或文本结果
        ↓ 任务工作台承接
预览 / 继续修改 / 保存 / 后续复用
```

这说明 `TaskCreate`/`TaskUpdate`、结构化补参、运行轨迹和右侧产物不是每个业务 Skill 重复实现的 UI，而是主 Agent/Harness 提供的共性编排与呈现；Skill 主要编码“何时触发、如何完成、参考什么、调用什么、产出什么”。同时，现有 frontmatter 主要依赖自然语言 `description` 路由，正文中的输入输出也以说明为主，尚未形成机器可校验的权限、数据等级、副作用和 Artifact 契约。【UI-E1】【SRC-E4】【INF】

源码仍没有证明 MCP 权限如何隔离、模型如何路由、定时任务如何持久化或内容审核如何实现；这些问题应交由架构材料和后续工程验证，而不是从 UI 或 Skill 目录反推。

## 11. 体验规律、优势与风险

### 11.1 已形成的体验优势

1. **目标优先**：教师可直接说要什么，快捷入口只是加速而非强制分类。【UI-E1】
2. **结构化补参**：把关键教学变量显式化，减少隐藏假设。【UI-E1】
3. **长任务可见**：计划、步骤、运行状态、停止动作让生成不再是黑盒等待。【UI-E1】
4. **产物可验收**：右侧预览、答案解析、编辑、AI 修改和保存把生成与验收连成闭环。【UI-E1】
5. **任务可调整**：运行中可改变输出格式，Skill 不锁死目标。【UI-E1】
6. **资产连续性**：历史任务、工作目录、我的文件和内容改编支持跨轮次继续工作。【UI-E1】
7. **能力供给闭环**：Skill、MCP、内容和定时任务都能回流统一任务工作区。【UI-E1】【INF】

### 11.2 体验和安全风险

1. **技术噪声过载**：命令、绝对路径、环境检查、内部工具名和大段 JSON 占据会话，普通教师难以判断业务进度。【UI-E1】
2. **敏感信息暴露面**：自定义 MCP 配置展示环境变量，执行轨迹可能暴露本地路径、参数与外部响应；录屏无法证明其脱敏或访问控制。【UI-E1】
3. **聊天承载过多状态**：计划、审批、错误、工具结果和产物入口仍大量混在转录流里，缺少独立的任务状态面板。【UI-E1】
4. **审批不是业务审批**：观察到的确认主要用于补参或高影响交互，没有看到 ProposedAction、Diff、教师审批与 ExecutionReceipt 的正式链路。【UI-E1】
5. **能力供应链治理不清**：允许上传/创建/安装 Skill 和自定义 MCP，但材料未展示签名、版本批准、机构白名单、权限声明和审计。【UI-E1】
6. **输出契约可能漂移**：工具/环境限制或教师改口会改变 PPT/HTML 等产物格式；灵活性与可预测性交织。【UI-E1】
7. **首页仍偏聊天**：没有观察到跨任务待办、阻塞、待审批、近期产物和自动化结果的工作台总览。【UI-E1】
8. **商业化打断**：积分和会员入口在首页/侧栏较显著，未必适合 ClassIn 的机构教师工作语境。【UI-E1】【INF】
9. **远端数据边界不够显式**：教学动画、几何、视觉理解、试卷诊断、视频和 OSS 上传会把输入或素材发送到远端；Skill 说明没有统一的数据分类、最小化、保留期、家长/学生信息处理或教师审批契约。【SRC-E4】【INF】
10. **错误链可能泄露凭据**：视频生成适配器在远端请求失败时会把完整请求 headers 拼入异常文本，其中包含客户端 Token；这是源码可见的具体风险，不再只是由 UI 推测的“可能暴露”。【SRC-E4】
11. **运行环境词汇漂移**：信息图 Skill 仍引用另一 Agent 生态的 `clarify`、`write_file`、`image_generate` 工具名，教师教学 Skill 则混用 `TodoWrite` 等运行时词汇；资产已安装不代表当前 Harness 能无适配执行所有步骤。【SRC-E4】
12. **触发冲突与能力抢占**：多个 Skill 使用“必须触发”和宽泛关键词，学科专家、几何、教学动画、物理可视化等边界存在重叠；只有自然语言 description 而缺少结构化路由策略时，稳定选 Skill 仍依赖模型判断。【SRC-E4】【INF】
13. **动态 HTML 不是可信产物**：教学动画和几何适配器直接从模型/SSE 响应截取 HTML 后落盘，本地 Skill 中没有发现统一的 sanitization、CSP、网络白名单或 iframe sandbox 契约。【SRC-E4】
14. **报告模板存在注入边界**：试卷诊断与学习报告把生成数据直接嵌入 `application/json` script 标签，没有像成绩分析器那样处理 `</script>` 边界；意外或恶意文本可能逃逸数据块。这是静态风险，未做攻击复现。【SRC-E4】【INF】
15. **依赖与发布完整性不足**：作业、试卷讲解和头脑风暴分别引用当前未挂载的 `geogebra`、`tutor`、`superpowers:*` 等能力；智能教案还残留旧开发机绝对路径。包可被发现不等于依赖闭合或发布清洁。【SRC-E4】
16. **Shell 参数拼接风险**：视频生成脚本把本地素材路径和下载 URL 拼入 shell 命令；若输入未经过严格转义，可能形成命令注入面。这是代码审计风险，未执行利用测试。【SRC-E4】【INF】

## 12. 与九章爱学的关系

用户提供的研究前提是：九章爱学是面向教师的散点 AI 工具集合，九章龙虾是以任务和目标为导向的 Agent 伴侣/工作台。该前提与可见体验基本一致，但仍需区分证据层级。

### 12.1 可见事实

- NineClaw 介绍/下载页面位于九章爱学教师 Web 产品壳内；同一壳内可见 AI 应用、资源、作业等导航和多个单点 AI 能力入口。【UI-E1】
- NineClaw 以独立桌面应用运行，拥有新建任务、历史、本地文件、Skill、工具、内容、定时任务和设置等持续工作区。【UI-E1】

### 12.2 关系推断

九章爱学更像“能力与资源入口”，决定教师可以单点使用什么；九章龙虾更像“任务编排与产物工作台”，把多个能力串入一个持续任务。二者在产品家族和入口上相邻，但材料不足以证明它们共享后台、业务对象或数据权限。【INF】

## 13. 对 ClassIn WorkBuddy 的迁移启示

### 13.1 可以直接吸收的事实启示

- 保持一个统一的教师主 Agent 入口，教师描述目标而非选择内部 Agent；
- 把“缺失变量检测 → 结构化补参”做成正式任务状态；
- 将计划、执行、暂停、失败恢复和完成标准从聊天文本提升为结构化 UI；
- 让 Artifact 与 Task 并列成为一等对象，提供右侧预览、来源、版本、编辑、AI 修改和保存；
- 支持任务运行中修订约束，但记录约束变化及其对产物的影响；
- 将 Skill/Tool/MCP 留作能力层，由主 Agent 在策略边界内选择；教师只在必要时看到解释；
- 将“内容/模板 → 一键改编任务”作为复用教学资产的核心桥梁；
- 将定时、IM、ClassIn 事件统一视作任务触发渠道；
- 保留有用的可追溯性：步骤、输入来源、工具类型、成功/失败、风险和输出，不默认展开原始实现细节。

这些是研究建议，不自动升级为项目 `LOCKED` 决策。【INF】

后续 ClassIn 在评估“某个 AI 能力是否已经实现”时，不应使用单一的已安装复选框，而应至少记录以下五级证据：【SRC-E4】【INF】

| 级别 | 判断条件 | 本次 NineClaw 研究中的对应证据 |
|---|---|---|
| L0 能力声明 | 有名称、触发描述、适用场景 | `SKILL.md` frontmatter 与正文 |
| L1 方法资产 | 有完整工作流、Domain Knowledge、模板、样例与质量规则 | 教案、作业、学科专家、逐字稿等 |
| L2 执行实现 | 有可解析脚本、依赖和输入/输出路径，或明确的受控远端 Adapter | 成绩分析、本地报告、Office 工具、SSE/API 适配器 |
| L3 产品闭环 | 真实任务中完成补参、执行、产物预览、修改和保存 | 本次相应端到端录屏 |
| L4 生产治理 | 有数据分级、权限、副作用审批、版本/签名、eval、观测、恢复和审计 | 本次材料尚未证明 |

ClassIn 的能力矩阵应同时标记这五级，而不是把 L0/L1 误写成 L3/L4。这样产品复刻、架构设计和工程排期会共用同一套“实现程度”语言。

### 13.2 不可直接照搬

- 不把 Skill、MCP、模型选择放在普通教师的核心导航或默认输入面板中；
- 不直接展示 shell、绝对路径、环境变量、密钥字段和原始 JSON；
- 不允许教师任意安装/上传/删除 Skill 或连接 MCP 而缺少机构治理、权限、版本和审计；
- 不把本地文件夹当作课程、课堂、作业、学生等正式 ClassIn 业务对象；
- 不让 AI 生成即等于正式保存、发布或业务写回；所有变化应形成 `ProposedAction → Approval → ExecutionReceipt`；
- 不用一条会话转录代替任务状态机、异常恢复、部分成功、撤销/过期、Diff 和版本历史；
- 不把产品介绍页的本地、沙箱、记忆和隐私主张直接当作实现事实；
- 不把模型或远端服务返回的 HTML 直接当可信应用打开；需要隔离 Renderer、CSP、网络策略、静态扫描和发布前验证；
- 不默认把学生图片/成绩/试卷转换成长期 CDN URL；数据外发必须经过对象级授权、短期访问、租户隔离、保留/删除策略和审计；
- 不让 Skill 自己读取长期凭据或在错误信息中回显请求头；统一经受控 SecretProvider 和脱敏日志使用；
- 不让积分/促销逻辑干扰机构教师的高频工作区，除非商业模式明确要求。

## 16. 最终判断

NineClaw 已经清晰展示了“教师说目标、Agent 组织工作、产物持续迭代”的产品骨架，尤其是结构化补参、运行中约束修订和生成后可验证/可修改三种模式。23 个当前运行时 Skill 又进一步证明，这套体验确实由业务工作流、领域知识、远端 Adapter、本地分析器和 Artifact Toolchain 组合支撑，而不是只有界面演示。【UI-E1】【SRC-E4】【INF】

但当前证据仍主要覆盖通用任务、聊天转录、本地/远端文件产物和松散 Skill 契约；它没有证明完整的生产治理。ClassIn WorkBuddy 应保留任务—产物闭环，同时把 ClassIn 领域对象、显式状态机、数据分级、隔离渲染、风险审批、执行回执、机构级 Skill 版本/权限/eval 和受控能力发现补入核心，并把底层技术噪声从教师默认体验中收起。【SRC-E4】【INF】
