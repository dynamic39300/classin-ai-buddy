# 独立教师 WorkBuddy 获客、AI 点数与会员体验研究

## 1. 研究问题

M4.4 要把已验证的教师 WorkBuddy 能力装配成独立 PC Web 产品，服务个人教师和未合作机构中的教师，并通过 ClassIn Context 能力形成转化。研究回答四个问题：

1. 独立教师 AI 产品如何让个人教师免费进入并理解付费增量；
2. AI 点数如何表达余额、任务成本、结算和恢复；
3. 会员与充值入口怎样存在于工作台而不打断任务；
4. 无 ClassIn Context 时如何保持可用，并清晰表达连接后的能力增量。

研究只采信官方产品页、官方帮助文档和项目内已归档的一手截图。竞品页面只能证明可见体验，不能证明其服务端支付、扣费、退款或隐私实现。

## 2. 一手证据

### 2.1 MagicSchool

MagicSchool 官方价格页将个人教师分为 Free 与 Plus，同时为学校和学区提供 Enterprise。Free 明确面向探索 AI 的个人教师；Plus 面向希望持续使用的个人教师，并把无限生成、完整历史和 AI 结果编辑作为增量。页面把免费注册作为主入口，而不是先要求机构采购。[MagicSchool Pricing](https://www.magicschool.ai/pricing)

对 M4.4 的启示：

- 首次价值不应被付费墙阻断；
- 个人教师与机构采购是两条不同路径；
- 会员权益应围绕持续任务、历史和可编辑产物表达，不只展示抽象模型能力。

### 2.2 Brisk Teaching

Brisk 官方首页把产品定位为教师和学生使用的 AI 教育平台，提供免费注册，同时为学校和学区设置独立方案入口。官方 Plans 页面明确存在 `Educator Free` 和学校/学区方案，说明个人教师获客与机构转化可以在同一品牌下分开承接。[Brisk](https://www.briskteaching.com/) [Brisk Plans](https://www.briskteaching.com/plans)

对 M4.4 的启示：

- 官网首屏应先说清教师能完成什么，再解释产品技术；
- “个人教师立即使用”和“机构了解 ClassIn”使用不同 CTA；
- 机构入口不应迫使个人教师先理解管理员、席位或采购流程。

### 2.3 Adobe Generative Credits

Adobe 官方说明将 generative credits 定义为跟踪生成式能力成本和用量的单位。不同能力可以消耗不同额度，套餐按月分配额度，用户可查看余额和重置时间；某些工作流在完成后根据实际使用结算。[Adobe Generative Credits FAQ](https://helpx.adobe.com/creative-cloud/apps/generative-ai/generative-credits-faq.html)

对 M4.4 的启示：

- 对教师使用“AI 点数”，不暴露模型 Token；
- 任务开始前展示预计点数，复杂任务可比简单任务消耗更多；
- 余额、流水、套餐到账和余额不足必须是显式状态；
- 任务失败或取消不能留下无法解释的扣点，应释放预占或形成退款流水。

### 2.4 Nine Claw 项目证据

项目内 Nine Claw 截图证明了以下可见体验：全局侧栏持续显示会员推广与积分余额；积分中心包含赚取任务与积分明细；流水记录 AI 对话消耗和奖励；充值页包含月度会员、积分充值、多个套餐和支付方式。现有材料没有证明支付成功、到账、退款、到期或余额一致性的真实服务端语义。

- 不照搬强促销卡和真实支付二维码；
- Demo 必须补齐模拟订单成功、到账、余额不足和失败释放状态，并明确 `[模拟]`。

## 3. 产品结论

### 3.1 用户与购买者

首期只有教师个人账号。未合作机构中的老师也按个人教师进入，不建设机构管理员、成员、团队额度或统一采购。机构需求通过“申请机构体验”转向 ClassIn。

### 3.2 首次价值路径

```text
官网理解价值
→ 注册或登录
→ 领取模拟体验点数
→ 进入完整教师 WorkBuddy
→ 看到未连接 ClassIn 的上下文提示
→ 用自然语言和上传资料补充教学范围
→ 查看预计点数并创建任务
→ 得到可预览、可修改、可保存的产物
→ 在需要业务事实或系统写回时了解 ClassIn 增量
```

### 3.3 AI 点数语义

产品点数不等于模型 Token。首期采用固定、脱敏、可重置的任务报价：单课件 60 点、测验 80 点、课程方案包 120 点。正式商业定价仍为 `UNKNOWN`。

点数状态机：

```text
quoted → reserved → settled
                  ↘ released
```

- `quoted`：页面展示任务类型与预计点数；
- `reserved`：余额足够后预占，阻止并发重复消费；
- `settled`：Run 已稳定创建，形成任务消费流水；
- `released`：Run 未创建或命令失败，点数退回并形成释放流水；
- 相同消费键稳定回放，不重复扣点；不同请求复用键时 fail closed。

### 3.4 模拟会员与订单

首期提供体验版、教学版、专业版三档固定模拟套餐。订单只验证选择、确认、成功到账和流水，不接真实支付、二维码、发票、退款或生产权益。所有金额、点数和订单均显示 `[模拟]`。

### 3.5 无 ClassIn Context

未连接 ClassIn 不意味着 AI 不可用。WorkBuddy 仍可依据教师目标、手动补充的年级/学科/单元和上传资料生成内容，但必须持续说明：

- 当前没有自动读取班级、课程、作业和学情事实；
- 结果只基于本次输入和上传资料；
- 连接 ClassIn 后可自动带入已授权 Context，并开放受治理的业务写回；
- 连接入口是价值说明和产品转化，不伪装成当前已完成的生产集成。

## 4. 不采用的模式

- 不用模型名称或 Token 数量作为教师价格语言；
- 不在官网首屏先展示套餐；
- 不把机构采购流程塞进教师注册；
- 不用积分奖励任务制造与教学无关的增长游戏；
- 不在余额不足后静默降级或负数扣费；
- 不让独立产品读取终局或 ClassIn MVP 的 Run、历史、文件、Receipt 或点数数据；
- 不根据竞品截图推断真实支付、退款和服务端一致性。

## 5. M4.4 建议 Gate

1. 未使用 ClassIn 的教师能独立注册并完成首次 AI 任务；
2. 创建任务前能看到预计点数，成功后余额与流水一致；
3. 余额不足时任务不创建，并可进入会员中心补充模拟点数；
4. 登录刷新后恢复同一独立账号、点数和任务空间；
5. 未连接 ClassIn 的限制与连接后的增量不依赖口头解释；
6. `standalone-teacher` 与 `ideal-full`、`classin-mvp` 的 Route、配置和私有数据空间完全隔离。
