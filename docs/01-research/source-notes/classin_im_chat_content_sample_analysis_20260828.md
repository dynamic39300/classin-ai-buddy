# ClassIn IM 2026 年 8 月单聊与班级群聊内容抽样分析

> **历史状态（2026-08-29）**：本文已作为预研 Round 0 封存。工作簿结构、样本规模和已明确的字段缺口可作为预研事实参考；规则主题、比例、响应代理及其产品映射不具备决策级语义真值。原样快照见 [Round 0 封存包](../../07-history/stage-deliverables/im-data-prestudy-round-0-20260828/README.md)；正式研究见 [ClassIn IM 真实沟通事实研究](../im-real-communication-fact-study/README.md)。

初版聚合工作簿：[ClassIn IM 2026 年 8 月单聊群聊抽样分析](../../../outputs/classin-im-analysis-20260828/ClassIn_IM_2026-08_单聊群聊抽样分析.xlsx)。其中主题计数与“占教学锚点”列仅保留为第一轮规则筛选结果；2026-08-28 复核后，不应再把该列理解为主题发生率或会话占比。

### 口径校准说明（2026-08-28）

用户复核后重新追溯了主题统计和群聊角色。必须修正四点：

1. `3,224`、`22,106` 等是**具体命中规则的消息行数**，不是命中会话所包含的全部消息，也不是会话数；
2. `30.6%`、`32.7%` 的分母分别是单聊和群聊的全部教学锚点消息，并不是全部消息或全部会话；
3. 主题采用多标签，一条长的课后反馈可能同时进入课程、知识、作业、进度和反馈等多个主题；
4. 人工抽样发现小说文本、课程模板和泛化学科词也会误命中，因此下文“高置信教学主题”统一降级理解为**规则候选主题**，必须经过人工场景复核。

三套并列口径如下：

| 渠道与主题 | 规则消息 | 旧口径：占教学锚点 | 占全部消息 | 覆盖会话 | 会话覆盖率 | 收紧口径消息 |
|---|---:|---:|---:|---:|---:|---:|
| 单聊：课程时间与课堂入口 | 3,224 | 30.6% | 1.8% | 737 | 40.8% | 2,883 |
| 单聊：知识答疑与讲解 | 1,869 | 17.7% | 1.0% | 554 | 30.7% | 809 |
| 群聊：课程时间与课堂入口 | 22,106 | 32.7% | 3.5% | 3,308 | 51.8% | 19,498 |
| 群聊：知识答疑与讲解 | 11,182 | 16.6% | 1.7% | 2,067 | 32.3% | 8,628 |

“收紧口径”只去掉“课程”单独出现、学科名无疑问语境等部分宽泛命中；它仍然不是人工真值。产品优先级不能再只依据原主题排名，需要结合脱敏上下文人工判断：真实任务、参与关系、是否解决、AI 介入价值和风险。

群聊角色回溯还发现：

- 师生班级群候选 4,913 个，占 76.9%；
- 样本内无学生的教师/班主任群候选 383 个，占 6.0%；
- 样本内无教师的学生交流群候选 1,096 个，占 17.1%。

在“课程时间/课堂入口 + 请假考勤”的收紧候选消息中，教师/班主任群候选贡献 920 条，约占全部该类收紧候选的 4.4%。这证明教学管理群确实存在，必须从师生班级群中拆分；但按当前固定样本内角色，它不是该主题候选的主体。此结论仍受 100 条截断和角色语义限制。

## 0. 结论摘要

本次对用户提供的 131 MB Excel 文件进行了全量流式扫描，共读取：

| 指标 | 结果 |
|---|---:|
| 数据行 | 819,700 |
| 会话数 | 8,197 |
| 单聊会话 | 1,805 |
| 班级群聊 | 6,392 |
| 单聊消息样本 | 180,500 |
| 群聊消息样本 | 639,200 |
| 观察到的去重发言用户 | 23,064 |
| 时间范围 | 2026-08-01 至 2026-08-27 |

最重要的六项发现如下。

### 发现一：数据是“每会话固定 100 条”的内容样本，不是自然消息量

8,197 个会话全部恰好 100 条；每个会话的 `rn` 都完整覆盖 `1–100`，并且 `rn` 顺序与时间戳在全部 8,197 个会话中单调一致。

因此本文可以较可靠地分析：

- 每类会话的内容和互动结构；
- 单聊与群聊的差异；
- 教学主题在会话样本中的相对出现情况；
- 群规模与角色差异；
- 可进入 AI 产品验证的场景。

但不能直接推断：

- 全站真实消息总量和单聊/群聊自然流量占比；
- 每日活跃、增长或衰减趋势；
- 每个群实际完整月消息量；
- 消息样本之外是否已经发生回复或问题解决。

本文所有“消息占比”均指固定 100 条会话样本内部，不代表线上流量市场份额。

### 发现二：ClassIn 班级群并不天然等于教学群

脱敏人工抽样验证发现，群聊同时包含：

- 学科教学与语言学习；
- 教师培训和职业培训；
- 金融投资交流；
- 电商与内容运营；
- 兴趣社群和普通社交；
- 泛娱乐和内容创作。

高精度教学词汇至少在 70.2% 的群聊和 67.0% 的单聊样本中出现过一次；但达到“100 条中至少 10 条带教学锚点”的会话只有：

| 渠道 | ≥1 条教学锚点 | ≥5 条 | ≥10 条 | ≥20 条 | ≥30 条 |
|---|---:|---:|---:|---:|---:|
| 单聊 | 67.0% | 35.8% | 21.4% | 7.5% | 2.8% |
| 群聊 | 70.2% | 46.5% | 35.5% | 21.4% | 11.3% |

这些是高精度规则的下限信号，不等于正式行业分类。但它证明：TeacherIn 和 Learning Loop 不能对所有“班级群”无差别启用，应先判断班级/机构场景、授权能力和教学相关度。

### 发现三：规则候选中课堂事务命中最多，但不能直接等同于真实业务主题频率

按规则型教学主题做多标签初筛：

| 教学主题 | 单聊消息 | 占单聊教学锚点 | 群聊消息 | 占群聊教学锚点 |
|---|---:|---:|---:|---:|
| 课程时间与课堂入口 | 3,224 | 30.6% | 22,106 | 32.7% |
| 知识答疑与讲解 | 1,869 | 17.7% | 11,182 | 16.6% |
| 作业提交与订正 | 1,055 | 10.0% | 9,761 | 14.5% |
| 资料文件与回放 | 376 | 3.6% | 7,224 | 10.7% |
| 学习计划与进度 | 136 | 1.3% | 3,973 | 5.9% |
| 考试测评与成绩 | 322 | 3.1% | 2,684 | 4.0% |
| 请假考勤与到课 | 459 | 4.4% | 2,104 | 3.1% |
| 反馈激励与情绪 | 18 | 0.2% | 2,098 | 3.1% |
| 技术与账号支持 | 279 | 2.6% | 1,392 | 2.1% |

多标签占比可以重叠，不应相加为 100%。

经口径校准后，这张表只能支持“候选场景发现”，不能单独支持“真实主题频率排序”。初步产品含义是：

- “课什么时候上、从哪里进、怎么调课、能否请假、资料在哪里”是最容易通过 ClassIn 事实和快捷操作解决的高频问题，适合方案一；
- “知识答疑 + 作业订正”虽然绝对频率稍低，却更适合形成 Learning Case 和 Learning Loop；
- 高价值产品不应把所有高频事务都包装成学习闭环，否则会制造过度结构化。

### 发现四：群聊中存在显著的“问题被看见”机会

在高置信教学语境内识别到：

- 单聊教学疑问 2,310 条，其中 91.9% 在样本后续 24 小时内观察到另一参与者发言；
- 群聊中学生教学疑问 11,289 条，其中 58.9% 在样本后续 24 小时内观察到教师/班主任发言；
- 群聊有 4,645 条学生教学疑问在固定样本内未观察到教师后续发言。

响应延迟代理值：

| 渠道 | 中位数 | P75 | P90 |
|---|---:|---:|---:|
| 单聊：对方后续发言 | 3.7 分钟 | 36.3 分钟 | 3.8 小时 |
| 群聊：教师后续发言 | 8.9 分钟 | 90.3 分钟 | 9.2 小时 |

必须强调：后续发言不一定是在回答该问题；未观察到也可能是样本截断、学生互助、线下解决或不需要老师处理。因此它是“注意力机会代理”，不是问题解决率或教师响应 SLA。

即便如此，这仍然是 3A Teacher Attention Radar 最有力的数据依据：AI 先在教师私密面聚合、去重和展示来源，让老师判断哪些问题需要自己回应、哪些可交给学生互助、哪些应转成群讲或 Learning Case。

### 发现五：群聊并非单纯广播，超过九成群样本包含显著学生交流

按每群固定 100 条样本中的发言角色分布：

| 群聊形态 | 群数 | 占比 |
|---|---:|---:|
| 师生混合互动 | 3,499 | 54.7% |
| 学生交流主导（学生消息 ≥80%） | 2,308 | 36.1% |
| 教师广播主导（教师消息 ≥80%） | 585 | 9.2% |

全部群聊消息样本中：

- 学生/旁听生发言约 64.3%；
- 教师/班主任发言约 35.7%；
- 每群 100 条样本中的去重发言者中位数为 4 人；
- 头部单一发言者平均贡献 53.7%，中位数为 53%。

这说明 ClassIn 群聊同时承担广播、事务协调、学生交流和教学互动。产品不能只按“老师发布—学生接收”设计，也不能让公开 Agent 默认插入每段学生交流。

### 发现六：三方案各有清晰的数据切入点

| 方案 | 最强数据切入点 | 当前建议 |
|---|---|---|
| 方案一 AI Enhanced IM | 课堂时间/入口、请假、资料检索、回复草稿、长消息摘要 | 作为低风险高频基础层优先增强 |
| 方案二 Learning Loop | 知识答疑、作业订正、学习计划、阶段反馈 | 选一个 Case 独立设计完整 Loop，不修改方案一页面 |
| 方案三 3A Radar + 3C Learning Case | 群聊问题发现、跨消息聚类、教师分流、持续跟进和结果收口 | 当前最值得做的创新概念探针 |
| 方案三 3B Agent Session | 学生交流主导群、讨论主持、阶段总结、微活动 | 更高风险，放在 Radar/Case 建立信任之后 |

## 1. 数据与方法

### 1.1 字段

原文件包含 20 个字段，主要包括：

- 发言者身份和用户类型；
- 班级规模分桶；
- 会话 ID 和群类型；
- 消息 ID、命令、正文和协议字段；
- 发信人、目标用户和显示名；
- 时间戳、日期与会话内排名。

本文不导出任何消息正文、用户 ID、群 ID、目标 ID 或显示名。

### 1.2 渠道口径

- `clustertype=1`：1v1 单聊；
- `clustertype=0`：班级群聊。

单聊的 `user_type` 在 180,500 行中全部为“其他”。因此当前文件无法可靠区分：

- 老师—学生单聊；
- 学生—学生单聊；
- 其他角色单聊。

本文只分析 1v1 整体，不通过昵称、语气或内容猜测角色。若要验证“老师—学生单聊”的具体产品机会，需要补充脱敏角色映射。

### 1.3 Conversation Episode

同一会话按时间排序，相邻消息间隔超过 30 分钟时切分为新的 `ConversationEpisode`：

| 指标 | 单聊 | 群聊 |
|---|---:|---:|
| Episode 数 | 27,924 | 125,273 |
| 每 Episode 消息数中位数 | 2 | 2 |
| P75 | 5 | 4 |
| P90 | 13 | 10 |
| 参与者中位数 | 1 | 1 |
| 时长中位数 | 56 秒 | 39 秒 |

这说明大量沟通是短促表达或单边信息片段。AI 不应强迫每次聊天都建立任务或 Loop；只有需要持续跟进、责任明确和结果确认的片段才升级为 Case。

### 1.4 教学主题方法

本文使用高精度规则做第一轮多标签初筛，主题包括：

- 课程时间与课堂入口；
- 知识答疑与讲解；
- 作业提交与订正；
- 资料文件与回放；
- 学习计划与进度；
- 考试测评与成绩；
- 请假考勤与到课；
- 反馈激励与情绪；
- 技术与账号支持；
- 班级通知与组织；
- 报名付费与服务。

规则结论用于发现方向和排序，不等于人工标注或模型语义分类。正式 PRD 前应对入选场景做人工 Episode 复核。

## 2. 单聊分析

### 2.1 基本结构

| 指标 | 结果 |
|---|---:|
| 单聊会话 | 1,805 |
| 消息样本 | 180,500 |
| 观察到的发言者 | 3,067 |
| 有两个发言者的会话 | 1,760（97.5%） |
| 样本内只有一个发言者 | 45（2.5%） |
| 发言者消息占比最高一方，中位数 | 58% |

虽然无法识别角色，但绝大多数单聊样本确实观察到双方发言，适合分析沟通节奏和回复辅助。

### 2.2 消息表达特征

| 指标 | 单聊 |
|---|---:|
| 消息长度中位数 | 8 字符 |
| P75 | 18 |
| P90 | 45 |
| 20 字符以内 | 78.0% |
| 疑问表达 | 13.8% |
| 确认/应答 | 4.3% |
| 感谢 | 2.7% |
| 请求/求助 | 1.2% |

产品含义：单聊 AI 不应要求老师写长 Prompt。更自然的入口是：

- 基于当前对话自动补上下文；
- 一键“帮我理解问题”“生成回复”“追问缺失信息”；
- 将建议插入输入框供老师修改；
- 老师发送后 AI 停止，不以 Agent 身份抢话。

### 2.3 单聊中的规则候选教学主题

| 排名 | 主题 | 消息数 | 占教学锚点消息 |
|---:|---|---:|---:|
| 1 | 课程时间与课堂入口 | 3,224 | 30.6% |
| 2 | 知识答疑与讲解 | 1,869 | 17.7% |
| 3 | 作业提交与订正 | 1,055 | 10.0% |
| 4 | 请假考勤与到课 | 459 | 4.4% |
| 5 | 资料文件与回放 | 376 | 3.6% |
| 6 | 考试测评与成绩 | 322 | 3.1% |
| 7 | 技术与账号支持 | 279 | 2.6% |

最适合方案一的单聊能力：

1. 查询课程、课堂和请假事实；
2. 根据当前聊天生成简短、可编辑回复；
3. 自动定位相关课件、作业、回放和课程对象；
4. 识别学生问题缺失的课程、作业或题号信息并建议追问；
5. 老师确认后以老师身份发送。

最适合方案二/3C 的单聊能力：

- 一个知识问题跨多轮仍未解决；
- 作业反馈需要学生补交、订正和复查；
- 学习计划需要连续跟进；
- 一次回复不足以证明学生已经理解。

但在获得师生单聊角色映射之前，只能做概念验证，不能把当前 1v1 总体统计直接当成师生单聊事实。

## 3. 班级群聊分析

### 3.1 角色和互动结构

| 发言角色 | 消息数 | 占群聊样本 |
|---|---:|---:|
| 学生 | 410,369 | 64.2% |
| 旁听生 | 408 | 0.1% |
| 班主任 | 135,655 | 21.2% |
| 教师 | 92,763 | 14.5% |

群聊不是纯广播。54.7% 的群是师生混合互动，36.1% 是学生交流主导，只有 9.2% 是教师广播主导。

这对 AI 身份有直接要求：

- 学生交流主导时，公开 Agent 默认保持安静；
- AI 先把值得关注的问题呈现在 TeacherIn 私密层；
- 教师显式开启 Session 或批准后，班级 Agent 才公开主持、总结或发布活动；
- 老师接管后 Agent 应停止该 Case 的公开发言。

### 3.2 群规模差异

| 班级规模 | 群数 | 100 条样本中的去重发言者中位数 | P90 |
|---|---:|---:|---:|
| ＜30 人 | 4,917 | 3 | 7 |
| 30–100 人 | 1,162 | 10 | 19 |
| ＞100 人 | 313 | 15 | 33 |

大群的高置信教学内容更偏：

- 课程时间与入口；
- 资料/课件分发；
- 知识问题；
- 考试测评。

小群中作业和知识答疑的相对出现率更高。这个结果支持按班级规模调整默认体验：

- 小群优先问题、作业和个别跟进；
- 大群优先搜索、摘要、资料入口、问题聚类和低打扰通知；
- 不给所有群配置相同的主动 Agent 频率。

### 3.3 学生、教师和班主任关注点不同

学生高频教学主题：

1. 课程时间与课堂入口；
2. 资料、课件和回放；
3. 知识答疑；
4. 作业；
5. 请假和到课。

教师高频教学主题：

1. 课程时间与课堂入口；
2. 知识讲解；
3. 作业与订正；
4. 学习计划与进度；
5. 反馈与课堂小结。

班主任更偏：

1. 课程时间与课堂入口；
2. 知识/事务转达；
3. 作业；
4. 资料；
5. 请假、技术与组织协调。

产品含义：

- 班主任模式更适合事务雷达、通知、课务和异常处理；
- 任课教师模式更适合问题雷达、讲解、作业 Case、学习计划和反馈；
- 学生入口应优先解决“怎么进、资料在哪、问题怎么表达”，而不是暴露复杂 Agent 能力拓扑。

### 3.4 群聊问题响应代理

高置信教学语境下，学生疑问 11,289 条：

- 6,644 条在样本后续 24 小时内观察到教师/班主任发言；
- 4,645 条未观察到教师/班主任后续发言；
- 观察到教师发言的中位等待约 8.9 分钟；
- P75 约 90 分钟；
- P90 约 9.2 小时。

这里最值得做的不是让 Agent 自动回答全部问题，而是建立分流：

```text
学生自然发言
→ AI 私密识别候选问题
→ 去重并判断：课堂事务 / 知识问题 / 作业问题 / 资料问题
→ TeacherIn Radar 展示来源、等待时间和相似问题
→ 老师选择：忽略 / 快速回复 / 群讲 / 个别跟进 / 建立 Learning Case
→ 经确认回流原会话
→ 观察是否还有追问或完成证据
```

## 4. 跨渠道比较

### 4.1 相同点

- 单聊与群聊的疑问表达均约占固定样本的 13.8%；
- 晚间 20–21 点是样本内最集中的沟通时段；
- 18–23 点约占单聊样本 42.9%、群聊样本 41.1%；
- 消息普遍短，不适合依赖长 Prompt；
- 课堂事务、知识问题和作业是教学语境中的稳定主题。

### 4.2 不同点

| 维度 | 单聊 | 群聊 |
|---|---|---|
| 主要关系 | 私密、双向、上下文连续 | 公开、多角色、话题容易交叉 |
| 消息长度中位数 | 8 | 12 |
| 教学锚点消息率 | 5.8% | 10.6% |
| 教学锚点中的疑问率 | 21.9% | 23.5% |
| 样本内响应代理 | 较高 | 较低且容易漏看 |
| 最适合的 AI | 回复建议、上下文补全、个别 Case | Radar、聚类、分流、群讲和 Agent Session |
| 主要风险 | 隐私、角色误判、敏感措辞 | 越权公开、噪声、错误扩散、学生标签化 |

## 5. AI 产品机会排序

### O1：课堂事务自助与快捷动作

证据：课程时间与课堂入口是单聊和群聊中命中最多的规则候选主题；但其中混有长模板、泛化课程词和非教学误判，必须结合人工复核后才能用于立项。

适合：方案一 `AI Enhanced IM`。

能力：

- 查询课程时间、课堂入口、调课和请假规则；
- 定位回放、课件和群文件；
- 生成简短回复；
- 必要时创建 ProposedAction，经确认后执行。

判断：高频、低风险、适合率先上线，但它是 AI IM 基础价值，不足以单独代表学习体验升级。

### O2：教师教学沟通雷达

证据：群聊中识别到 11,289 条学生教学疑问，41.1% 在样本内没有观察到教师后续发言。

适合：方案三 `3A Teacher Attention Radar`。

能力：

- 跨群/单聊发现等待、重复和未收口的问题；
- 按课程事务、知识、作业、资料、情绪风险分流；
- 聚类相似问题并保留原消息证据；
- 只向老师私密展示；
- 老师决定是否回应、群讲、建 Case 或继续观察。

判断：当前最强的方案三概念探针。

### O3：从聊天生成 Learning Case

证据：知识答疑和作业订正在群聊中分别命中 11,182 和 9,761 条；两者都需要比一次回复更持续的处理。

适合：方案三 `3C Conversation-to-Learning Case`，并作为方案二 Learning Loop 的入口。

Case 最小字段：

- 来源消息；
- 问题/目标；
- 对象与 Owner；
- 当前状态；
- 下一步；
- AI 建议和授权；
- 学生响应；
- 结果、未解决项和复查时间。

判断：与 3A 组合成 `Learning Signal Network`；避免把每条消息都转成工单。

### O4：1v1 教师回复副驾驶

证据：单聊消息中位数只有 8 字符，疑问表达占 13.8%，教学主题集中在课堂事务、知识和作业。

适合：方案一。

能力：

- 当前对话摘要；
- 缺失上下文提示；
- 分层解释和回复草稿；
- 建议保持私聊还是转成群内共性回答；
- 插入输入框，老师编辑后发送。

阻塞：当前数据缺少 1v1 参与者角色，必须先补充角色映射再做目标人群量化。

### O5：资料与学习对象检索

证据：资料/课件/回放在群聊中命中 7,224 条，且中大群相对更突出。

适合：方案一。

能力：自然语言搜索、来源引用、权限校验、一键分享；不要让 AI 复制一份失去版本和权限的内容。

### O6：有边界的班级 Agent Session

证据：36.1% 的群由学生交流主导，54.7% 是师生混合互动；群聊有真实的讨论促进空间。

适合：方案三 3B，高风险实验。

能力：老师指定目标、时限、作用范围和干预预算后，Agent 在一个 Topic/Thread 内主持、追问、总结和发起微活动。老师可随时暂停或接管。

判断：不作为首个切片。先通过 Radar 和 Case 建立信任，再验证公开促进是否提高参与和收口质量。

## 6. 对三方案的具体推进建议

### 6.1 方案一：先强化“事实型问题 + 私密辅助”

建议优先：

1. 会话 Catch-up：问题、等待、决定、资料和下一步；
2. 课程/课堂/请假/资料的 ClassIn 事实查询；
3. 1v1 和群聊的回复草稿；
4. 来源、权限和公开前预览；
5. Action + Approval + Receipt；
6. Human Takeover 后 Agent 停止。

不建议把主动公开发言作为方案一 P0。

### 6.2 方案二：从一个真实 Case 独立重构

首个概念原型建议在人工复核后，从以下二选一：

- 知识问题 Loop：提问 → 追问卡点 → 分层讲解 → 微检查 → 理解证据 → 收口；
- 作业订正 Loop：问题/错题 → 反馈 → 学生订正 → 复查 → 结果沉淀。

页面重新设计为 Today / Class Stage / Loop Canvas / Learning Memory，不在方案一消息页增加越来越多的卡片。

### 6.3 方案三：优先做 3A + 3C 组合探针

建议最小概念原型只有三段：

```text
Teacher Radar
→ Case View
→ Conversation Return
```

- Radar 验证老师是否更快发现真正值得处理的问题；
- Case 验证聊天问题能否持续推进并留下结果；
- Return 验证所有行动是否能回到原单聊/群聊，而不制造第二套孤立系统。

方案三成立的标准不是“老师喜欢看摘要”，而是：发现时间下降、漏看下降、正确分流增加、Case 收口率提高，并且没有明显监控感和越权。

## 7. 建议的第一轮人工验证样本

从原始数据中按匿名 ID 抽取 Episode，但不进入代码仓库：

| 样本 | 建议数量 | 目的 |
|---|---:|---|
| 群聊：学生教学疑问，后续有教师发言 | 50 | 研究老师如何判断和回答 |
| 群聊：学生教学疑问，样本内无教师发言 | 50 | 判断是真漏看、无需处理还是样本截断 |
| 群聊：相似知识问题/作业问题 | 50 | 验证聚类和 Case 价值 |
| 单聊：高置信教学问题 | 50 | 在补齐角色后研究师生私聊 |
| 课程事务与资料问题 | 30 | 验证方案一事实查询 |
| 非教学班级群 | 30 | 验证能力启用边界和误触发风险 |

每个 Episode 由研究员标注：任务、角色、上下文、是否解决、老师负担、学生影响、AI 最适介入方式和风险。

## 8. 仍需补充的数据

### P0：1v1 脱敏角色映射

提供稳定匿名 ID 对应的角色类型即可，不需要姓名：

```text
pseudonymous_user_id
role: teacher / head_teacher / student / auditor / other
```

这样才能将 1,805 个单聊拆成老师—学生、学生—学生和其他类型。

### P0：会话真实总消息数

为每个会话增加 `total_message_count_in_period` 或提供不封顶聚合数，才能：

- 恢复真实单聊/群聊消息量权重；
- 计算群活跃度；
- 判断 100 条上限造成的截断程度；
- 分析自然日趋势和真正高频场景。

### P1：脱敏班级业务元数据

- 机构/个人班；
- 学科或培训类型；
- 年龄/学段；
- 班级是否真实教学用途；
- 班级状态和课程活跃度。

这样可以把金融、电商、兴趣社群和教学班分开，避免 TeacherIn 错误启用。

### P1：响应和业务结果

- 消息是否被读；
- 是否显式回复；
- 是否进入课堂、打开文件或提交作业；
- 问题是否解决；
- 是否发生后续订正或复查。

原文件中 `replymsgid` 非空约 70,005 行，但这只是协议字段。它与用户已确认的“1.0 不支持可见单条 Reply 操作”存在表面差异，不能据此推断线上 UI 支持回复，需要工程侧解释字段语义。

## 9. 风险和解释边界

1. 每会话固定 100 条，不能用于全站流量和趋势结论；
2. 单聊缺少角色，不能直接声称某结论属于师生私聊；
3. 规则型主题只用于初筛，不能替代人工语义标注；
4. 群聊包含大量非教学场景，不能把“班级”当成教学标签；
5. 后续发言不等于问题得到回答或解决；
6. 未观察到教师发言可能来自样本截断；
7. 情绪、安全和学生评价不应仅凭关键词自动判断；
8. 原始聊天和身份信息不得进入仓库、Prompt 日志或无治理长期记忆；
9. 进入 Feature Spec 前，必须使用匿名 Episode 人工复核入选场景；
10. 本文结论是研究建议，不自动升级为 `LOCKED` 产品决策。

## 10. 当前建议结论

基于本轮数据，下一阶段不应只在“方案一还是方案二”之间选择。

更合理的推进是：

1. 用方案一解决高频、低风险的课堂事务、资料和回复辅助；
2. 用 3A Radar 解决群聊中问题难以被老师看见和分流；
3. 用 3C Learning Case 承接知识答疑与作业订正中需要持续跟进的少数高价值问题；
4. 从这些 Case 中选择一个，独立设计方案二 Learning Loop；
5. 在 Radar/Case 建立信任后，再实验 3B 班级 Agent Session；
6. 补齐单聊角色映射和会话真实总量后，再对首个纵向切片做量化决策。

这组数据第一次把“方案一、方案二、方案三”从概念讨论推进到了可由真实聊天行为验证的产品组合。
