# 腾讯 WorkBuddy“资料库 / 我的文件”体验证据核验

- 核验日期：2026-08-22
- 结论状态：`VERIFIED_WITH_BOUNDARIES`
- 一手证据：`reference/腾讯-workbuddy-我的文件/` 下 6 张本地实测截图
- 对照范围：[领域词汇](../../../CONTEXT.md)、[决策台账](../../00-project/DECISION-LEDGER.md)中的 D-041 / D-044 / D-045、当前 [FileLibrary.tsx](../../../src/features/ai-agent-workspace/FileLibrary.tsx) 与 [file-library.ts](../../../src/features/ai-agent-workspace/file-library.ts)
- 用途：验证 ClassIn WorkBuddy“我的文件”的既定方向，并为后续升级提供可回查的体验输入；本文不把腾讯 WorkBuddy 的业务边界或底层能力推断为 ClassIn 事实。

## 结论

腾讯 WorkBuddy 的可见设计支持我们已经确定的核心方向：以任务为上层组织单元、以文件为下层资产；在文件行和预览层同时提供低成本复用动作；用 Hover、图标按钮和溢出菜单控制列表噪声。尤其是“添加到任务”同时出现在文件行与预览层，使“历史 AI 产物可从资产回溯入口重新进入任务”呈现为高优先级动作，而不只是详情页中的附属入口；静态截图本身不能证明真实使用频率。

但腾讯截图中的“资料库”比 ClassIn WorkBuddy“我的文件”范围更宽：它包含“空间”目录、上传到多个云端、打开文件夹等通用文件管理能力。依据 D-044，这些能力不能照搬。“我的文件”仍只收录教师与 AI 协作生成的 Artifact 及其文件结果，不提供上传入口；ClassIn Space 继续拥有底层存储与文件权限。

当前实现已经覆盖任务分组、精简文件行、类型 / 时间 / 大小、收藏、作为上下文、分享、下载与回到任务。主要缺口是：尚未形成腾讯截图所示的可读文件预览；“作为上下文”尚未在本文件证据范围内证明携带稳定文件引用；D-043 已锁定的“创建草稿到 TeacherIn”也尚未进入当前文件行或详情动作。

## 证据方法与边界

1. 逐张查看 6 张截图，只记录当时可见的页面、控件、文案和选中状态。
2. 静态截图可以证明入口与视觉状态，不能证明点击后的数据写入、权限校验、失败恢复、跨会话持久化或服务端真实能力。
3. 截图里的“添加到任务”可以证明产品使用了这一动作名称；没有后续任务页截图，因此不能证明它是否创建新任务、加入既有任务、如何携带文件引用或是否等同于 ClassIn 方案中的“作为上下文”。
4. 截图里的“分享”只证明入口存在；没有目标选择或成功结果画面，因此不能证明具体分享范围与回执。

## 可见信息架构与交互模式

### 1. 任务是主分组，文件是子级资产

截图中的“未分组”是可折叠集合并显示“4 个任务”；任务标题作为粗体块级主项，文件在任务下缩进排列。另一组“空间”则出现文件夹层级。这说明腾讯“资料库”同时承载任务产物视图和通用空间视图。

对 ClassIn WorkBuddy 可借鉴的是“任务 / Session → 文件”的父子扫描关系；“空间目录”不能被复制到“我的文件”，否则会违反 D-044 并再次形成类云盘入口。

### 2. 文件行采用“稳定信息 + 渐进披露动作”

文件名、类型、更新人、相对时间和大小保持对齐；Hover 后才出现选择框、添加到任务、上传到云端和更多入口。主列表因此同时具备可扫描性和就近操作效率。

当前 ClassIn 实现已经采用相同原则：类型、生成时间和大小是稳定列，收藏、作为上下文和分享在 Hover / Focus Within 时出现。ClassIn 不需要照搬“更新人”，因为“我的文件”范围已限定为当前教师与 AI 协作产物；版本、复用次数和分享去向继续放在详情更符合现有决策。

### 3. 预览层承担阅读与二次流转

腾讯预览不是只有文件摘要，而是可滚动阅读文档正文；分享、上传、更多、放大与关闭集中在头部。预览层的“添加到任务 / 收藏”等动作与列表层复用，减少用户读完文件后返回列表再操作的往返。

这一模式可以借鉴为 ClassIn“只读预览 + 常驻详情动作”，但不能据截图扩展成文档编辑器；截图没有编辑入口，也没有证明保存能力。

### 4. 高频动作直接露出，低频动作进入溢出菜单

“添加到任务”在文件名旁有直接按钮，在详情更多菜单和行级更多菜单中也重复出现；“打开文件夹、收藏、分享给好友”等进入更多菜单，云端上传则有独立快捷按钮。这是按动作频率而不是按技术模块组织入口。

对 ClassIn 来说，高频动作应是“作为上下文 / 加入任务”；“创建草稿到 TeacherIn”是否进入行级快捷区，应由适用文件比例和发布资格决定，至少应在详情中常驻可达。通用云端上传不属于“我的文件”。

## 事实、合理推断与未知

### 已验证事实（FACT）

- 腾讯“资料库”存在任务聚合和空间目录两类上层组织。
- 文件行稳定展示名称、类型、更新人、相对时间和大小。
- 文件行 Hover 后提供“添加到任务”、上传到云端和更多快捷操作。
- 文件详情 / 预览层可直接阅读 Markdown 正文，并提供分享、上传、更多、放大和关闭入口。
- “添加到任务、收藏”在文件行或预览层重复可达；“分享给好友、打开文件夹”等位于更多菜单。
- 上传目标明确包含“我的资料库、腾讯文档、ima 知识库、乐享知识库”。

### 合理推断（INFERENCE）

- “添加到任务”大概率用于把历史文件重新带入 Agent 任务，功能意图与 ClassIn 的“作为上下文”接近。由于没有后续页面证据，二者不能直接视为相同状态转换。
- 行级直接按钮与预览层重复动作表明“复用历史 Artifact”很可能是高频行为；这是根据入口层级和重复可达性做出的体验推断，不是使用频率数据。
- 任务标题、子级缩进和 Hover 动作共同服务于快速扫描与低噪操作；这是界面结构推断，不代表腾讯公开声明的设计原则。

### 未知（UNKNOWN）

- 添加文件到任务时，是否创建新任务、选择既有任务、写入稳定文件引用或复制文件内容。
- 分享目标、权限检查、链接有效期、消息回执和撤回能力。
- 上传到云端的文件所有权、同步 / 复制关系、格式转换和失败恢复。
- 选择框是否支持批量添加、批量上传或批量收藏。
- 预览支持的完整格式范围，以及解析失败、无权限、超大文件等状态。
- 腾讯“空间”与任务产物之间的底层存储关系。

## 可借鉴、不可照搬与后续缺口

### 可直接借鉴的体验原则

1. **任务主项、文件子项**：继续保持独立的 Session 标题、上下文换行和文件整体缩进。
2. **就近复用**：把“作为上下文 / 加入任务”保留为行级快捷动作，同时在详情或预览中常驻。
3. **预览后即行动**：未来接入真实只读预览时，分享、作为上下文、下载、回到任务和符合资格时的“创建草稿到 TeacherIn”应在同一层可达。
4. **渐进披露**：稳定字段始终可扫描；快捷动作只在 Hover / Focus Within 显示，且必须有 Tooltip 与键盘可达替代。
5. **主次分层**：高频动作直接露出，来源定位、收藏等次级动作可以进入更多菜单，但不要因收纳而丢失可发现性。

### 不可照搬

1. **上传到云端及多个外部知识库**：违反 D-044；“我的文件”不是通用导入、同步或跨云搬运中心。
2. **空间目录树**：ClassIn Space 是底层存储载体，但“我的文件”只做 AI 产物投影视图，不能复制云盘目录。
3. **打开文件夹**：腾讯截图没有证明其对象含义；ClassIn 如需来源定位，应使用领域明确的“在空间中定位”。
4. **更新人稳定列**：在单教师 AI 产物入口中信息价值低，不应挤占生成时间、类型或大小。
5. **选择框与批量操作**：截图没有证明完整批量流程；在真实批量需求和权限策略明确前不应增加。

### 当前缺口与建议验证顺序

1. `P0`：为“作为上下文”建立稳定文件引用契约，并用刷新、重命名、权限变化等状态验证，不只追加文件名 Prompt。
2. `P0`：按 D-043 为符合资格的 Artifact 增加“创建草稿到 TeacherIn”，保留来源 Run、Artifact 版本和 TeacherIn 草稿标识。
3. `P1`：把详情摘要逐步升级为只读文件预览，并处理加载、解析失败、无权限、超大文件与不支持格式状态。
4. `P1`：补齐“在 ClassIn 空间中定位”，明确它与“回到任务”的不同目的地。
5. `P1`：保证列表与详情共享同一动作资格判断和执行回执，避免同一文件在两个入口出现不同状态。

以上均为后续方案输入，不表示本轮已经锁定新的范围或要求立即实现。
