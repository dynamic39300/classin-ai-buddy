# 腾讯 WorkBuddy 任务首页、专家、技能与文件装配交互研究

## 1. 结论摘要

这组材料最有价值的不是腾讯 WorkBuddy 的独立产品 Shell，而是它把文件、专家（Agent）、技能和连接器组织成了同一个“任务装配入口”：用户保持在输入框附近，通过加号、二级菜单、搜索列表、选中标签和可撤销状态完成任务准备；当浮层不足以承载发现或管理时，再跳转到完整的专家页或技能管理页。

当前 ClassIn TeacherIn Demo 已经覆盖自然语言任务输入、Skill 搜索与选择、可移除 Skill 标签、快捷教学任务、Core Context 和独立技能市场；尚未覆盖真实文件选择、AgentIn 智能体选择、统一的加号菜单和首页常用能力横条。因此，下一步适合**复刻微交互骨架，改写教育语义和数据落点**，不适合直接复制腾讯的 Shell、通用办公分类、模型选择、外部知识库或“更换主 Agent”的心智。

本文是研究与设计讨论输入，不是 PRD 或开发授权。第 10 节记录用户于 2026-09-03 明确确认的产品方向；Prompt 与非空草稿的合并规则已完成确认。

## 4. SOURCE_FACT：任务首页和完整交互链

### 4.1 首页结构

首页主区从上到下依次是：问候标题、场景分类、常用 Agent / Skill 快捷横条、任务输入器、工作空间与权限、最佳实践案例。输入器左侧有加号，右侧有模型或策略选择、语音和发送；页面还出现活动气泡、积分和升级提示等腾讯自身运营元素。

2026-09-03 新增的第二张截图专门用红框强调了快捷横条。可见项目包括“文档处理、金融服务、数据分析及可视化、个人工作台、幻灯片”等，右侧有继续浏览箭头。Notion 文字把这条横栏定义为“常用的一些 Agent 和 Skill”，但截图没有显示点击其中一项后的状态，因此以下问题仍是 `UNKNOWN`：

- 点击后是直接选择 Agent、加载 Skill、插入 Prompt，还是进入详情；
- 横条由个人使用频率、平台推荐还是固定配置生成；
- Agent 与 Skill 是否有视觉类型区分；
- 是否支持换一批、拖动或键盘横向浏览。

### 4.2 加号与二级菜单

```text
任务输入器
  → 加号
    ├─ 添加文件 → 本地文件 / 腾讯文档 / ima 知识库 / 乐享知识库
    ├─ 模式
    ├─ 专家 → 搜索 / 常用专家 / 召唤更多专家
    ├─ 技能 → 搜索 / 已安装技能 / 从本地添加 / 管理技能
    └─ 连接器
```

这是一个典型的渐进披露结构：一级菜单先按任务资源类型分类，二级菜单承担搜索、短列表和进入完整管理页；用户不必离开当前任务就能完成高频选择。

### 4.3 文件

- 添加文件的二级菜单可见四类来源：本地文件、腾讯文档、ima 知识库、乐享知识库；
- 选择“本地文件”打开操作系统文件选择器；
- 选择“腾讯文档”打开居中的大弹窗，背景遮罩并模糊；
- 腾讯文档弹窗包含搜索框、选择框以及名称、所有者、最近查看和文档大小列；
- 截图没有显示已选文件进入输入器后的标签、上传进度、解析状态、取消、权限失败和格式限制。

### 4.4 专家（Agent）

- 专家二级面板顶部是搜索框，下方是简短的常用专家列表，底部是“召唤更多专家”；
- 输入无匹配关键词时，面板保留稳定高度并显示“未找到专家”；
- “召唤更多专家”进入完整的“专家·技能·连接器”页面，专家 Tab 为当前态；页面包含精选场景、专家 / 专家团、分类、排序、搜索、“我的专家”和卡片网格；
- 选择某个专家后，专家以头像和名称标签进入输入器，同时一段任务 Prompt 自动出现在文本区；
- Hover 专家标签后，头像位置切换为 `X`，可以移除专家。

`UNKNOWN`：已有 Prompt 是被覆盖、追加还是合并；专家是否只能选一个；专家选择是否改变模型、权限或工具；移除专家是否同时撤销自动代入的 Prompt。

### 4.5 技能

- 技能二级面板顶部是搜索框，中部是可滚动的已安装技能列表；每项有图标、名称和简介；
- 搜索输入会动态过滤列表；
- 底部固定“从本地添加技能”和“管理技能”；
- 选择技能后，技能以标签进入输入器；Hover 后出现 `X` 和完整名称 Tooltip，可取消引用；
- “管理技能”进入已安装技能页，页面可见搜索、批量管理、卡片、启用 / 停用开关和套件标记。

`UNKNOWN`：是否允许同时选择多个技能；停用技能是否仍出现在任务选择器；Skill 的权限、版本、冲突、升级、执行失败和结果追溯规则。

## 7. 可以充分复用或 100% 复刻的部分

这里的“100% 复刻”指**交互状态与转场逻辑**，不指复制腾讯视觉 Token、品牌文案或外部数据源。

1. **加号切换与两级浮层**：点击加号打开资源菜单，再 Hover / 点击一级项打开右侧二级面板；关闭后恢复加号。
2. **短选择器结构**：搜索框、可滚动短列表、无结果状态、底部“更多 / 管理”入口。
3. **就地装配**：选中的文件、智能体或 Skill 不离开任务页，先以结构化标签进入输入器，再随任务提交。
4. **可撤销选择**：标签始终提供移除操作；Hover 可以增强反馈，但键盘 Focus 和可见按钮必须同样可达。
5. **浮层到完整页面的分工**：短列表解决“立即选择”，完整 AgentIn / 技能市场解决“发现与管理”；返回时保留任务草稿和已经选择的 Context。
6. **搜索稳定性**：输入搜索词后动态过滤；空结果保持面板尺寸，提供明确文本而非空白。
7. **本地文件调用系统选择器**：该系统行为可以直接复用，但需要补上传、解析、取消和失败状态。

## 8. 必须改成 ClassIn TeacherIn 形态的部分

以下均为 `DESIGN_HYPOTHESIS`，等待用户讨论确认。

### 8.1 Shell 与视觉

- 不复制腾讯左栏、版本号、积分运营气泡、升级横幅、账号区和通用办公案例；
- 保留当前 ClassIn 教师身份、一级导航、TeacherIn 二级导航、任务 Tab、Token 和 `WorkspaceComposer`；
- 浮层与标签使用当前 Design System，不新建第二套圆角、阴影或焦点规则。

### 8.2 “专家”改为 AgentIn 智能体引用

- 用户可见名称建议使用“智能体”或“AgentIn”，不沿用“专家”；
- TeacherIn 仍是统一主 Agent，老师不需要先选择内部 Agent 才能开始任务；
- 显式选择 AgentIn 项时，把它理解为“本次任务引用的专业智能体 / AI 应用”，而不是替换主 Agent 或暴露多 Agent 拓扑；
- 短列表优先显示已收藏、已添加到当前班级或最近使用的智能体；“更多智能体”跳转现有 `/teacher/ai-agent/agentin`；
- 若任务草稿非空，智能体模板不应静默覆盖；可只在空草稿时预填，或显示“插入建议 Prompt”让老师确认。

### 8.3 Skill 作为可选高级能力

- 默认由 TeacherIn 根据教学任务自动规划 Skill；显式 Skill 选择保留为可选增强，不成为完成任务的前置条件；
- 当前 Skill 搜索、选择、移除和市场跳转可以保留；入口可并入加号菜单，并在输入器中继续显示已选标签；
- “管理技能”跳转现有技能市场 / 我的 Skills，不复制腾讯技能管理页。

### 8.4 文件来源改造

腾讯的“腾讯文档、ima 知识库、乐享知识库”不能直接照搬。候选结构是：

```text
添加资料
  ├─ 上传本地文件
  ├─ 从我的文件选择（TeacherIn 历史产物）
  ├─ 从 ClassIn 空间选择
  └─ 从 TeacherIn 内容选择（若本轮授权）
```

若从 ClassIn 对象选择，应显示名称、来源位置、所有者 / 授权范围、更新时间和格式；文件大小只有在本地上传或下载判断中有价值。选择后要生成稳定引用，不应只把文件名拼进 Prompt。

### 8.5 首页快捷横条

新增截图的横条形式可以复用，但不建议直接放“金融服务、个人工作台”等通用类别，也不建议把 Agent 和 Skill 混为一组没有类型标识的胶囊。

更符合 TeacherIn 的候选是“常用教学任务 / 最近使用能力”两种明确模式中的一种：

- 任务模式：备课、生成课件、生成测验、分析学情、作业订正、家校沟通；点击后填充可编辑任务模板；
- 能力模式：最近使用的 AgentIn 智能体和 Skill，带清晰类型图标；点击后形成对应标签。

不建议在一个横条里同时混合这两种点击结果，否则老师难以预判点击后是“选中能力”还是“改写任务”。

### 8.6 不进入首轮的腾讯元素

- 模型名称与模型切换；
- “模式”与“连接器”显式选择；
- 腾讯外部知识库；
- 通用工作空间和“完全访问”权限文案；
- 积分活动、升级提醒和最佳实践营销卡片；
- 只靠 Hover 出现的唯一移除操作。

## 9. 候选的新任务装配流程

```text
老师直接描述教学目标
  ├─ 可选：点击常用教学任务，获得可编辑模板
  ├─ 可选：加号 → 添加资料 → 选择文件并形成稳定引用标签
  ├─ 可选：加号 → 智能体 → 选择 AgentIn 引用
  ├─ 可选：加号 → 技能 → 选择已安装 Skill
  └─ 必需：确认 Core Context / 教学范围
       → 创建 TeacherIn Run
       → Run 中可追溯本次文件、智能体、Skill 与 ContextSnapshot
```

这个候选保留“从教师目标开始”的项目不变量，同时吸收腾讯 WorkBuddy 在任务装配效率上的优势。

## 10. 用户已确认的产品方向

以下内容由用户于 2026-09-03 在研究 Review 中明确确认，可作为下一阶段 PRD 输入：

1. **首页快捷横条承载 Agent / Skill**：不是高频教学任务模板。默认展示 5 条常用 Skill，随后展示 4 条常用 Agent；Skill 与 Agent 需要有可识别的类型样式。
2. **统一使用 Agent 命名**：不使用“专家”；“更多 Agent”跳转当前 TeacherIn 的 AgentIn 页面。
3. **选择数量不设产品上限**：Agent、Skill 和文件均不限制选择数量。5 条 Skill 与 4 条 Agent 只是首页默认常用项数量，不是任务选择上限。任务材料区需要处理大量标签的换行、收起 / 展开和键盘可达，不得挤压正文输入区。
4. **选择 Agent 后自动带入推荐 Prompt**：推荐 Prompt 进入聊天输入框并保持可编辑。若输入框已有老师内容，如何避免覆盖并完成合并仍需确认。
5. **首版文件来源锁定三类**：本地文件、我的文件、ClassIn 空间；首版不加入 TeacherIn、班级群文件、腾讯文档、ima 知识库或乐享知识库。
6. **统一任务材料区**：选中的文件、Agent 与 Skill 统一放在输入框顶部的“任务材料区”；标签视觉参考腾讯 WorkBuddy 的选中 Skill / Agent 样式，但使用当前 ClassIn Design System，并让移除按钮在 Hover、Focus 和触摸条件下都可达。

### 10.1 已确认：推荐 Prompt 与已有草稿

本文中的“空白草稿”是指：老师尚未在聊天输入框里输入任何有效文字，内容为空或只有空格。此时选择 Agent，可以直接把该 Agent 的推荐 Prompt 填入输入框，不存在覆盖用户内容的风险。

当输入框已经有老师输入的文字时，评审过的候选包括：

- `A. 覆盖`：用 Agent 推荐 Prompt 替换已有文字；风险最高，不建议默认采用；
- `B. 自动追加`：保留已有文字，在末尾换行追加推荐 Prompt；满足“自动带入”，但可能形成语义重复；
- `C. 保护原文并确认合并`：保留已有文字，展示“追加推荐 Prompt”动作，老师确认后再插入；最安全，但多一步操作。

用户确认采用以下规则：

- 空白草稿：选择 Agent 后，直接把该 Agent 的推荐 Prompt 填入聊天输入框；
- 非空草稿：保留老师原文，在末尾换行自动追加推荐 Prompt，不覆盖老师输入；
- 追加结果：推荐 Prompt 与原文都保持可编辑，并提供一次“撤销自动追加”；
- 多 Agent：每次选择都追加与对应 Agent 关联的 Prompt 片段，内部保留来源标识，界面不限制选择数量；
- 移除 Agent：若关联 Prompt 片段尚未被老师修改，则同步移除该片段；若已经被老师编辑，则保留文字，避免误删老师内容；移除动作同样提供撤销。

### 10.2 后续 PRD 仍需定义但不阻塞方向的问题

- 5 条常用 Skill 和 4 条常用 Agent 的来源：固定 Mock、最近使用、使用频次或个性化推荐；
- Agent 与 Skill 在快捷横条中的分组标题、类型图标和横向溢出规则；
- “更多 Agent”跳转 AgentIn 后，返回新任务页时如何恢复草稿、任务材料和滚动现场；
- 不限数量条件下，材料区的默认展开高度、折叠阈值、重复选择和批量清空规则；
- Agent 被移除后，是否保留其自动带入且已被老师编辑过的 Prompt。

## 11. 下一道 Gate

研究阶段的核心产品语义已由用户确认，可以在用户发出进入下一阶段的明确指令后编写 PRD。PRD 应定义入口、常用项来源、不限数量下的材料区规则、Prompt 片段来源与编辑状态、草稿保护、标签状态、文件解析、权限、返回现场和错误恢复；之后再按 `PRD → Feature Spec → Tickets → Implementation → Verify` 推进。本研究本身不直接触发代码修改。
