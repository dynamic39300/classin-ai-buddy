# ClassIn IM 真实会话调研 HTML 汇报 V2

## 汇报对象与表达目标

- 对象：管理层、产品专家、AI 产品与教学业务伙伴。
- 目标：先还原 IM 真实现场，再解释用户行为，最后为下一份产品能力方案提供事实起点。
- 表达：业务语言优先；研究方法简练但严谨；Case 使用脱敏原文节选；产品方向只做引子，不写成已经立项的结论。

## 叙事主线

```text
抽样与方法
  -> 会话业务场景
  -> 场景中的高频 Topic
  -> 按角色展开真实 Case
  -> 为什么形成这些聊天特征
  -> IM 与 AI 能力机会
  -> Human Input Context 的延展与边界
```

## 页面结构

1. 封面：人们在 ClassIn IM 里，究竟在聊什么？
2. 研究问题：一个会话中有哪些主题，这些主题由谁、在什么关系中产生？
3. 抽样分析：819,700 条消息、8,197 个窗口、比例分层抽取 1,000 个窗口、100,000 条消息。
4. 分析方法：完整上下文、多 Topic、5% 普通 Topic 门槛、特殊业务例外、可回溯、人机校准。
5. 业务场景地图：780 个群聊窗口与 220 个 1v1 窗口的角色关系。
6. 场景结构：师生班级群 741 个；学生与学生 1v1 132 个；“教师-管理者-教师”跨群聊与 1v1 合计 76 个。
7. 一级 Topic 全景：课程运营、数字平台、学习内容、关系社交、教学设计等。
8. 高频具体事项：课程改期、教材资料、作业、到课缺勤、群治理、技术排障。
9. 多 Topic 现场：每窗平均 3.18 个；851 个窗口含 2 个及以上 Topic；共现不是噪音，而是复合任务。
10. 师生班级群 Case：课程协调、作业闭环、技术排障。整段对话一次呈现，高亮证据句。
11. 教师管理 Case：“教师-管理者-教师”的群聊与 1v1 两种形态。聚焦规范、调课、课时、审核、薪酬。
12. 教师与学生、家长 Case：作业订正、课程恢复、时间确认。
13. 学生同伴 Case：游戏与见面、校园生活、作业互助、写作与 AI 边界。
14. 同一个 Topic，不同责任结构：以“作业”和“排课”为例，说明不能脱离角色直接设计功能。
15. 行为解释：教师是教学执行与专业判断者；管理者是多方约束协调者；学生同时是学习者和社会主体。
16. 核心观点：IM 是意图、约束、承诺和人类判断形成的现场，不只是消息传输渠道。
17. 产品机会引子：意图到业务对象、多方约束到方案、人类判断到成果物、异常到处理事项、表达到账户有边界的 Context。
18. 能力落点：基础 IM、确定性业务工作流、AI 辅助、治理与回执四层组合；按关键场景点出候选能力。
19. Context 的三类 Human Input：教师评价学生、管理者反馈教师、学生表达困难与兴趣。
20. Context 延展：真实聊天只能证明“有人表达过”，不能自动证明内容客观正确；建立有来源、有限期、任务级的 Context Claim 与 ContextSnapshot。

## 视觉与交互原则

- 单页 16:10，优先适配 1440 × 900 投屏。
- ClassIn 品牌绿仅用于重点、证据高亮和控制；其余使用深墨色、冷白与中性灰。
- 不用传统多卡片堆叠，不用聊天气泡，不用装饰性渐变和 AI 紫色。
- Case 以纯文本对话节选呈现，整段一次出现；一页多个 Case 时按整组淡入淡出切换。
- 方向键翻页；空格切换当前页 Case；F 全屏；O 打开目录；N 查看讲者备注。
- 所有动效在 `prefers-reduced-motion` 下自动关闭。

## 事实边界

- 比例均为固定 1,000 会话样本内比例，不直接等同全平台发生率。
- 一个会话可以包含多个 Topic，所以覆盖率合计可以超过 100%。
- 高频不等于痛点强度，也不自动等于应使用 AI。
- 所有产品机会均为从研究事实出发的候选方向，需要在后续方案中继续验证。
