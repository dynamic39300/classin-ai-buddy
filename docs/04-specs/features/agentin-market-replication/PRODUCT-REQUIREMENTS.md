# TeacherIn 内 AgentIn 市场静态复刻 PRD

## 1. 产品目标

在不改变现有 TeacherIn 任务工作台和能力模块的前提下，为教师增加一个可发现 ClassIn 教学智能体的 `AgentIn` 二级入口，并在右侧 Work Surface 中高保真呈现线上 AgentIn 首页市场。当前版本用于产品评审和视觉验证，不连接线上 Agent 市场，不声称真实创建、收藏、授权或班级添加已接入。

## 2. 用户与场景

- 主要用户：进入 ClassIn 教师端 TeacherIn 的教师；
- 主要场景：教师从 TeacherIn 二级导航查看当前 AgentIn 市场的内容组织、推荐与兼容状态；
- 宿主身份：当前 Demo 教师身份；
- 线上参考截图中的学生账号只作为线上页面证据，不复制为当前教师会话身份。

## 3. 事实与适配

| 层 | 内容 |
|---|---|
| `ONLINE_FACT` | AgentIn 线上从班级详情“AI 应用”加号进入，支持独立窗口和全屏页，首页包含内部导航、推荐、学段、搜索、分类、排序、可添加与不支持添加分区 |
| `USER_REQUIREMENT` | 在首页 TeacherIn 二级导航新增 AgentIn Tab，右侧展开对应页面，元素与内容高保真复刻 |
| `DEMO_ADAPTATION` | 用 TeacherIn Work Surface 承载 AgentIn，不复制操作系统窗口边框；保留 AgentIn 自身内部导航和市场主体；采用响应式列数适配现有宽度 |
| `UNKNOWN` | 详情、创建、收藏写入、授权、添加班级与后端搜索逻辑；本轮不实现 |

## 4. 范围

### 4.1 本轮包含

1. 在 `ideal-full` 教师端 TeacherIn 二级导航增加 `AgentIn`；
2. 增加稳定路由 `/teacher/ai-agent/agentin`；
3. 渲染 AgentIn 内部左侧栏：品牌、首页、我创建的、我的收藏和收藏 Agent 列表；
4. 渲染市场主体：学段、搜索框、猜你喜欢、换一换、分类、排序、可添加卡片和不支持添加分区；
5. 使用截图中的中文内容、收藏数、作者和标记；
6. 支持主内容区纵向滚动，1440×900 无横向滚动；
7. 提供 Hover、Focus、选中和输入焦点等基础可访问状态；
8. 标注未接入的操作不产生虚假成功结果。

### 4.2 本轮不包含

- 不替换既有“技能市场”；AgentIn 是新增的 ClassIn 教学智能体市场入口；
- 不进入 `classin-mvp` 班级独立 TeacherIn Shell，除非后续用户明确扩大范围；
- 不实现 Agent 详情、DIY、发布、收藏持久化、授权和添加到班级；
- 不调用真实 Notion 图片或线上 AgentIn API；
- 不复制参考截图的 macOS 红黄绿窗口按钮、最小化、最大化和关闭按钮，因为 Work Surface 不是独立操作系统窗口；
- 不复制截图中的学生账号 Footer，避免教师宿主出现身份冲突。

## 5. 信息架构与路由

```text
ClassIn 教师端
  → TeacherIn
    → 二级导航 AgentIn
      → /teacher/ai-agent/agentin
        → AgentIn 首页
          ├─ 首页（当前）
          ├─ 我创建的（仅展示入口，无未知页面跳转）
          ├─ 我的收藏（仅展示列表）
          ├─ 猜你喜欢
          ├─ 学科市场
          └─ 当前场景不支持添加
```

`AgentIn` 不与 `Skill` 同义：Skill 是 TeacherIn 任务运行时能力；AgentIn 是 ClassIn 现状中的教学智能体发现与班级添加市场。两者在本轮保持独立入口，后续是否融合属于新的产品决策。

## 6. 页面规格

### 6.1 宿主导航

- 标签：`AgentIn`；
- 图标：使用与智能体/机器人语义匹配的现有 Lucide 图标；
- 位置：TeacherIn 二级资源能力区，建议置于“技能市场”之前；
- 当前态：复用现有二级导航选中背景、品牌色左标和 Focus 规则；
- 进入能力页面后隐藏任务 Tab，遵循既有能力页规则。

### 6.2 AgentIn 内部左侧栏

- 宽度：宽屏参考 220–240px；紧凑工作区不低于 196px；
- 顶部：`AgentIn` 和收起图标；本轮收起图标只提供可访问标签，不切换未知布局；
- `首页` 为选中态，`我创建的`正常态；
- `我的收藏`为分组标题；
- 列表内容与顺序保持截图一致；
- 列表可在高度不足时独立滚动；
- 不重复渲染截图中的学生账号 Footer。

### 6.3 市场头部

- 左侧学段胶囊：`小学·二年级`；
- 右侧搜索框：搜索图标 + `搜索智能体`；
- 两者在窄屏可换行，但不可重叠；
- 搜索框允许输入并在当前静态数据集内按标题、简介、作者过滤，明确属于 Demo 本地行为；
- 空结果显示“没有匹配的智能体”，不伪装后端错误。

### 6.4 猜你喜欢

- 标题与“换一换”位于同一行；
- 推荐卡片顺序固定为：每日名言、成语溯源与应用专家、地理百科大全、孔子；
- “换一换”本轮只提供按钮视觉和说明性反馈，不随机制造未提供的推荐数据；
- 宽屏四列、标准 Work Surface 三列、紧凑布局两列或一列。

### 6.5 分类与排序

- 分类顺序：语文、数学、科学、道德与法治、其他；
- 默认 `语文`；
- 排序默认 `最热`，另一项 `最新`；
- 本轮允许切换选中视觉，但不重排未提供的真实数据；切换时显示“静态演示数据未接入真实排序”的非阻塞说明；
- 控件必须可键盘访问，选中态不只依赖颜色。

### 6.6 Agent 卡片

字段：

```text
id
title
description
favoritesLabel
author
avatarPresentation
badge?        // 热门、知识库
compatibility // available | unavailable_in_context
```

规则：

- 头像 36–40px 圆形；
- 标题最多两行，简介最多三行，底部元信息固定靠近卡片底部；
- 卡片高度统一；
- 收藏数保持截图原始显示格式，例如 `5.9W 人收藏`；
- 作者使用 `@ClassIn` 或截图中对应昵称；
- 本轮点击卡片不进入未知详情页；使用非阻塞提示说明“详情与添加流程未接入本静态 Demo”；
- 不支持添加卡片放在独立分区，视觉可保留，但必须通过语义属性或文案让状态可识别。

## 7. 响应式与视觉验收

### 7.1 目标宽度

| Work Surface 宽度 | 内部侧栏 | 市场列数 |
|---:|---:|---:|
| ≥ 1500px | 232px | 5 |
| 1100–1499px | 220px | 3–4 |
| 820–1099px | 196px | 2–3 |
| < 820px | 顶部/抽屉式或隐藏 | 1–2 |

当前主验收基线为 1440×900 的应用窗口：AgentIn 右侧 Work Surface 不出现横向滚动，搜索、分类、排序、卡片和分区标题均可达。

### 7.2 视觉基准

- 主背景、卡片、边框、文字层级、圆角和控件形状以五张证据图为基准；
- 复用当前 Demo Token 和字体，不引入第二套全局 Shell；
- 页面内部允许使用 AgentIn 的浅灰选中态和中性卡片风格；
- 不使用大面积渐变、营销 Hero 或与原图无关的装饰。

## 8. 状态

| 状态 | 本轮表现 |
|---|---|
| loaded | 默认完整市场页 |
| search-empty | 搜索后无匹配卡片 |
| local-feedback | 未接入操作的非阻塞说明 |
| narrow | 响应式降列，不产生横向滚动 |
| unavailable-in-context | 独立分区与语义状态 |

真实 loading、网络错误、权限拒绝、收藏失败和添加失败需要真实接口契约，本轮不伪造。

## 9. 可访问性

- 页面有唯一 `h1`：AgentIn；
- 内部导航、分类、排序使用适当的 `nav`、`button`、`aria-current` 或 `aria-pressed`；
- 输入框有可访问名称；
- 卡片按钮使用完整 Agent 名作为可访问名称；
- Focus 环清晰，键盘顺序先内部导航、再头部控制、再推荐和市场卡片；
- 头像装饰图不重复朗读。

## 10. 验收标准

1. 教师从 `/teacher/ai-agent/new` 可在二级导航看见并进入 `AgentIn`；
2. URL 稳定为 `/teacher/ai-agent/agentin`，刷新不丢页；
3. 页面能对应五张证据图中的可见结构、顺序、标签和核心卡片内容；
4. 1440×900 无水平滚动、遮挡、不可达操作和身份冲突；
5. 纵向滚动可到达“不支持添加”分区；
6. 搜索可过滤静态卡片并显示空结果；
7. 未提供的详情、创建、收藏、授权和添加班级不被伪装成已完成；
8. 现有技能市场、工具连接、我的文件、定时任务和 Agent Run 回归不受影响；
9. TypeScript、ESLint、单元测试和 Playwright 范围内检查通过；
10. 实机截图与参考图进行布局、密度、文字和关键状态对照，并在追踪文档记录差异。

## 11. 后续证据需求

若下一轮要做真实可交互 AgentIn，需要用户补充或线上系统采集：Agent 详情页、创建/DIY 流程、收藏状态、班级添加与授权流程、教师与学生权限差异、成功/失败/不兼容原因、版本和第三方发布治理。

## 12. 交付门禁

本 PRD 当前只供用户审阅。后续必须按以下顺序推进，每个阶段独立审阅或确认：

1. `To Spec`：把已确认 PRD 转成 Feature Spec，明确 Interface、状态、交互和非功能约束；
2. `To Tickets`：从 Feature Spec 拆出可验证 Ticket、Write Set、依赖和逐项验收；
3. `Implementation`：只按已确认 Ticket 修改代码和测试；
4. `Verify / Record`：执行静态、单测、E2E 与视觉验收，并写回实现追踪。

PRD 已于 2026-09-03 通过用户审阅，当前进入 `To Spec`。Feature Spec 审阅完成前，禁止进入 `To Tickets` 或 `Implementation`。
