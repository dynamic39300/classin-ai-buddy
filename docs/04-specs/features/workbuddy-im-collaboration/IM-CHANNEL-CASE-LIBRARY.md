# WorkBuddy 与班级 Agent 三渠道 Case Library

## 1. 使用边界

本库先回答“任务应该进入哪条渠道”，不把 Case 名单解释为已实现能力。当前只有作业催交、课前准备通知和确定性物理答疑达到可运行 Demo；其余条目均为 `[未来]`，必须经过独立 Spec、Ticket 和验收后才能改变状态。

渠道选择规则：

- 教师私密 WorkBuddy：跨业务对象编排、产生 Artifact 或 ClassIn 副作用、需要教师审批；
- 群内公开班级 Agent：问题和答案适合全班看见，且只在显式结构化 `@Agent` 后响应；
- 教师/学生 Agent 私聊：课程范围内的个别辅导或教师专业协作，不应自动暴露给群成员；教师与学生线程互相隔离。

## 2. 优先级

- `P0`：下一阶段候选，能够复用当前 ConversationRun、Context、Artifact、Approval、Receipt 和 Evaluation 骨架；
- `P1`：渠道价值明确，但需要新增领域模型或治理规则；
- `P2`：需要更强的生产事实、长期结果证据或敏感数据治理，暂不进入实现。

## 6. 下一阶段建议

建议以 `WB-03 作业批改 → 错因分析 → 订正任务` 作为下一条工程纵向切片。它已有 M5 Feature Spec，能复用 M4.1 的 ConversationRun 和本轮新增 Evaluation Module，同时迫使系统验证“原始错误事实、AI 错因推断、教师审批、草稿作业回执”四种不同事实所有权。

并行但不扩大实现范围的设计工作是补齐 `PA-02` 与 `DA-02` 的渠道契约，使同一作业事实分别投影为公开事实问答与学生隔离订正辅导；未通过用户 Review Gate 前不进入代码。
